# T303: Startup prune protecting the resumed id

Phase 3 · Model: opus: deletes user files at startup; interaction with `--resume` · Depends-on: T301 · Covers: R85

## Brief
In `cmd/yip/main.go` `runUI`: after `applyResume` succeeded and before `d.launch`, prune the sessions of the start directory: `store.Prune(25, resumedID...)` where `resumedID` is the id of the session reopened by `--resume <id>`/`-c` (empty when none; read it from the flags/options `applyResume` fills). It runs synchronously (before the UI exists, so never on the UI goroutine), ignores its error silently, and is skipped when the store cannot be created. A resume picker (`--resume` without id) does not protect anything. Add a small seam `deps.prune`-free design: the default code path must use the real `session.Store`; tests use a temp start directory and the `deps.launch` stub.

Tests (names exact, `cmd/yip`): `TestStartupPruneKeeps25` (30 session files → 25 remain, newest kept), `TestStartupPruneProtectsResumed` (`--resume <id of the 28th newest>` → that file survives and loads), `TestStartupPruneIgnoresStrayFiles`, `TestStartupPruneNoSessionsDir` (no dir: nothing created, no error).

## Verification
`scripts/verify/v10/T303.sh` exits 0: the named tests pass; negative: a probe-built binary run with 30 files and `--resume <old id>` must not delete that id (fails the script if it does); the five security files are unchanged.
