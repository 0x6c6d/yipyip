# T102: Fatal panic path: cmd/yip exit 2, tui panic guard

Phase 1 · Model: opus: panic/terminal-restore ordering, secrets in the stderr line, exit paths · Depends-on: T101 · Covers: R78

## Brief
Files: `cmd/yip/main.go` (+ new `cmd/yip/crash.go`), `internal/tui/crashguard.go`, tests next to them. Use the T101 API (`crashlog.New/Options/Logger.Fatal/SetDefault`).

**cmd/yip**
1. After `config.Load` succeeds in `runUI`, build the logger: `crashlog.New(crashlog.Options{Version: version, Redact: cfg.Redactor.Redact, Resolve: guard.Resolve, SessionID: <func returning the active tab's saved session id or "">})` where `guard` is `tools.NewPathGuard(startDir)`; call `crashlog.SetDefault(l)`. (`SessionID` may return `""` for now if the TUI cannot give it yet; if cheap, add an exported `tui.Options.ActiveSessionID func() string`-style hook set by the model.) Before config is loaded (startup panics) use a logger with `Redact` nil and a `Resolve` from a PathGuard on the working directory, or stderr only if that fails.
2. Fatal path: `runWith`/`main` get a deferred `recover` (named `crashExit`) around everything: on a panic call `l.Fatal(v)`; print exactly one line to stderr `yip: crashed, details in <path>` (when the write failed, the record already went to stderr; print `yip: crashed (could not write the crash log)`); return exit code 2. The Bubble Tea terminal must already be restored when the line is printed (Bubble Tea restores it itself before `p.Run` returns/re-panics; do not print while the alt screen is active).
3. `launchUI`: keep Bubble Tea's own panic catching (do NOT use `tea.WithoutCatchPanics`). Wrap the model in `tui.Guard` (below). If `p.Run()` returns an error with `errors.Is(err, tea.ErrProgramPanic)` and the guard recorded nothing in this process, write a fallback record via `Fatal("program panic caught by Bubble Tea (value unavailable): "+err.Error())` and exit 2. If the guard recorded a panic, exit 2 without a second record. Other `Run` errors keep today's behaviour (`yip: <err>`, exit 1).
4. Test seam: `var testPanic string` in package main (set only by `-ldflags "-X main.testPanic=<mode>"`; empty in the shipped binary). Modes: `main` panics at the start of `runUI` (before config); `launch` panics inside `launchUI` before the Program starts, with value `"forced test panic"`; `leak` panics inside `launchUI` with value `"forced test panic " + os.Getenv("FAKE_KEY")`. No env var is read for this.

**internal/tui/crashguard.go**: `func Guard(m tea.Model, rec func(v any)) tea.Model` returns a model whose `Init`, `Update` and `View` call the wrapped model under `defer func(){ if r := recover(); r != nil { rec(r); panic(r) } }()` (record first, then re-panic so Bubble Tea restores the terminal), and whose returned `tea.Cmd`s are wrapped the same way (wrap the Cmd; when a Cmd yields a `tea.BatchMsg`, wrap each element; `tea.Sequence` messages cannot be inspected: leave them, the fallback record of rule 3 covers them). `Guard` must keep the wrapped model's value semantics (`Update` returns a guarded copy of the new model). `rec` is `func(v any){ l.Fatal(v) }` plus a package-level flag `recorded` the launcher reads (use `sync/atomic`).

Tests (names exact): `cmd/yip`: `TestMainCrashLaunchPanic` (via the `deps.launch` seam: the launch func panics → exit code 2, `crash.log` in a temp start dir has panic value and stack, stderr has `yip: crashed, details in <path>` with the real path), `TestMainCrashMainPanic` (testPanic `main` set in-process), `TestMainCrashProgramPanicFallback` (a stub launch returns an error wrapping `tea.ErrProgramPanic` → fallback record, exit 2), `TestMainCrashWriteFailureStderr` (start dir `.yipyip` is a file → record on stderr, line `could not write`, exit 2), `TestMainNoCrashNoLog` (normal `--version`/clean launch: exit 0/unchanged, no `crash.log`). `internal/tui`: `TestGuardUpdatePanic`, `TestGuardViewPanic`, `TestGuardCmdPanic` (run a headless `tea.NewProgram(guard(model), tea.WithInput(nil), tea.WithOutput(io.Discard), tea.WithoutRenderer())`; the panic value and a stack containing the panicking test model's function name are in the recorder; `Run` returns `ErrProgramPanic`), `TestGuardPassThrough` (no panic: behaves exactly like the wrapped model).
