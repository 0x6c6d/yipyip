# T402: Per-block render guard

Phase 4 · Model: sonnet: one new containment wrapper around existing render code · Depends-on: T201 · Covers: R84 (second half)

## Brief
In `internal/tui/blocks.go` (the function that renders one conversation block to text), wrap the render of each block in `defer recover`: on a panic the block's text becomes `[render error]` (one line, styled like an error block), `crashlog.Recovered("render block", v)` is called (inside the deferred func), and the other blocks render as usual. The surrounding view stays valid (no lost width/viewport state). The guard must not hide a secret leak: `[render error]` never contains block text. A test-only unexported hook `renderBlockHook func(b *block)` (nil in production), called at the start of a block render, lets tests panic for one chosen block.

Tests (names exact, `internal/tui`): `TestRenderGuardBlock` (3 blocks, the middle panics: the view contains the first and third block text and `[render error]`, no panic), `TestRenderGuardLogged` (record `where: render block` without block text), `TestRenderGuardDoesNotLeakText`, `TestRenderGuardMarkdownBlock` (an assistant block with a panicking markdown render).
