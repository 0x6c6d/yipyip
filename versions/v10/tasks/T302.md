# T302: TUI autosave, exit-save coordination, prune after save

Phase 3 · Model: opus: concurrency (UI goroutine vs. writer), data loss / duplicate files, deletion hook · Depends-on: T202 T301 · Covers: R82, R83, R85, R30 (changed)

## Brief
Files: `internal/tui/save.go` (+ new `internal/tui/autosave.go`), `model.go` (event handling, Options), tests. Today sessions are saved only by `saveTabs` on exit through `Options.SaveOnExit` or the default `session.Store.Save`; `saveState` (shared by pointer between Model copies) keeps `created` and `id`.

1. New seams in `tui.Options`: `Autosave func(*session.SessionData) error` (nil → the default store's `Save`) and `PruneSessions func(keep int, protect ...string) error` (nil → the default store's `Prune`). Test clock: the existing `Options.Now`.
2. Trigger: (a) `agent.EvTurnDone` of the main agent; (b) `agent.EvCheckpoint` (T202) when at least 1 minute has passed since the tab's last autosave (`m.now()`). Only for a tab whose `assembleSession` returns `ok` (non-empty conversation). The data is assembled on the UI goroutine (`assembleSession`, as today: mid-turn it is stored `Turn.Interrupted = true` and its conversation ends at the last checkpoint), the write happens in a `tea.Cmd`/goroutine, never on the UI goroutine.
3. Per-tab state in `saveState` (add a `sync.Mutex`): `id`, `created`, `lastAutosave time.Time`, `inFlight bool`, `wantAgain bool`, `errShown bool`. At most one autosave per tab in flight; a turn-end request arriving meanwhile sets `wantAgain` and runs right after the current write ends (the 1-minute spacing never delays a turn-end save). The writer goroutine stores the id derived by the Store (`data.ID`) into `saveState.id` under the mutex as soon as the write returns, so later saves (autosave and exit) overwrite the same file.
4. Exit coordination (R30): `saveTabs`/`saveTab` first wait for the tab's in-flight autosave (bounded wait, e.g. 5 s) and then save with the stored id, so exactly one file exists per conversation even when the first autosave was still running at exit. The exit save is otherwise unchanged (`SaveOnExit` seam, error line `could not save session: ...`).
5. Errors (R82): the first failing autosave of a tab appends one `could not autosave session: <redacted err>` block (through the existing block/redaction path, delivered to the right tab even when it is not the current one); further failures stay silent until an autosave succeeds again (`errShown` reset).
6. Retention (R85): after each successful save (autosave and exit save) call `PruneSessions(25, protect...)` in the same goroutine, `protect` = ids of every tab's `saveState.id` (all open tabs) plus the id just saved; a prune error is ignored silently. Never call it when the save failed.
7. Subagent and non-main events do not trigger autosave. `/clear`, `/new` and closing a tab keep today's behaviour.

Tests (names exact, `internal/tui`, with the `Autosave` seam recording calls; use `Options.Now` for the clock): `TestAutosaveAfterTurnEnd`, `TestAutosaveSpacing` (checkpoints at +10 s, +59 s: no save; +61 s: one save; turn end always saves), `TestAutosaveNotOnUIGoroutine` (the seam blocks on a channel: `Update` returns, UI stays responsive, release finishes the write), `TestAutosaveErrorOnce` (3 failing saves → exactly one `could not autosave session` line; after a success and a new failure → one more), `TestAutosaveInterruptedMidTurn` (a mid-turn snapshot has `Turn.Interrupted == true` and a conversation without a dangling tool call), `TestAutosaveEmptyConversationSkipped`, `TestAutosaveExitSingleFile` (real Store in a temp dir: exit while the first autosave is blocked in flight → after release exactly one file for the conversation), `TestAutosavePrunesProtectingTabs` (prune seam sees the ids of all open tabs plus the saved id, keep 25; not called on a failed save). Run `go test -race ./internal/tui -run Autosave`.
