# T202: Main-agent history checkpoints and EvCheckpoint

Phase 2 · Model: opus: concurrency on `Session.history`, data-loss semantics, history validity for the next request · Depends-on: T000 · Covers: R81

## Brief
Today `runLoop` (`internal/agent/loop.go`) keeps the working history in the local `out` and `runTurn` commits it to `s.history` only when the turn ends (`s.history = newHist` if `s.gen == gen`); a recovered panic sets `newHist = nil`, so the whole turn's work is lost. Add checkpoints:

1. `func (s *Session) checkpoint(gen uint64, out []provider.Message)`: under `s.mu`, if `s.gen == gen`, set `s.history` to a copy of `out` (no aliasing), then emit `Event{Kind: EvCheckpoint, AgentID: MainAgentID}` (new kind in `events.go`, after the existing kinds so values do not shift; no text).
2. `runLoop` calls it only for `agentID == MainAgentID`, after a model round is complete: after the final assistant message without tool calls, and after the last tool result of a round has been appended (never between an assistant message with tool calls and its results; never with a dangling call). Subagents never checkpoint.
3. `runTurn`'s end-of-turn commit stays. After a recovered panic `newHist` stays nil and `s.history` keeps the last checkpoint (user message included, as `Submit` appended it). The undo journal's recorded history length (`openTurnRecord`) and `autoCompact` must keep working (a checkpoint replaces the whole slice consistently with the working history).
4. Test hook for panics: an unexported field `roundHook func(agentID string, round int)` on `Session` (nil in production) called at the top of each loop iteration of `runLoop`; tests set it to panic.

Tests (names exact, `internal/agent`): `TestCheckpointRounds` (after each completed round `History()` already contains it, observed from an event handler on `EvCheckpoint`), `TestCheckpointPanicKeepsRounds` (two tool rounds then a panic in round 3: `History()` has the user message and both completed rounds, the turn ends with the existing `internal error` line and `EvTurnDone`, the session accepts the next `Submit` and the next provider request contains the kept rounds), `TestCheckpointNoDanglingCall` (every assistant tool call in every checkpoint snapshot has its tool results; also after a panic raised while running a tool round), `TestCheckpointNotForSubagent`, `TestCheckpointEvent` (exactly one `EvCheckpoint` per completed round; none for a failed first round). Run `go test -race ./internal/agent` too.
