# T401: Subagent iteration limit 500, main 50

Phase 4 · Model: opus: raises how many paid model calls one subagent run may make, × `max_subagents` (Consequential assumption 12), in the shared agent loop · Depends-on: T000 · Covers: R54 (a subagent loop stops after 500 model calls, the error names the number used), R6 (changed: main agent 50, subagents 500)

## Brief
State before this task (`internal/agent/loop.go`): `const MaxIterations = 50` bounds the model
calls of one run of `runLoop(ctx, gen, agentID, hist, ts)`, which serves both the main agent
(`agentID == MainAgentID`, from `runTurn`) and subagents (`runSubagent` in `agenttools.go`, agent
ids like `a1`). When the limit is reached it returns
`errIterationLimit = fmt.Errorf("iteration limit (%d) reached", MaxIterations)`; for a subagent
that error becomes the subagent's failure (`SubInfo.Err`, `wait_agent` result).

Change `internal/agent/loop.go` (and `agenttools.go` only if needed):
- Keep `const MaxIterations = 50` (main agent) and add `const MaxSubagentIterations = 500` with a
  doc comment (per `spawn_agent` run).
- `runLoop` takes its limit from the agent kind: `MaxIterations` for the main agent,
  `MaxSubagentIterations` for subagents (a limit field on the tool set or a parameter; your choice).
- The error text names the limit actually used: `iteration limit (50) reached` for the main agent,
  `iteration limit (500) reached` for a subagent. History stays valid (every tool call answered),
  cancellation unchanged. No other behaviour changes.

Tests (exact names) in `internal/agent/loop_test.go` (keep `TestIterationLimit` passing):
- `TestMainIterationLimit`: a fake provider that always answers with a tool call (e.g. `glob`) →
  exactly 50 requests, `EvError` contains `iteration limit (50) reached`.
- `TestSubagentIterationLimit`: auto mode; the main agent spawns one subagent (`spawn_agent`) and
  waits for it (`wait_agent`); the fake provider answers every subagent request (recognise it by
  its user message = the task) with a tool call → exactly 500 subagent requests, the subagent's
  error (`Subagents()[0].Err` or the `wait_agent` result) is `iteration limit (500) reached`, the
  main turn then finishes normally. Must run in well under 10 s.
