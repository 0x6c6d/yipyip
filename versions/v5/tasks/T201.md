# T201: Remove jev question answering

Phase 2 · Model: opus: jev must never decide on the user's behalf again and conversation text must stop leaving the machine for questions (Risk item "jev never answers a question") · Depends-on: T000 · Covers: R49 (removed: every `question` call goes to the user, jev on or off; `jevAnswer`, `jevQuestionState`, turn-history context value, `JevChoice` use deleted)

## Brief
State before this task (`internal/agent`): `question.go` `questionTool` first calls
`s.jevAnswer(ctx, req)`: with jev on, a single-choice question with ≥ 2 options is sent to jev as a
`provider.JevChoice` question (state from `jevQuestionState(req, turnHistory(ctx))`); a confident
valid choice becomes the tool result (`EvInfo` `jev answered: ...`, `noteJev(true)`), otherwise the
user is asked. `loop.go` attaches the loop history with `withTurnHistory(ctx, out)` before running
the question tool. `question.go` also defines `turnHistoryKey`, `withTurnHistory`, `turnHistory`.
Tests: `internal/agent/jev_question_test.go` (`TestJevQuestion`, `TestJevQuestionState`,
`TestJevFallback`); `e2e/jev_test.go` `TestJevE2E` asserts that jev answers a question.

Change:
- `internal/agent/question.go`: delete `jevAnswer`, `jevQuestionState`, `turnHistoryKey`,
  `withTurnHistory`, `turnHistory` and every use; `questionTool` always emits `EvQuestion` and waits
  for the user (behaviour exactly as before v4: labels joined `, `, free text, `cancelled`).
- `internal/agent/loop.go`: drop the `withTurnHistory` call (the question tool gets the plain ctx).
- `internal/agent/jev.go`: only if something there exists solely for question answering (leave
  `routeTurn`, `askJev`, `noteJev` and the `JevStats` fields as they are; a later task reworks stats).
- Delete `internal/agent/jev_question_test.go`. No file under `internal/agent` (tests included)
  may contain the string `JevChoice` afterwards: that also rules out `providertest.JevChoiceAnswer`
  there (build answer maps literally if needed). `provider.JevChoice` and
  `providertest.JevChoiceAnswer` themselves stay (generic client and fake).
- `e2e/jev_test.go`: adapt `TestJevE2E` so its question step expects the question to reach the
  user (answer it through the model like the other e2e question tests) and no `jev answered` info;
  keep its other phases as they are.

Tests (exact names):
- `TestJevQuestionAsksUser` in `internal/agent` (new file, e.g. `jev_noanswer_test.go`): jev
  configured and on, the fake jev answers every question confidently (a `choice` answer naming
  option 2 with confidence 0.99, and a score answer for routing); a model `question` call with 2
  options → `EvQuestion` is emitted, the user's answer is the tool result, the fake jev receives no
  question of type `choice` and none named `answer`; the same with jev off.
- `TestJevQuestionGoesToUser` in `e2e` (in `e2e/jev_test.go` or a new e2e file): through the TUI
  model with jev on and a route configured, a 2-option question appears in the view, the user's
  key answer becomes the tool result, the fake jev received only routing (`score`) questions.
