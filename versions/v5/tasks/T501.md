# T501: Click-to-cursor really moves the textarea cursor

Phase 5 · Model: sonnet: TUI mouse geometry and textarea cursor handling, no security path · Depends-on: T000 · Covers: R41 (changed: a click puts the textarea's own cursor on the clicked cell, incl. soft-wrapped rows, a scrolled input with more than 3 rows and wide runes; a click outside the input does not move it; regression test with a real `tea.MouseMsg` through `Update`)

## Brief
Users report that a click in the input does not move the cursor in practice, although the v4
test `TestInputClick` passes. Reproduce first, then fix; do not assume the cause.

State before this task (`internal/tui`): `View()` (`model.go`) is, top to bottom: tab bar
(`tabBarRows` = 1), the viewport area (`m.viewport.Height` rows, overlays drawn over it), the
input box (rounded border around `m.withGhost(m.inputView())`; `m.input` is a bubbles
`textarea.Model` with `Prompt = ""`, no line numbers, `inputRows` = 3 visible rows, width
`m.width - borderCols`), then 2 status rows. `inputmouse.go` has `inputVisualRows` (walks a copy of
the textarea with `CursorUp`/`CursorDown`), `inputTop` (infers the textarea's scroll offset by
comparing `m.input.View()` with the rows), `inputCellAt(x, y, clamp)` (screen → visual row/column,
the only place that knows the input geometry) and `inputClick(row, col)`; `mouse.go` calls them on a
left press (and select-to-copy on motion/release). Notes for reproducing: the Bubble Tea runtime
calls `View()` after every `Update`, and the textarea's own vertical scroll (`repositionView`) only
works against content rendered by an earlier `View()`, so a test that never renders can hide or
create differences; the runtime is started with `tea.WithMouseCellMotion()` (`cmd/yip/main.go`), so
a click is a press followed by a release, possibly with motion events; other messages (cursor blink,
ticks, session events, window size) arrive between clicks and renders; the Bubble Tea renderer drops
the top rows when `View()` has more rows than the terminal, which would shift every click. A
supervisor reproduction that clicks on cells located in the rendered `View()` of a session-less
model at 80×24 did not show the defect, so compare with the real program (a model with a session,
status rows, overlays such as the completion line, queue, thinking line or inline question, motion
at the press cell before the release). When you find the cause, also cover it with an extra test
(any name) besides the named ones.

Change `internal/tui/inputmouse.go` and/or `mouse.go` (`model.go`/`input.go` only if needed):
- Take the input geometry from the rendered layout (the same row/column offsets `View()` uses),
  and set the textarea's own cursor (row and column) so that `m.input.Line()` and
  `m.input.LineInfo()` (`StartColumn + ColumnOffset`) name the clicked rune, the cursor is drawn
  there in the next `View()` and the next typed rune is inserted there; it must stay there after
  further runtime messages (blink, same-size `tea.WindowSizeMsg`).
- Clicks past the end of a row land at the end of that row; the second cell of a wide rune selects
  that rune. Clicks outside the input text rows (conversation, tab bar, status rows) do not move it.
  Select-to-copy (`TestInputSelect*`) keeps working.

Tests (exact names) in `internal/tui/inputmouse_test.go`; each one types or sets the text, calls
`View()` after every `Update` like the runtime, finds the target cell from the rendered `View()`
(not from constants), sends `tea.MouseMsg{Action: tea.MouseActionPress, Button: tea.MouseButtonLeft}`
then the release through `Update`, and checks `Line()` and the column:
`TestInputClickMultiLine` (3 lines), `TestInputClickWrapped` (one soft-wrapped long line, click on
its second visual row), `TestInputClickScrolled` (more than 3 rows, input scrolled; click on a
visible row that is not the cursor row), `TestInputClickWideRunes` (CJK text, click on either cell of
a wide rune), `TestInputClickOutside` (clicks on the conversation and status rows leave the cursor).
Keep `TestInputClick`, `TestInputSelect`, `TestInputSelectHighlight`, `TestInputSelectSecretNeverCopied` passing.
