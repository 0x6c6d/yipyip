# T301: Routing-only jev stats and /jev stats lines

Phase 3 · Model: sonnet: counters and fixed-format output across agent and TUI, no security path or Consequential assumption · Depends-on: T102, T201, T202 · Covers: R56 (the 11 `/jev stats` lines, per-tier turns and main-model tokens, subagents included, averages, `jev is not configured`), R48 (changed: routing only, current tab, in memory; `QuestionTokens`, `Answered` and the question/routing/other categories removed)

## Brief
State before this task: `internal/agent/jev.go` has
`type JevStats struct{ Answered, Fallbacks, InputTokens int; QuestionTokens, RoutingTokens, OtherTokens int }`,
`Session.JevStats()` (a copy under `s.mu`), `noteJev(answered bool)` (only `routeTurn` calls it now)
and `accountJev(calls, total)`, which `recordUsage` in `loop.go` calls under `s.mu` for every
model response of the main agent and of subagents. Routing (`routeTurn`) already stores the
effective tier of the current turn (`Tier`: `TierNone`, `TierEasy`, `TierMedium`, `TierHard`;
`TurnTier()`), reset in `Submit`; `askJev` adds jev input tokens to `InputTokens`.
`internal/tui/jev.go` `cmdJev` prints the old six stats lines for `/jev stats`.

Change:
- `internal/agent/jev.go`: replace the struct by exactly
  `type JevStats struct { Turns [4]int; MainTokens [4]int; Fallbacks, InputTokens int }`
  where both arrays are indexed by `Tier` (`TierNone` = not routed). Remove `Answered`,
  `QuestionTokens`, `RoutingTokens`, `OtherTokens` and the question/routing/other logic; replace
  `noteJev(bool)` by a fallback-only counter.
- Every main-agent turn started by `Submit` counts once in `Turns[tier]`, with the turn's effective
  tier as decided before its first model request (`TierNone` for jev off, no route, a fallback, or
  Esc during routing). `/init`, if it runs as a turn, counts like one.
- Every model response's total tokens (main agent and subagents of that turn) go to
  `MainTokens[current turn's tier]`; tokens outside a turn (e.g. `/compact`) go to `TierNone`.
- `Fallbacks` (jev error, timeout, malformed answer, below `min_confidence`) and `InputTokens`
  keep their meaning. Stats stay per Session (tab), in memory, never saved; `/new` keeps them.
- `internal/tui/jev.go`: `/jev stats` prints exactly these 11 lines (one info block, `N` an integer):
  `turns routed easy: N`, `turns routed medium: N`, `turns routed hard: N`, `turns not routed: N`,
  `jev fallbacks: N`, `jev input tokens: N`, `main tokens easy: N`, `main tokens medium: N`,
  `main tokens hard: N`, `main tokens not routed: N`,
  `avg main tokens per turn: easy N, medium N, hard N, not routed N` (integer division of
  MainTokens by Turns per tier, `-` for a tier with 0 turns). Without a configured jev
  (`!sess.JevConfigured()` or no session) it prints only `jev is not configured`.
  `/jev` (toggle) and `/jev <other>` stay as they are.
- Update the v4 tests that use the removed fields (`internal/agent/jev_test.go`
  `TestJevStatsTokens`, `internal/agent/jev_route_test.go`, `internal/tui/jev_test.go` `TestJevStats`)
  to the new struct and lines; afterwards `grep -rn QuestionTokens internal` finds nothing.

Tests (exact names):
- `TestJevStatsCounters` in `internal/agent`: a three-tier route (extra models via the project
  file, which is deep-merged with the global config), fake provider usage fixed per request; turns
  routed easy, medium, hard, one jev 500 fallback and one with jev off → `Turns`, `MainTokens`,
  `Fallbacks` exact, `InputTokens > 0`; a subagent's tokens in an easy turn count under easy.
- `TestJevStatsLines` in `internal/tui`: through `Model.Command`, turns routed easy, medium, hard
  and one fallback with known token totals → the view shows exactly the 11 lines in order with the
  expected counts, tokens and averages, and no line containing `question`.
- `TestJevStatsNotConfigured` in `internal/tui`: no `jev` block → `/jev stats` shows
  `jev is not configured` and none of the 11 lines.
