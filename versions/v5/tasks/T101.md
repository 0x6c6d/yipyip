# T101: Config: three-tier jev.route, only hard required

Phase 1 · Model: opus: changes the public config schema (Consequential assumption 1) and must keep v4 configs loading · Depends-on: T000 · Covers: R53 (config part: `medium` key, optional `easy`/`medium`, unknown model rejected naming the key, v4 two-key route still loads), R50 (changed: three tiers instead of two)

## Brief
State before this task: `internal/config/jev.go` parses the optional `"jev"` object into
`Config.Jev *Jev` (`BaseURL`, `APIKey`, `Model`, `MinConfidence`, `Route *JevRoute`).
`type JevRoute struct{ Easy, Hard string }`; `parseJevRoute` requires both `"easy"` and `"hard"`,
each a string naming a configured model `"<provider>/<model>"` (checked with `c.Lookup(id)`).
Errors name the JSON path only, never the value: `config: "jev.route.hard" is required`,
`config: "jev.route.easy" must be a string`, `config: "jev.route.easy" names an unknown model`.
`fillJev` runs after the providers are parsed.

Change `internal/config/jev.go` (only this production file):
- `type JevRoute struct{ Easy, Medium, Hard string }` (field order exactly this; doc comment: model
  ids for easy, medium and hard turns, `""` when the key is absent).
- `"hard"` is required (`config: "jev.route.hard" is required` when missing). `"easy"` and
  `"medium"` are optional: an absent key leaves the field `""`. A present key must be a string
  naming a configured model, else the v4 errors with that key's path
  (`config: "jev.route.medium" must be a string` / `... names an unknown model`). The error never
  contains the given value. Unknown keys inside `"route"` stay ignored, as before.
- A v4 two-key route `{"easy": ..., "hard": ...}` loads unchanged (`Medium == ""`).
- Nothing else changes (no defaults filled in for absent tiers here: the agent decides that an
  absent tier means the `hard` model).

Tests (exact names) in `internal/config/jev_test.go` (keep every existing test passing, including
`TestJevRouteUnknownModel` and `TestJevConfigInvalid`; add models to the test provider string if
you need a third one):
- `TestJevRouteThreeTiers`: `{"easy":..,"medium":..,"hard":..}` with three different configured
  models → all three fields set; also a route with only `"hard"` → `Easy == "" && Medium == ""`,
  and `{"medium":..,"hard":..}` → `Easy == ""`.
- `TestJevRouteTwoKeys`: the v4 route `{"easy":..,"hard":..}` loads, `Medium == ""`.
- `TestJevRouteMediumUnknown`: `"medium"` naming an unknown model (e.g. `fake/ghost`) is rejected,
  the error contains `jev.route.medium` and not `ghost`; `"medium": 3` is rejected naming
  `jev.route.medium`; a route without `"hard"` is rejected naming `jev.route.hard`.
