# T302: /jev prints the active route

Phase 3 · Model: sonnet: one slash-command output plus TUI tests, no security path · Depends-on: T102 · Covers: R55 (`/jev` without args prints the active route: `jev on · easy=<id> medium=<id> hard=<id>` or `jev on · no route configured`)

## Brief
State before this task: `internal/tui/jev.go` `cmdJev` handles `/jev`: without a session or without a
configured jev (`!sess.JevConfigured()`) it prints `jev is not configured`; otherwise it toggles jev
for all tabs (`m.setJev(!sess.JevOn())`) and prints `jev on` or `jev off`. The agent session has
`func (s *Session) JevRoute() (easy, medium, hard string)`: the effective model id of each tier (an
absent `easy`/`medium` key yields the `hard` id), all `""` without a route.

Change `internal/tui/jev.go` (only the no-args branch; `/jev stats` and the usage error stay):
- Toggling on prints exactly `jev on · easy=<easy> medium=<medium> hard=<hard>` (the separator is
  ` · `, a U+00B7 middle dot between single spaces), e.g. `jev on · easy=a/x medium=b/y hard=c/z`;
  with a configured jev but no `route`: `jev on · no route configured`. Toggling off prints
  `jev off`; not configured stays `jev is not configured` (jev stays off).
- The `/help` entry for `/jev` may stay as it is (the docs task updates it).

Tests (exact names) in `internal/tui/jev_test.go` (keep `TestJevToggle`, `TestJevUnconfigured`,
`TestJevHelp` passing, adapting `TestJevToggle` only where it pins the exact old `jev on` text):
- `TestJevCmdRoute`: a config whose route names three different models (e.g. two or three providers
  `a`, `b`, `c` with models `x`, `y`, `z`, or extra models of the fake provider via the project
  file) → `/jev` shows `jev on · easy=<id> medium=<id> hard=<id>` with those ids; a second `/jev`
  shows `jev off`; a two-key v4 route prints the `hard` id for `medium`.
- `TestJevCmdNoRoute`: jev configured without `route` → `jev on · no route configured`.
