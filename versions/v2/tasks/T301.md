# T301: Live subagent blocks

Phase 3 · Model: sonnet: event-driven TUI state, no agent change · Depends-on: T201, T203 · Covers: R25

## Brief
Each subagent gets one live block in the conversation instead of separate tool blocks. New file
`internal/tui/subagents.go`; changes in `internal/tui/model.go` (`apply`, block kinds) and
`internal/tui/blocks.go` (`renderBlock` / `refreshTo`). `internal/agent` is not changed: all
times and counts are tracked in the TUI from events and `m.now()`.

State (names are fixed; a later task reads them):
`type subState struct { id string; start, end time.Time; toolUses int; lastCall string; ended bool }`,
`Model.subs map[string]*subState` (created in `New`), and an unexported field
`subInfo func() []agent.SubInfo` on `Model` used by the existing `subagents()` method in
`agents.go` when non-nil (test seam; nil → `Session.Subagents()`).

Events (`agent.Event`, `AgentID` = subagent id such as `a1`; main agent = `agent.MainAgentID`):
- The first `EvSubagent` or `EvToolCall`/`EvToolResult` of an unknown subagent id creates its
  `subState` (`start = m.now()`) and appends one block of a new kind `blockSubagent` holding the
  id. Later events update the state; the block is re-rendered in place, never duplicated.
- Subagent `EvToolCall`: `toolUses++`, `lastCall = Name(summary)` using the same summary rules as
  tool blocks (reuse the summary function in `blocks.go`). No tool block is added. Subagent
  `EvToolResult`: no block.
- Main-agent `EvToolCall` with tool `spawn_agent` and its matching `EvToolResult`: no block
  (the result must not attach to another call or become a plain block).
- `EvSubagent` whose `SubInfo` status (looked up via `subagents()`) is no longer `running` sets
  `ended = true`, `end = m.now()` once.
- Approval requests and `/agents`, `/agents <id>`, `/agents kill <id>` stay unchanged.

Rendering (plain text; `formatTokens` and `formatElapsed` from `turn.go`; task shortened with the
existing `shortTask(task, taskWidth)`; tokens, task, status and `Err` from `SubInfo`; all redacted):
```
● Subagent a1 (task)
  ⎿  bash(ls)
  ⎿  Running… (3 tool uses · 1.2k tokens · 14s)
```
- The `⎿` line with the latest call is grey (`lipgloss.Color("244")`) and omitted while there is
  no call. `1 tool use` singular, otherwise `N tool uses`.
- Running: `Running…` in `lipgloss.Color("#D77757")`, the parenthesis in `244`; elapsed =
  `m.now() - start` (the 1 s tick of the Thinking line refreshes it).
- Ended: the last line becomes `Done (…)` green `lipgloss.Color("2")`, `Failed (…)` red
  `lipgloss.Color("1")` followed by one more line `     <first line of Err>` in red, or
  `Cancelled (…)` grey `244`, with the final counts and elapsed `end - start`.
- The bullet `●` uses the same colour as the status word.

Tests (new file `internal/tui/subagents_test.go`, names start with `TestSubagent`; use
`newClockModel` + `fakeClock` from `clock_test.go`, set `m.subInfo` to return scripted
`[]agent.SubInfo`, feed events with `m.Update(EventMsg{Event: ...})`):
- `TestSubagentBlockSingle`: `EvSubagent`, two `EvToolCall`s and their results for `a1` give
  exactly one `● Subagent a1 (` in the view.
- `TestSubagentBlockRunning`: SubInfo tokens 1200, clock +14 s, two calls (`bash {"command":"ls"}`
  last) → lines `  ⎿  bash(ls)` and `  ⎿  Running… (2 tool uses · 1.2k tokens · 14s)`.
- `TestSubagentBlockEnded`: status done/failed/cancelled → `Done (`, `Failed (` + error line,
  `Cancelled (`, rendered with `32m`, `31m`, `38;5;244` under `withColorProfile(t, termenv.TrueColor)`;
  the elapsed time freezes after the end.
- `TestSubagentNoSeparateBlocks` (negative): a main `spawn_agent` call + result and `[a1]` tool
  calls produce no `spawn_agent(` and no `[a1]` text in the view.
- `TestSubagentRealSpawn`: with the existing `agentsModel` helper from `agents_test.go`, after the
  turn the view has one `● Subagent a1 (TASK-SUB` block ending in `Done (`.
The existing `TestAgents*` tests must keep passing unchanged; `TestSubagentPanel` may still
expect the v1 panel format (another task changes the panel).
