# T201: Borderless tool-call blocks

Phase 2 · Model: sonnet: rendering rework of one block type with test adaptation · Depends-on: T000 · Covers: R15 (conversation: tool calls and results), R15 (removed bordered tool blocks)

## Brief
Rewrite the tool-call rendering in `internal/tui/blocks.go` (`renderTool`, `resultText`) in
Claude Code style, without borders. Remove `toolBorderStyle` and `toolBlockMargin`.

Layout of one tool block (plain text, `ansi.Strip`ped):
```
● bash(ls -la)
  ⎿  first line of the result
     second line
     third line
     … +4 lines (ctrl+o to expand)
```
- Header: `● ` + tool name + `(` + summary + `)`. The tool name is bold
  (`lipgloss.NewStyle().Bold(true)`). Summary by tool, taken from the JSON arguments: `bash` →
  `command`; `read_file`, `write_file`, `edit_file` → `path`; `glob`, `grep` → `pattern`;
  `spawn_agent` → `task`; any other tool, a missing key or arguments that are not a JSON object →
  the existing `compactArgs` output (one line, at most 200 runes). Newlines in a summary become
  spaces; a summary longer than 200 runes is cut to 199 runes + `…`. Arguments are redacted
  (`m.redact`) before use.
- Subagent calls (`agentID` not empty and not `main`) get `[<id>] ` after the bullet:
  `● [a1] bash(ls)`.
- The bullet `●` is dim (`lipgloss.Color("244")`) while no result exists, green
  (`lipgloss.Color("2")`) for a successful result, red (`lipgloss.Color("1")`) for an error result.
  A call closed without a result (turn ended) stays dim.
- Result: first line after `  ⎿  ` (2 spaces, `⎿`, 2 spaces), every further line indented 5
  spaces. Collapsed unless `m.expanded` (Ctrl+O, existing): at most 3 lines, then a line
  `     … +N lines (ctrl+o to expand)` (dim, N = hidden lines). Error results are rendered red. An
  empty result shows no `⎿` line. Trailing newlines of the result are dropped (as now).
- The result-matching logic (`addToolResult`, oldest open call of the same tool and agent) and
  `closeToolCalls` stay unchanged.

Tests (in `internal/tui/blocks_test.go`, names start with `TestRender`; use the existing
`newBlockModel()` helper and feed `EventMsg{Event: agent.Event{Kind: agent.EvToolCall, ...}}` /
`EvToolResult` through `Update`):
- `TestRenderToolCallLine`: a `bash` call `{"command":"ls"}` with result `a.txt\nb.txt` renders
  the plain lines `● bash(ls)` and `  ⎿  a.txt` and `     b.txt`.
- `TestRenderToolSummaries`: `read_file {"path":"a.txt"}` → `● read_file(a.txt)`;
  `glob {"pattern":"**/*.go"}` → `● glob(**/*.go)`; `spawn_agent {"task":"do x"}` →
  `● spawn_agent(do x)`; an unknown tool `{"a":1}` → `● other({"a":1})`; a subagent call →
  `● [a1] bash(ls)`.
- `TestRenderToolCollapsed`: a 7-line result shows 3 lines plus `… +4 lines (ctrl+o to expand)`;
  after `ctrl+o` all 7 lines and no `ctrl+o to expand`.
- `TestRenderToolDotColors`: under `withColorProfile(t, termenv.ANSI256)` the header bullet is
  rendered with `38;5;244` before the result, with `32m` after a success, with `31m` after an
  error result.
- `TestRenderToolNoBorder`: the rendered tool block contains none of `╭`, `│`, `╰`, `╮`, `╯`.
Adapt `TestToolBlockRendered`, `TestToolResultCollapsed`, `TestToolResultExpand` and
`TestToolResultsMatchByOrder` (they count or look for `╭` and the old `… (N more lines` text) to
the new layout; keep their intent (order matching, expand toggle).
