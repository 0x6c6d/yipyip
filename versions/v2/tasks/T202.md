# T202: Borderless message blocks

Phase 2 · Model: sonnet: conversation layout of the remaining block kinds · Depends-on: T201 · Covers: R15 (conversation: user, assistant, error blocks, spacing, fences)

## Brief
Render all non-tool blocks of the conversation in Claude Code style. The rendering loop is
`refreshTo` in `internal/tui/model.go`; move per-block rendering into a function
`func (m *Model) renderBlock(b block, width int) string` in `internal/tui/blocks.go` (tool blocks
keep using `renderTool`, which already renders `● Name(summary)` / `  ⎿  ` without borders).

- User message (`blockPlain` whose text starts with `> `, created by `Command` as `"> "+text`):
  shown as `> text` on a full-width shaded background `lipgloss.Color("236")`, i.e. every line of
  the block padded to the viewport width with that background
  (`lipgloss.NewStyle().Background(lipgloss.Color("236")).Width(width)`). Multi-line messages
  keep their line breaks; continuation lines are indented 2 spaces. Other `blockPlain` text is
  shown unchanged.
- Assistant text (`blockAssistant`): first line prefixed `● `, every continuation line indented
  2 spaces. Fenced code keeps its syntax highlighting (`highlightFences`, applied before the
  indentation). An empty streamed block renders nothing.
- Error blocks (`blockError`): red (`lipgloss.Color("1")`), no border.
- Info blocks (`blockInfo`): dim as now.
- Exactly one blank line between consecutive blocks (join rendered blocks with `"\n\n"`).
- No border characters anywhere in the conversation; the input box keeps its rounded border.
- All text still passes `m.redact` before styling.

Tests (in `internal/tui/blocks_test.go` or a new `internal/tui/render_test.go`, names start with
`TestRender`; build models with `newBlockModel()` or `newSessionModel(t, srv)`):
- `TestRenderUserBlock`: after `m.Command("hello")` (no session is fine) the viewport contains
  the plain line `> hello`; under `withColorProfile(t, termenv.ANSI256)` the line contains
  `48;5;236` and its `lipgloss.Width` equals the viewport width.
- `TestRenderAssistantBlock`: an `EvText` event `"first\nsecond"` renders the plain lines
  `● first` and `  second`.
- `TestRenderErrorBlock`: an `EvError` event renders red (`31m` under ANSI256) and without
  border characters.
- `TestRenderBlankLineBetweenBlocks`: user, assistant and info blocks are separated by exactly
  one empty line in `ansi.Strip(m.viewport.View())` (no two consecutive empty lines between them).
- `TestRenderNoBordersOutsideInput`: after a user message, assistant text, a `bash` tool call
  with result, an error and an info block, every line of `View()` above the input box's top
  border line contains none of `╭`, `│`, `╰`, `╮`, `╯` (the input box itself still has `╭`).
Adapt `TestFenceHighlightedInView`, `TestSendMessageStreams` and other existing tests that
assert the old unmarked assistant text or plain `> ` lines, keeping their intent.
