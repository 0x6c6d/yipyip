# T601: Mouse wheel and key scrolling

Phase 6 · Model: sonnet: key and mouse routing to the viewport · Depends-on: T000 · Covers: R23, R21 (mouse capture enabled)

## Brief
Scroll the whole conversation with the mouse wheel and keys. Files: `cmd/yip/main.go`,
`internal/tui/model.go` (`Update`), optionally a new `internal/tui/mouse.go`.

- `cmd/yip/main.go`: pass `tea.WithMouseCellMotion()` to `tea.NewProgram` next to
  `tea.WithAltScreen()` (enables mouse capture; the literal `WithMouseCellMotion` must appear
  in that file).
- Mouse wheel: `tea.MouseMsg` with `Button` `tea.MouseButtonWheelUp` / `tea.MouseButtonWheelDown`
  scrolls the viewport 3 lines per event (`m.viewport.ScrollUp(3)` / `ScrollDown(3)`, or the
  viewport's own wheel handling with `MouseWheelEnabled = true` and `MouseWheelDelta = 3`). Other
  mouse buttons are ignored here (a later task uses the left button for selection; do not
  consume left-button events in a way that prevents that, e.g. route them to a no-op handler).
- `Ctrl+Home` (`tea.KeyCtrlHome`) → first line of the whole conversation (`GotoTop`);
  `Ctrl+End` (`tea.KeyCtrlEnd`) → last line (`GotoBottom`), in every input state.
- `Home` / `End` (`tea.KeyHome` / `tea.KeyEnd`) do the same only when the input is empty;
  otherwise they go to the textarea (line start / end) as before.
- `PgUp` / `PgDn` keep working. New output follows only while the view is at the bottom (the
  existing `refresh` / `refreshTo(m.viewport.AtBottom())` logic); scrolling up must not be undone
  by streaming text.
- Approval prompt and model picker keep their key priority (existing routing).

Tests (new file `internal/tui/scroll_test.go`, names start with `TestScroll`; build a long
conversation with `m.add(blockInfo, fmt.Sprintf("line %03d", i))` for i in 0..199 on a model from
`New(Options{StartDir: "/x"})` sized `tea.WindowSizeMsg{Width: 80, Height: 24}`):
- `TestScrollWheel`: at the bottom, one wheel-up `tea.MouseMsg{Button: tea.MouseButtonWheelUp, Action: tea.MouseActionPress}`
  lowers `m.viewport.YOffset` by exactly 3; one wheel-down raises it by 3.
- `TestScrollCtrlHomeEnd`: `Ctrl+Home` → the view contains `line 000`; `Ctrl+End` → it contains
  `line 199` and not `line 000`.
- `TestScrollHomeEndEmptyInput`: with an empty input `Home` shows `line 000`, `End` shows `line 199`.
- `TestScrollHomeEndWithText` (negative): with input `abc`, `Home` does not change
  `m.viewport.YOffset` and moves the textarea cursor to column 0.
- `TestScrollNoSnapBack`: after scrolling up, adding a block (or an `EvText` delta) keeps
  `YOffset` unchanged; at the bottom, a new block is followed.
- `cmd/yip`: no new test needed; the grep in the verification checks the option.
`TestPageKeysScrollViewport` must keep passing.
