# T502: Restore queued messages into the input

Phase 5 · Model: opus: turn cancellation path that must never lose or auto-send queued text · Depends-on: T501 · Covers: R27 (Esc/Ctrl+C/Up restore, /new), R20 (Up order with a queue)

## Brief
Queued messages (`Model.queue []string`, filled by `Enter` while busy and sent as one turn at a
normal turn end) can be pulled back into the input. Code in `internal/tui/model.go` (`Update`
key handling, `ctrlC`), `internal/tui/input.go`, `internal/tui/commands.go` (`cmdNew`).

- `func (m *Model) restoreQueue()`: moves all queued messages into the input, appended to the
  current draft: `draft + "\n" + q1 + "\n" + q2` (no leading `\n` when the draft is empty),
  cursor at the end, queue emptied. Queued text that contains paste placeholders keeps them (they
  still expand when sent).
- `Esc` while busy and the queue is non-empty: cancel the turn exactly as before
  (`sess.Cancel()`, the turn is marked interrupted so it ends with `✻ Interrupted after …`) and
  call `restoreQueue()`. Nothing is sent automatically afterwards.
- `Ctrl+C` while busy and the queue is non-empty: the same as `Esc` (plus the existing double
  Ctrl+C quit arming, unchanged).
- `Up` with an empty input and a non-empty queue: `restoreQueue()` (the turn keeps running)
  before any history navigation; with an empty queue `Up` navigates the history as before.
- `/new` and `/clear` empty the queue.
- While an approval prompt is open its keys keep priority (the existing routing at the top of
  `Update` is unchanged): `Esc` there goes to the prompt's handler as now and does not restore
  the queue.

Tests (in `internal/tui/queue_test.go`, names start with `TestQueue`; use `newClockModel(t, srv)`
from `clock_test.go`; hold the provider with `providertest.NewFunc` blocking on a channel the
test closes in `t.Cleanup` (registered after `srv.Close`); queue by setting the input and
pressing `Enter` while busy):
- `TestQueueEscRestores`: with draft `draft` in the input and `q1`, `q2` queued, `Esc` → after
  `waitSession` + `Drain` the input value is `draft\nq1\nq2`, the queue is empty, the
  conversation ends with `✻ Interrupted after`, and no provider request contains `q1`.
- `TestQueueCtrlCRestores`: the same with one `Ctrl+C` (empty draft → input `q1\nq2`); the
  program did not quit.
- `TestQueueUpRestores`: empty input, queue `q1`, `Up` → input `q1`, queue empty, session still
  busy.
- `TestQueueUpEmptyQueueHistory`: empty queue, `Up` recalls the newest history entry.
- `TestQueueClearedByNew`: `/new` while messages are queued empties the queue (no `> q1` line
  in the view) and nothing is sent later.
- `TestQueueNothingSentAfterInterrupt` (negative): after `Esc` with a queue and releasing the
  provider, the number of provider requests does not grow and no request contains the queued
  text.
