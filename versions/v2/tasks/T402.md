# T402: Input history

Phase 4 · Model: opus: consequential privacy rule (history kept in memory only, never on disk) · Depends-on: T000 · Covers: R20

## Brief
`Up` / `Down` recall submitted inputs. Code in `internal/tui/input.go` (create it if missing,
package `tui`) and `internal/tui/model.go` (`Update`, `submit`); `/new` in
`internal/tui/commands.go` must not clear it.

- `type inputHistory struct { entries []string; pos int; draft string }` held by pointer
  (`Model.hist *inputHistory`, created in `New`) so copies of the model share it.
- `push(s string)`: called in `submit()` for every non-empty submitted input (messages and slash
  commands), with the trimmed text exactly as it was in the input. A value equal to the newest
  entry is not stored again. At most 500 entries: the oldest is dropped. Pushing resets the
  navigation position.
- `Up`: when the input is empty or the cursor is on its first line (`m.input.Line() == 0`), show
  the next older entry (newest first); the first `Up` saves the current input as the draft. At the
  oldest entry `Up` stays there. Otherwise `Up` moves the cursor as before (pass the key to the
  textarea).
- `Down`: when the input is empty or the cursor is on its last line (`m.input.Line() ==
  m.input.LineCount()-1`) and the user is navigating, show the next newer entry; past the newest
  restore the saved draft and stop navigating. Otherwise move the cursor as before.
- A recalled entry is placed in the input with the cursor at the end; it can be edited and sent
  like any input (sending pushes the edited text).
- Keys while an approval prompt or the model picker is open keep going to them (existing
  routing at the top of `Update`); history is not used there.
- Kept across `/new` and `/clear`. Memory only: no file, no environment variable, nothing written
  to disk, ever (do not add any `os.WriteFile`, `os.Create`, `os.OpenFile`, `os.MkdirAll` or
  similar call to `internal/tui`).

Tests (in `internal/tui/input_test.go` (create if missing), names start with `TestHistory`; use
`newSessionModel(t, srv)` from `session_test.go` with a fake provider, submit with
`m.input.SetValue(...)` + `Update(tea.KeyMsg{Type: tea.KeyEnter})`, waiting for each turn with
`waitSession` before the next message; `Up`/`Down` are `tea.KeyUp`/`tea.KeyDown`):
- `TestHistoryUpDownOrder`: after sending `one`, `/mode auto`, `three`: `Up` → `three`, `Up` →
  `/mode auto`, `Up` → `one`, `Up` → `one`, `Down` → `/mode auto`, `Down` → `three`.
- `TestHistoryDraftRestored`: type `draft`, `Up` → `three`... `Down` past the newest → `draft`.
- `TestHistoryDuplicateCollapse`: sending `same` twice → one entry (`Up`, `Up` reach the earlier one).
- `TestHistoryCap500`: push 510 entries directly via `m.hist.push`; `len(m.hist.entries) == 500`
  and the oldest kept is entry 11.
- `TestHistoryMultilineMovesCursor` (negative): input `a\nb` with the cursor on line 1: `Up`
  moves the cursor to line 0 and the value stays `a\nb`; a second `Up` recalls history.
- `TestHistorySurvivesNew`: after `/new`, `Up` still recalls the earlier entries.
- `TestHistoryRecallEditResend`: recall `three`, append `!`, `Enter` → the fake provider receives
  `three!`.
- `TestHistoryNoFiles` (negative): list every file under the test's temp HOME and start dir
  (`filepath.WalkDir` over the parent of `sess.StartDir()`) before and after sending messages and
  commands and navigating history; the lists are equal (no new file).
