# T103: Auto start mode in cmd/yip

Phase 1 · Model: opus: consequential safety default (tools run unprompted at start) · Depends-on: T102 · Covers: R28 (auto default), R7 (default mode changed)

## Brief
yipyip now starts in `auto` mode. Only `cmd/yip` changes; `internal/agent` stays as it is (its
constructor default stays `manual`, which keeps the v1 agent and e2e tests valid).

Files: `cmd/yip/main.go`, `cmd/yip/main_test.go`, new test file(s) in `internal/tui`.

- In `cmd/yip/main.go` add
  `func newModel(startDir string, sess *agent.Session) tui.Model` which calls
  `sess.SetMode(agent.ModeAuto)` and returns
  `tui.New(tui.Options{StartDir: startDir, Session: sess, Mode: string(agent.ModeAuto)})`.
  `runUI` calls it immediately after `agent.NewSession` succeeded and passes the result to
  `tea.NewProgram` (keep `tea.WithAltScreen()`). The literal text `SetMode(agent.ModeAuto)` must
  appear in `cmd/yip/main.go`.
- `--help`, `--version` and unknown-argument handling stay as they are (no config load).

Tests:
- `cmd/yip/main_test.go`: `TestNewModelStartsAuto`: build a config with `config.Load` from a
  temp HOME containing `.config/yipyip/config.json` = `{"provider": {}}` and a temp start dir
  (use `config.GlobalPath(home)`), `agent.NewSession`, then `newModel(dir, sess)`; assert
  `sess.Mode() == agent.ModeAuto` and that `ansi.Strip(m.StatusLine())` contains
  `auto (shift+tab to toggle)`.
- `internal/tui` (names start with `TestMode`; use `newSessionModel` from `session_test.go`,
  which builds the session exactly as `cmd/yip` does, then `sess.SetMode(agent.ModeAuto)` and
  rebuild the model with `New(Options{StartDir: dir, Session: sess, Mode: "auto"})` sized with a
  `tea.WindowSizeMsg{Width: 160, Height: 40}`; or add a small helper doing this):
  - `TestModeStartAutoLikeCmd`: the status row 1 shows `auto (shift+tab to toggle)`.
  - `TestModeAutoBashUnprompted`: the fake provider answers the first request with a `bash`
    tool call `{"command":"echo hi"}` and then text `done`; after `m.Command("run it")`,
    `waitSession` and `m.Drain()` there was no approval prompt (no `agent.EvApproval` was
    rendered, the model has no pending approval) and the tool result `hi` is in the view.
  - `TestModeManualPromptsAgain` (negative): after `m.Command("/mode manual")`, the next
    message whose reply is a `bash` call produces an approval prompt (wait until the view shows
    it, then answer `n`); the command did not run unapproved (use a command that creates a file
    `marker.txt` in the start dir and assert it does not exist after denying).
  Look at `internal/tui/approval_test.go` for how approval prompts are driven and detected.
