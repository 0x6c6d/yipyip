# T501: Queue messages while busy

Phase 5 · Model: opus: consequential memory-only queue and turn sequencing across async events · Depends-on: T204, T402, T403 · Covers: R27 (queue, display, batch send), R6 (changed busy handling)

## Brief
While a turn runs, `Enter` queues the message instead of rejecting it. Code in
`internal/tui/input.go` (queue), `internal/tui/model.go` (`submit`, `apply`, `View`) and
`internal/tui/turn.go` (turn end). Existing pieces you use: `m.turnActive` / `startTurn()` /
the `blockMarker` appended on the main `EvTurnDone` (turn.go), `m.hist.push` (input history),
`m.pastes.expand` (paste placeholders), `Command` (sends a message: adds the `> text` block,
expands placeholders, calls `sess.Submit`, starts the turn).

- Busy = `m.turnActive || (session != nil && session.Busy())`.
- `Enter` while busy on a non-empty input that does not start with `/`: push it to the input
  history, append it to `Model.queue []string`, clear the input. Nothing is sent, nothing is
  added to the conversation, and the v1 `busy: press Esc to cancel the running turn` line is not
  shown. Slash commands typed while busy run immediately as before (never queued).
- Queue block, shown only while the queue is non-empty, directly above the input box and below
  the `Thinking…` line: one line per queued message `> text` in `lipgloss.Color("244")`, in queue
  order; a multi-line message shows its first line plus `…`; at most 5 lines, then
  `… +N more`. Like the other overlay lines it takes its lines from the top of the viewport view
  so `View()` keeps its height.
- Turn end: on the main `EvTurnDone`, after the R26 marker has been appended, if the turn was
  not interrupted and the queue is non-empty: add one `> text` user block per queued message (in
  order), then submit one new turn with the messages joined by `\n` (placeholders expanded),
  start the turn clock (new `Thinking…` line, later its own marker), and empty the queue. The
  tick command returned by `startTurn()` must reach Bubble Tea: return it from `Update` together
  with `m.waitEvent()` (`tea.Batch`); `Drain()` may drop it.
- If `sess.Submit` returns `agent.ErrBusy` at that moment, keep the queue (no user blocks) and
  add the info line `busy: press Esc to cancel the running turn`; the queue is sent at the next
  turn end. Any other error: show it as an error block and keep the queue.
- Interrupted turns (Esc / Ctrl+C) do not send the queue (another task restores it into the
  input). The queue is memory only.

Tests (new file `internal/tui/queue_test.go`, names start with `TestQueue`; use
`newClockModel(t, srv)` and `fakeClock` from `clock_test.go`; hold the first provider request
with `providertest.NewFunc` blocking on a channel `release` the test closes to end the turn
(register `srv.Close` before a `t.Cleanup` that closes `release`); type with
`m.input.SetValue(...)` + `Update(tea.KeyMsg{Type: tea.KeyEnter})`):
- `TestQueueEnterWhileBusy`: busy turn `first`; `Enter` on `second` clears the input; the plain
  view shows `> second` above the input box; under `withColorProfile(t, termenv.ANSI256)` that
  line has `38;5;244`; `srv.Requests()` contains no message `second`.
- `TestQueueOrderAndOverflow`: two queued messages show in order; with 7 queued, 5 lines plus
  `… +2 more`; a queued `a\nb` shows `> a…`.
- `TestQueueSentAtTurnEnd`: queue `second` and `third`, release the turn, drain until idle: the
  conversation shows the first marker `✻ Worked for` before the blocks `> second` and `> third`;
  exactly one new request whose last user message is `second\nthird`; while it runs the view has
  a `Thinking…` line; after it ends there are two markers.
- `TestQueueSlashRunsImmediately`: `/mode auto` while busy runs at once (mode changes, info
  line shown) and is not queued.
- `TestQueueInHistory`: a queued message is in the input history (`Up` on an empty input with
  an empty queue recalls it).
- `TestQueuePasteExpanded`: a 3-line paste queued while busy is sent expanded in the request.
- `TestQueueNoBusyLine` (negative): queueing never produces `busy: press Esc` in the view.
