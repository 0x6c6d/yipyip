# T701: Secret audit across all packages

Phase 7 · Model: opus: end-to-end secret leakage check and fixes (Consequential A4, Risks "Secrets", "No log files") · Depends-on: T504, T505, T506, T507, T604, T605 · Covers: R16, R18

## Brief
Prove, with tests named `TestSecret*`, that the fake API key value `SECRET123` never appears in
any rendered view, error message, tool result, event or file written by yipyip, and fix every
leak you find (in any package; security fixes belong in the shared files
`internal/config/redact.go`, `internal/provider/transport.go`, `internal/tools/bash.go`,
`internal/tools/pathguard.go`, `internal/agent/approval.go` or at the call sites that forgot to
redact).

Existing pieces: `config.Load(home, startDir, getenv)` registers every resolved `{env:}` value in
`Config.Redactor` (`Redact`, nil-safe, `[redacted]`); `provider.Client` redacts error text and
always masks its own key; `tools.Registry.Run` redacts every result and strips `Config.EnvNames`
from the bash environment; `agent.Session` redacts event text; the TUI shows text through
`Session.Redact`. Existing secret tests: `TestSecretRedactor`, `TestSecretConfig` (config),
`TestSecretProviderError` (provider), `TestSecretToolResult`, `TestSecretBashEnv` (tools),
`TestSecretTUIView` (tui). Keep them; add what is missing.

Add:
- `internal/agent/secret_test.go`: `TestSecretAgentEvents`: with `FAKE_KEY=SECRET123`
  (injected getenv) and a `providertest` fake that (a) echoes the request's `Authorization`
  header inside its text reply, (b) requests a bash call `echo $FAKE_KEY; echo SECRET123`, and
  (c) answers a later request with HTTP 401 and a body containing the header: no event text/args,
  no `History()` message and no `Subagents()`/transcript entry contains `SECRET123`.
- `e2e/secret_test.go`: `TestSecretEndToEnd`: the same scenario through the TUI (`e2e` helpers,
  auto mode, plus a `write_file` of `notes.txt` with ordinary content and an `/undo`): the final
  `View()` and `StatusLine()` contain no `SECRET123`; afterwards walk the temp HOME and the temp
  start dir: no file contains `SECRET123`, and the only files in HOME are the config files written
  by the test (yipyip writes no logs, history or session files).
  `TestSecretMissingEnvError`: a config referencing `{env:YIP_TEST_UNSET}` next to a resolved
  `FAKE_KEY`: the `Load` error names `YIP_TEST_UNSET` and does not contain `SECRET123`.
- If a test exposes a leak (for example an echoed header in assistant text entering the history,
  or tool-call arguments shown unredacted), fix it at the point where the text enters yipyip:
  the key travels only in the `Authorization` header; every response text, tool-call argument
  shown in the UI, tool result and error is redacted before it is stored in the history, queued
  as an event or rendered. Do not weaken or delete existing tests.

Every package that handles secrets must have at least one passing `TestSecret*` test:
`internal/config`, `internal/provider`, `internal/tools`, `internal/agent`, `internal/tui`, `e2e`.

## Verification
`scripts/verify/v1/T701.sh` exits 0. It runs `go test ./... -run Secret` (DoD D10), checks each of
the six packages ran at least one `TestSecret*` test, and runs `make check`. Negative: the built
binary started with a config referencing an unset variable must exit 1 naming it without the
other secret value, and no file under a temp HOME may contain `SECRET123` afterwards.
