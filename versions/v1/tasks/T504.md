# T504: `/model` picker and direct selection

Phase 5 · Model: sonnet: one UI component plus a command · Depends-on: T503 · Covers: R10

## Brief
Implement `/model` in `internal/tui` (new file `picker.go`; replace the placeholder entry in the
command table of `commands.go`). Agent API: `Session.Models() []string` (sorted
`provider/model` ids), `ModelID()`, `SetModel(id) error` (unknown → error wrapping
`agent.ErrUnknownModel`, model unchanged).

- `/model` without argument opens a picker listing all configured `provider/model` ids, the
  current one marked (e.g. `> fake/m1` vs `  fake/m2`) and the cursor on it. `Up`/`Down` (and
  `k`/`j`) move, `Enter` selects (`SetModel`, show `model: <id>`), `Esc` closes without change.
  While the picker is open, keys go to the picker, not to the input, and `Esc` does not cancel a
  turn. The picker is rendered above the input (in place of the completion line area) and is
  visible in `View()`. No models configured → `no models configured` and no picker.
- `/model <provider/model>` sets it directly (`model: <id>`); an unknown id shows
  `error: unknown model: <id>` and keeps the current model.
- The status line shows the new model after a change.

Tests in `internal/tui/picker_test.go` (temp HOME + `providertest.ConfigJSON` config with
`fake/m1`, `fake/m2` + `agent.NewSession`): `TestModelPicker` (`/model`, Down, Enter →
`fake/m2` active and shown in the status line), `TestModelPickerEsc` (unchanged),
`TestModelDirect` (`/model fake/m2`), `TestModelUnknown` (`/model nope/x` → error shown, still
`fake/m1`).
