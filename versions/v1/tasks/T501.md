# T501: TUI connected to the agent session

Phase 5 · Model: sonnet: Bubble Tea wiring and rendering · Depends-on: T104, T403 · Covers: R6, R11, R15, R16

## Brief
Connect `internal/tui` to `internal/agent` and start the session from `cmd/yip`.

Existing: `internal/tui/model.go` (`Options{StartDir, ModelID, Effort, Mode}`, `New`, `Init`,
`Update`, `View`, `StatusLine`; Enter submits, Alt+Enter newline, `/exit` `/quit` quit) and
`help.go`. Agent API (`internal/agent`): `NewSession(agent.Options{Config, StartDir})`,
`Submit(text) error` (`ErrNoModel`, `ErrBusy`), `Cancel()`, `Wait()`, `Busy()`,
`NextEvent(ctx) (Event, error)` (blocking), `PollEvents() []Event` (non-blocking), `Redact`,
`ModelID`, `Effort`, `Mode`, `Tokens`, `ContextSize`; `Event{Kind, AgentID, Text, Tool, Args,
IsError, Approval}` with kinds `EvText, EvToolCall, EvToolResult, EvApproval, EvError, EvInfo,
EvTurnDone, EvSubagent`.

Add / change (contract):
```go
type Options struct { StartDir, ModelID, Effort, Mode string; Session *agent.Session } // Session added
type EventMsg struct{ Event agent.Event }
func (m Model) Command(line string) (Model, tea.Cmd) // handle one submitted input line as if typed + Enter
func (m Model) Drain() Model                          // apply all queued session events (PollEvents), non-blocking
```
Behaviour:
- With a Session, model/effort/mode come from it (the Options fields are fallbacks for a nil
  Session, which keeps the skeleton behaviour: `no model configured`).
- `Init` returns a command that blocks on `Session.NextEvent` and returns `EventMsg`; `Update`
  applies the event and re-arms the command. `Drain` applies the same rendering logic to
  `PollEvents()` (used by tests; never call both in tests).
- Enter / `Command`: text starting with `/` is a command (`/exit`, `/quit` → `tea.Quit`; all other
  commands for now show `unknown command: <name>`, never sent to the model; a later task adds a
  dispatcher table: keep commands in one `map[string]func(Model, args string) (Model, tea.Cmd)`).
  Other text → render `> text`, `Session.Submit`; `ErrNoModel` → `no model configured`,
  `ErrBusy` → `busy: press Esc to cancel the running turn`.
- Rendering in the viewport (auto-scroll to the bottom): assistant `EvText` deltas appended to
  the current assistant block (streaming), `EvError` as `error: <text>` (red), `EvInfo` dimmed,
  `EvToolCall`/`EvToolResult` as plain lines `tool <name> <args>` / result for now (a later task
  styles them). Every string shown passes `Session.Redact` first.
- `Esc`: if `Session.Busy()` → `Session.Cancel()`; idle → no-op.
- `Ctrl+C`: first press shows `press Ctrl+C again to quit` (and cancels a running turn); a
  second press within 2 s returns `tea.Quit`.
- `cmd/yip`: after `config.Load` create `agent.NewSession(agent.Options{Config: cfg, StartDir:
  startDir})` (error → `yip: <error>`, exit 1) and pass it in `tui.Options.Session`. Program exit
  → exit code 0 and the terminal restored (Bubble Tea alt screen).

Tests in `internal/tui/session_test.go` (temp HOME, `providertest` fake, config from
`providertest.ConfigJSON(srv.URL, "{env:FAKE_KEY}", 8000)` loaded with an injected getenv

`Drain()`, assert on `View()` at width 160): `TestSendMessageStreams`, `TestEscCancels`,
`TestDoubleCtrlCQuits`, `TestNoModelMessage`, `TestSlashNotSentToModel`, `TestSecretTUIView` (the
fake replies with text containing `SECRET123` and an HTTP 401 body echoing it: the view contains
