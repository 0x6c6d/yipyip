# T703: CLI end to end: install, start directory, startup errors

Phase 7 · Model: sonnet: integration tests of the binary, small fixes in `cmd/yip` · Depends-on: T501, T702 · Covers: R17, R1, R18

## Brief
Make sure the installed binary behaves as README R17/R1 require and prove it with tests that
build and run the real binary.

Existing: `cmd/yip/main.go` (`run(args, stdout, stderr) int`; `--version` prints `yip <version>`,
`--help` prints usage plus `tui.HelpText()`, both before any config access; otherwise start dir
= symlink-resolved working directory, `config.Load(home, startDir, os.Getenv)`,
`agent.NewSession`, Bubble Tea program); `Makefile` targets `build`, `check`, `install` (into
`$(go env GOBIN)` or `$(go env GOPATH)/bin`, `-ldflags -X main.version=...`).

Check and fix where needed (only `cmd/yip/` and `Makefile`; other packages only for a bug you can
prove with a test):
- `--version`/`--help` work with no HOME config, no API key, an invalid `yipyip.json` in the
  current directory, and from any directory.
- A config referencing an unset/empty variable → stderr `yip: environment variable NAME is not set
  or empty` (no value), exit code 1, nothing else printed, no TUI started.
- Invalid config JSON → stderr names the file, exit 1.
- The start directory is the shell's current directory (symlinks resolved).
- `make install` honours `GOBIN` and falls back to `$(go env GOPATH)/bin`.

Tests `e2e/cli_test.go` (build the binary once per test run with `go build -o <tmp>/yip
./cmd/yip` via `os/exec` from the repository root, `-ldflags "-X main.version=test"`; run it with
a temp HOME, a clean environment containing only `PATH` and `HOME`, and a temp working
directory): `TestCLIVersionAnyDir` (output `yip test`), `TestCLIHelpListsCommands` (all of
`/model /effort /init /new /exit /compact /undo /mode /agents /help`), `TestCLIMissingEnvExit1`
(config with `{env:YIP_TEST_UNSET}` plus another variable set to `SECRET123`: exit code 1, stderr
names `YIP_TEST_UNSET`, does not contain `SECRET123`), `TestCLIInvalidConfigExit1`.

Audit (fix if violated): no non-test `.go` file contains `openrouter.ai`; the Makefile contains
neither `proxy.golang.org` nor `openrouter`; non-test code uses no `http.DefaultClient`,
`http.DefaultTransport`, `http.Get`, `http.Post`.

## Verification
`scripts/verify/v1/T703.sh` exits 0. It runs the four tests and `make check`, then the real
acceptance commands: `make install` into a temp GOBIN, and `make install` (default location)
followed by `cd / && yip --version` with `OPENROUTER_API_KEY` unset (DoD D11), and `yip --help`
from an empty temp dir (D12). Negative: the installed binary with a config naming an unset
variable must exit 1 without printing the other secret value; the D13 greps must find nothing.
