# T201: Redactor for secret values

Phase 2 · Model: opus: secrets handling (Consequential assumption A4, Risk "Secrets") · Depends-on: T101 · Covers: R16

## Brief
Create `internal/config/redact.go` (package `config`, standard library only). This is the only
place where secret masking is implemented; every other package calls it (shared-code rule).

Exported API (contract; keep names and types exactly):
```go
const Redacted = "[redacted]"
type Redactor struct{ /* unexported: mutex + secrets */ }
func NewRedactor(secrets ...string) *Redactor
func (r *Redactor) Add(secret string)
func (r *Redactor) Redact(s string) string
```
Behaviour:
- `Redact` replaces every occurrence of every registered secret with `[redacted]`. Secrets are
  applied longest first, so a secret that contains another one leaves no fragment
  (`NewRedactor("abc", "abcdef").Redact("x abcdef y") == "x [redacted] y"`).
- Also replace the JSON-escaped form of a secret (as produced by `json.Marshal` without the
  surrounding quotes) when it differs from the raw value, so secrets echoed inside JSON bodies are
  masked too.
- `Add("")` (and empty strings passed to `NewRedactor`) is ignored; duplicates are stored once.
- A nil `*Redactor` is valid: `Redact` returns the input unchanged, `Add` does nothing.
- Safe for concurrent use (`Add` and `Redact` from many goroutines).
- Never log, print or store secrets anywhere else; no `String()`/`GoString()` method that could
  reveal them (if you add one, it must print only the count).

Tests in `internal/config/redact_test.go`: `TestRedactorReplaces`, `TestRedactorOverlapping`,
`TestRedactorNilAndEmpty`, `TestRedactorConcurrent` (many goroutines, no data race in logic),
`TestRedactorJSONEscaped` (a secret containing `"` is masked in its escaped form), and
`TestSecretRedactor` (the fake key value `SECRET123` never survives `Redact`).
