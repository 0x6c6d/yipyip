# T604: `/compact` command and e2e Compact tests

Phase 6 · Model: sonnet: command wiring and end-to-end tests · Depends-on: T603, T602 · Covers: R13

## Brief
Wire `/compact` into the TUI and add the end-to-end compaction tests of README §8.

Existing: `internal/tui` command table in `commands.go` (placeholder entry for `/compact`),
`Model.Command(line) (Model, tea.Cmd)`, `Drain()`; agent
`Session.Compact(ctx) error` (`agent.ErrBusy`, `agent.ErrNothingToCompact`), automatic
compaction inside `Submit` at 80% of `limit.context` unless `auto_compact` is false; e2e helpers
in `e2e/helpers_test.go` (temp HOME and start dir, `providertest` fake, config via
`providertest.ConfigJSON(srv.URL, "{env:FAKE_KEY}", contextLimit)`, session in auto mode, TUI
model, `submit` helper). Extend the helper if you need a context limit parameter or a project
`yipyip.json`, without breaking the existing undo tests.

TUI (`internal/tui/compact.go`, replace the placeholder): `/compact` returns a `tea.Cmd` that runs
`Session.Compact(context.Background())` and yields a message; on that message show
`compacted` (or the info text) or `error: <err>` (`nothing to compact` for
`ErrNothingToCompact`). Tests run the returned command synchronously:
`m, cmd := m.Command("/compact"); msg := cmd(); mm, _ := m.Update(msg)`.

End-to-end tests `e2e/compact_test.go` (fake built with `providertest.NewFunc`; the summary
request is recognisable by its last user message asking for a summary):
- `TestCompactShrinksHistory`: three turns, `/compact`, then a fourth message; the request sent
  for the fourth message contains exactly: the system prompt, the summary message, the last 2
  turns verbatim, and the new user message (compare roles and contents).
- `TestAutoCompact80`: context limit 1000; the fake reports usage prompt 800 on a reply; the next
  submitted message first triggers a summary request, then the normal request.
- `TestAutoCompactOff`: same, with `{"auto_compact": false}` in the start dir's `yipyip.json`: no
  summary request.
