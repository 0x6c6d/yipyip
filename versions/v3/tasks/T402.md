# T402: Tab bar rendering and tab keys

Phase 4 · Model: sonnet: rendering + key wiring of an already-opus-built tab model (T401); the
`Tab`/`Shift+Tab` unchanged rule is a guard on existing behaviour, no new security logic ·
Depends-on: T401, T103 · Covers: R38 (bar + keys, limit message, Ctrl+W neighbour rule), R11
(`/new` opens a tab via T401's path), R15 (new top line, rest unchanged), A8

## Brief
Render the tab bar and bind the tab keys on top of T401's `tabs []tab` / `cur` / `addTab` /
`closeTab` / `switchTab` and the `tabLimitMsg` constant. Files: new `internal/tui/tabbar.go`
(rendering), edits in `internal/tui/model.go` (Update key handling + `View` composition), tests
in new `internal/tui/tabbar_test.go`.

**Tab bar** — the top line of `View()`, above everything (R15: the existing viewport, status and
input lines are unchanged, they just start one line lower; keep the total view height contract:
the tab bar takes the top line, all other lines follow). One segment per tab
`<N>:<title>` where N is the 1-based tab number and title is the tab's session title (the first
60 runes of the first user message, the value `session.Title` produced — for a title-less tab use
`new session`). The **current tab is highlighted** (the colour profile pattern the picker/status
already use — highlight = default fg on a dimmed palette or bold; under
`withColorProfile(t, termenv.ANSI256)` assert the exact codes you emit, and pick something the
status line's existing helper can reuse — prefer plain `lipgloss` Bold + the existing dim style).
The other segments get colour 244 (`38;5;244`). Separate segments with one space. No mouse
handling (deferred in the plan), no scroll indicators.

**Keys** (only when no overlay is open — mirror how the existing key handler gates on the
picker/approval state):
- `Ctrl+T` → `addTab()`; success: the bar gains a segment and the new tab is current and empty.
  At the limit: append one info block `tab limit reached` to the **current** tab's conversation
  (the constant T401 defined), no other change.
- `Ctrl+W` → `closeTab()` (T401's neighbour rule: left neighbour, else right; last tab = the
  `/exit` path including the save). The bar re-renders with one segment less / the program quits.
- `Ctrl+Tab` / `Ctrl+Shift+Tab` → cycle: `switchTab((cur±1+len)%len)` (forward on Ctrl+Tab,
  backward on Ctrl+Shift+Tab). Bubble Tea delivers these as `"ctrl+tab"` and `"ctrl+shift+tab"`
  key strings on most terminals — match `km.String()` against both spellings.
- `Alt+1` … `Alt+8` → `switchTab(N-1)` for N in 1..8; if tab N does not exist (N > len), no change
  (no error line).
- **Negative rule (R38, must not regress)**: `Tab` keeps doing exactly what it does today (input
  completion / suggestion ghost) and `Shift+Tab` keeps toggling manual/auto mode. Both behaviours
  are asserted unchanged by the existing tests — do not touch them, and make sure the tab
  bindings register nowhere near those keys.

Also: `Alt+<digit>` must not collide with any existing binding (check `grep -rn 'alt' internal/tui/*.go`
and resolve by namespacing inside the existing key switch, not by removing anything).

Tests in `internal/tui/tabbar_test.go` (names exact; strip ANSI with `ansi.Strip` for layout
asserts, raw view under a forced profile for colour asserts; the fake-provider helpers):
- `TestTabBarRendersSegments`: two tabs (one with a run turn → titled, one fresh); the top line is
  `1:<title> 2:new session` in that order (assert on the stripped first line), the current tab is
  the second one (assert raw/coloured contains the highlight style on the second segment: under
  the forced profile, the second segment carries the bold/dim style you chose, the first carries
  `38;5;244`).
- `TestCtrlTOpensEightTabsThenLimit` (negative): press Ctrl+T 8 times from 1 tab: after 7 presses
  8 tabs, the 9th press produces the info block `tab limit reached` in the current tab, tab count
  stays 8, no file is written.
- `TestCtrlWSavesAndSwitchesLeftNeighbour`: run a turn in tab 2 of 3, Ctrl+W on it: the file for
  its session exists, the current tab is the left neighbour (index 1), the bar shows 2 segments,
  and the closed segment is gone.
- `TestCtrlWLastTabExitsLikeExit` (negative): one non-empty tab, Ctrl+W → the save file exists
  and the quit is the same command the `/exit` path produced (compare the produced `tea.Cmd`'s
  side effect class or the exact same internal function name via `fmt.Sprintf("%T", cmd…)` on the
  returned cmd, whichever the exit tests already use).
- `TestTabCycleKeys`: Ctrl+Tab moves to the next (wraps to 0), Ctrl+Shift+Tab back (wraps to the
  last); assert `cur` after each.
- `TestAltDigitJumps` (negative: out of range is a no-op): Alt+3 on 2 tabs → still tab 2, no error
  block; `Alt+2` on 2 tabs → tab 2.
- `TestTabKeyStillCompletes` (negative regression guard): a suggestion-ghost input scenario (see
  `input_test.go`'s existing ghost test) plus `Tab` still accepts the ghost text; `Shift+Tab` on
  a manual-mode session still toggles to auto (reuse the existing assertions' shape).
- `TestTabBarNotShownWithOneFreshTab` (optional but recommended): one fresh tab renders no
  numeric-only bar (still acceptable: one `1:new session` segment — assert whichever you choose,
  but define it and keep the two above consistent).
