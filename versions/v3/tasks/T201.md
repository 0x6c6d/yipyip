# T201: `--resume [id]` (alias `-c`) in cmd/yip

Phase 2 · Model: opus: touches the Consequential resume edges A6 (placement + globals) and A7
(edges, queue→draft, fmts) and the public interface (`-c`, exit 1 message) · Depends-on: T000 ·
Covers: R31 (flag + edges), R34 (entry seam for the e2e), R11 (`--help`)

## Brief
Add session resume to `cmd/yip/main.go` (and its `main_test.go`). Before phase 4 the TUI still has
exactly one tab: the task file for T202 defines how a resumed `session.SessionData` is restored
into the model — this task only decides *what* is resumed and passes the loaded data through, so
define the hand-over as an `Options` field or constructor argument `ResumeData *session.SessionData`
(nil = fresh start) in `internal/tui` (Options struct extension only; do not implement the restore
rendering). If `internal/tui` does not compile with the field before T202, keep the field in the
Options struct and default the restore path to a no-op TODO that T202 fills — the flag tests must
not depend on the TUI rendering at all.

- Both `--resume [id]` and `-c [id]` are parsed for every flag position (also
  `--resume=<id>`; and `-c` composed into existing short flags if the current parser supports that).
  `--help` gains one line mentioning `--resume [id]` (`-c`).
- `yip --resume <id>` / `yip -c <id>`: `internal/session.Store(startdir).Load(id)`; on success call
  `internal/tui.New(Options{..., ResumeData: data})` instead of the fresh path. On a load error
  (unknown id, invalid file, version mismatch): print exactly `unknown session <id>` on stderr,
  exit 1 — never print the file path or any config material, even when the error names a path.
- `yip --resume` / `yip -c` without id: if stdin is a tty AND `Store.List()` returns ≥ 1 session,
  the caller enters the picker state (T202 implements the overlay; here only set
  `ResumeData: nil` plus a new `ResumePick true` field the TUI/loop consumes — the default
  behaviour without the picker is a fresh session). Empty sessions dir → fresh session. Non-tty
  (stdin is not a character device; use `os.Stdin` stat, testable via a boolean field
  `StdinTTY bool` on the Options struct so tests do not fake a tty) → fresh session.
- In all resume paths the already-open `Options.Session` (the fresh `agent.Session`) stays
  constructed as today; resume only *adds* the data to restore into it. Startup errors
  (config load, `{env:NAME}` unset) keep their exact v1/stderr + exit 1 behaviour unchanged, and a
  resume never bypasses the config load.
- The start dir is resolved as today (symlink-resolved `os.Getwd()`); the Store gets that dir.

Tests in `cmd/yip/main_test.go` (names exact; temp start dirs via `t.TempDir()` built the same way
the config tests fake a `HOME`; drive the flag parsing + hand-over, not a real program run — refactor
`main`'s tail into a testable `run(opts)` seam if needed):
- `TestResumeFlagParsesId` (positive): `--resume <id>`, `-c <id>`, `--resume=<id>` all produce
  `ResumeData` with that id; plain `yip` produces `ResumeData == nil`.
- `TestResumeUnknownIdExit1` (negative): `--resume deadbeefdead` (not in the store) → process view
  gets `unknown session deadbeefdead` on stderr and exit code 1; the message does not contain
  `.yipyip/sessions` (no path leak).
- `TestResumeWithIdLoadsData` (positive): save one valid session via `internal/session.Store`,
  run the flag path, assert the Options carry a `*session.SessionData` whose conversation/history
  match the file (round object identity, not re-parsed strings).
- `TestResumeNoIdNonTTYStartsFresh` (negative): `StdinTTY=false` + a non-empty store →
  `ResumeData == nil` and `ResumePick == false` (no picker path for a non-tty).
- `TestResumeNoIdEmptyDirStartsFresh`: `StdinTTY=true`, empty sessions dir → no picker.
- `TestResumeHelpMentionsFlag`: the `--help` text contains `--reload`… no: contains `--resume`
  (grep-able). (Also keeps the existing `--version`/`--help` tests green.)

## Verification
`scripts/verify/v3/T201.sh` exits 0. It runs these tests by name plus the whole `./cmd/yip`

contains a file path, non-tty with a full store never produces a picker hand-over, the protected
paths (transport + tools) have an empty diff at the v2 commit, and `make check` passes.
