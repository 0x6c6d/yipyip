# T401: Tab state refactor (per-tab sessions, global settings)

Phase 4 · Model: opus: cross-cutting refactor of the TUI's core state — every field split into
per-tab vs global; touches Consequential A6 (resume placement + globals: stored
model/effort/mode become global) and the Ctrl+W neighbour rule wiring (A8) · Depends-on: T103,
T102 · Covers: R38 (tab model, per-tab state, global model/effort/mode, `/new` opens a tab, at-8
limit error), R11 (`/new` changed), R15 (view layout stays)

## Brief
Restructure the TUI's state so up to 8 sessions live side by side. Files: new
`internal/tui/tabs.go` (the tab model + the switch/close/add helpers), edits in
`internal/tui/model.go`, `internal/tui/input.go`, `internal/tui/commands.go`, `internal/tui/save.go`,
tests in new `internal/tui/tabs_test.go`. Do not implement the tab bar rendering or the tab key
bindings (T402 does); this task is state + helpers only, broadly testable via direct helper calls
and `Update`/`Command` on the model.

**Per-tab state** — each of these becomes a member of a new `tab` struct (name the fields after
today's model fields, moved verbatim): `sess *agent.Session` (the conversation/agent), the
conversation blocks + blockMarker bookkeeping, the paste store, the input history, the queue, the
`sessID string` the save path stores, `created time…`/ids, `turnActive` + the `Thinking…`/turn
label state, the viewport's stored scroll position (if the current model keeps one). The `Model`
holds `tabs []tab` (len 1..8) and `cur int` (0-based index). Refactor mechanically: wherever
`m.someField` was read/written, it becomes `m.tabs[m.cur].someField` (or a tiny accessor
`m.tab()`); keep the field names and types untouched so View/Update diffs stay small.

**Global state** (stays on `Model`, untouched by switches): model id / effort / mode one
selection shared by all tabs. Implementation: the agent `Session` carries model/effort/mode, so
this is "one setter applied to all current + future tabs": add `m.setGlobals(model, effort, mode)`
called on every existing setting path (`/model`, `/mode`, and the resumed-values path T202 added —
it must set all tabs' agent sessions at once, so resume then keeps the globals consistent, A6).
New tabs inherit the current globals at creation time.

**Operations** on `tabs`:
- `addTab()`: len < 8 → append a fresh session tab inheriting the globals, make it current.
  At 8 → **no change**, return a sentinel/false so the (future) key handler can print
  `tab limit reached` — export the sentinel as `errTabLimit` in tabs.go (or a bool return;
  the *message text* itself is T402's job; still, define the constant `tabLimitMsg = "tab limit reached"` here
  so the two tasks' string tests converge on one constant).
- `closeTab()`: saves the current tab through the T103 save loop (the same function; non-empty
  conversation → file written, empty → nothing), then removes it. With tabs remaining: switch to
  the **left neighbour** if there is one, else the right one (A8). With one tab left: this is the
  `/exit` path (same function T103 wired — quit after saving). Saving failure keeps A12
  (`could not save session: <err>` line in that tab, still close/quit).
- `switchTab(i int)`: 0 ≤ i < len → `cur = i`; out of range → no change. Switching swaps
  conversation/counters/history/pastes/queue/turn state — i.e. simply point `m.tabs[m.cur]` at the
  right index, and refresh the viewport/resize state for the new tab.
- `/new`: now opens the fresh session in a **new tab** via `addTab()` (R11 changed; at the limit
  it must NOT reuse/export the current tab and also must not lose the queued draft — the
  sentinel path prints the limit message, T402's handler). `/new` on a resumed tab keeps the
  old file (nothing is deleted silently).
- Exit (T103's save loop) now iterates **all** tabs and saves each non-empty one.

SSH to the last hidden risk: the tick/clock helpers (`turn.go`) and the event pipe (`apply(ev)`)
are per-session; make sure `apply` targets `m.tabs[m.cur].sess` (the running turn keeps running in
its own tab if the user switches away — verify `EvTurnDone` from a background tab still appends to
that tab, not the current one; that is why the event must carry or resolve its session, e.g. by
comparing pointer identity to one tab's `sess`).

Tests in `internal/tui/tabs_test.go` (names exact; the fake-provider helpers + temp start dir;
drive helpers directly and `Update`/`Command` for the command paths; assert on `View()` when a
block is expected):
- `TestAddTabSwitchesToNewTab`: `addTab` → len 2, cur 1, the new tab's conversation is empty, its
  agent session has the global model/effort/mode (assert via the accessors).
- `TestSwitchTabSwapsState` (negative side: state does NOT leak): run a turn in tab 0 to give it
  one assistant block + history + counters; switch to tab 1; `View()` shows no assistant block,
  the input history is empty (Up finds nothing), TokenCounts are 0; switch back and all state is
  back.
- `TestGlobalModelSharedAcrossTabs`: switch tabs, set the model in one, assert the other's session
  reports the same model/effort/mode; a tab added after the change inherits them.
- `TestCloseTabSwitchesLeftNeighbour` (negative: never right): with tabs 0/1/2, close tab 1 from
  tab 2's perspective (i.e. cur=2, before it tab 1): the remaining tabs are 0 and 2 and cur is the
  left neighbour index after removal; assert via the tab count + `cur`.
- `TestCloseLastTabQuitsAndSaves`: with one non-empty tab, `closeTab` → the save file exists and
  the quit command is produced (same test shape as T103's exit-save tests).
- `TestCloseTabSavesSession` (negative: the closed file is not lost): two tabs, run a turn in
  tab 0, close tab 0 → the file exists with run-1 conversation content, the program keeps running
  on the (renumbered) other tab.
- `TestAddTabAtLimitNoChange` (negative): 8 tabs, `addTab` → still 8 tabs, cur unchanged, no new
  file written, `errTabLimit`/false returned.
- `TestNewOpensTabKeepsOldFile` (negative): run a turn in tab 0, `/exit`-save once to create the
  file (or drive the save helper), then `/new` → 2 tabs; the old file still exists on disk after a
  second save from the other tab.
- `TestBackgroundTurnAppendsToItsTab` (negative, the isolation danger): start a turn in tab 0,
  switch to tab 1, let the turn finish (release the fake provider), assert the block landed in
  tab 0's conversation, tab 1's view stayed empty, and no marker/`Thinking…` leaked into tab 1's
  view.
