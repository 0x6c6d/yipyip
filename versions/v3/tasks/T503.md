# T503: e2e Question test

Phase 5 · Model: sonnet: e2e against the fake provider following the existing `./e2e` pattern;
no new security logic · Depends-on: T501, T502 · Covers: R39 (full flow: tool call → user
answer → result travels back to the provider in the follow-up request), R16 (no secret in the
file, nothing else here), A2

## Brief
New file `e2e/question_test.go` (package `e2e`; reuse the helpers of `e2e/session_test.go` /
`e2e/undo_test.go`: temp dir, temp `HOME`, the recording fake provider, the program-level drive).
Scripted provider behaviour:

- **Turn 1**: the assistant stream makes exactly one tool call — `question` with args
  `{"question":"Which database?","options":["postgres","sqlite"],"multiple":false}` — so the
  overlay opens. From the test, drive the key presses that select `sqlite` and confirm (`Space`
  on the right row, then `Enter` — through the program's real `Update` path). The recorded
  **follow-up request's** tool-result message must then contain exactly `sqlite`
  (the T502 contract at the process level): unmarshal the recorded request 2's messages, find the
  message with `role == "tool"`, assert its content is `sqlite` (no prefix, no JSON wrapper).
  Then the fake streams the assistant's plain final reply for turn 1 (e.g. `sqlite it is`).
- **Turn 2 (the multiple + free-text + cancel variants are already unit-tested)**: a second
  scripted call, `multiple:true` with options `a`,`b`,`c`; from the test drive two `Space`s and
  `Enter`; assert the next follow-up tool result is exactly `a, c`. Then finish the turn with a
  streamed assistant reply.
- **Turn 3**: a scripted call whose overlay is cancelled (`Esc`); assert the follow-up tool
  result is exactly `cancelled` and the turn still finishes normally (a final assistant reply
  arrives after the result).
- The overlay's visual presence: while turn 1's overlay is open the `View()` contains the
  question text and both option labels (strip ANSI) — this is the R15 acceptance; also assert the
  turn is still running (`Busy()`/no finished marker in the view) while the overlay waits (A2
  negative), and that opening the overlay did not produce an approval prompt or a
  `denied by user` line (R39: never gated).
- Offline only (fake provider, temp dirs).

Tests (names exact, all in `e2e/question_test.go`):
- `TestQuestionSingleChoiceEndsInFollowupRequest`: the turn-1 flow above with the exact-`sqlite`
  request assertion.
- `TestQuestionMultipleJoinedInRequest`: the turn-2 flow asserting `a, c`.
- `TestQuestionCancelledResultInRequest` (negative): the turn-3 flow asserting `cancelled` and a
  normally finished turn.
- `TestQuestionOverlayVisibleAndTurnRunning` (negative): overlay title/labels visible in the
  view; no `denied by user` and no approval prompt anywhere in the view; the turn is busy while
  the overlay waits.

## Verification
`scripts/verify/v3/T503.sh` exits 0. It runs these four tests by name plus the whole `./e2e`
package, and negatives: no `denied by user`/approval-prompt line ever appears for a `question`
call, the follow-up tool-result content is exactly the expected string (no wrapper/prefix), the
protected paths (`internal/tools`, transport) diff empty, and `make check`.
