# T103: Save on exit (ExitSave wiring)

Phase 1 · Model: sonnet: multi-file wiring of already-opus-built pieces (Store + accessors follow a
clear pattern), no new security logic · Depends-on: T101, T102 · Covers: R30, R30a, R11 (exit saves)

## Brief
Wire the exit paths so that `/exit`, `/quit` and a double `Ctrl+C` save every open tab (v3 still has
one tab before phase 4; write the loop over the eventual tab list as one entry — the tabs work
generalises it, not you). Conversation through the redactor stays as it is; the save path is new.

**Files:**
- `internal/tui/save.go` (new): assembles a `session.SessionData` from the current tab and saves it
  (A4: `internal/session` is pure storage; the TUI assembles). Fields: `startdir` (the session's
  start dir), `model`/`effort`/`mode` (agent accessors), counts + `last_context`,
  `conversation` (agent History()), `history`/`pastes`/`queue` from the TUI's own state (already
  tracked in `internal/tui/input.go`/model fields), `title` (reuse `session.Title` on the first
  user message — or an empty conversation → **skip saving entirely**: no file, no error, A12),
  `turn` (agent TurnState(); interrupted → finished per A5), `created`/`updated` (created set on
  first save of this conversation; if the model has no `created`, the Store's derived id path will
  set the file's id — fill `created` at first assembly).
- `internal/tui/commands.go`: `/exit` and `/quit` call the save loop (only tabs with a non-empty
  conversation) **before** the existing quit; a save failure appends one line
  `could not save session: <err>` to that tab's conversation (visible in `View()`) and the quit
  continues with exit 0 (A12). Empty tab → nothing written, no error line.
- `internal/tui/model.go`: the double-`Ctrl+C` confirm path (v1 quits on the second press) calls the
  same save loop before quitting. No change to single `Ctrl+C` (still cancels the turn) and no
  change to `Esc`.
- `cmd/yip`: no behavioural change needed for the save itself (exit codes unchanged, R30a) — only
  pass what `newSessionModel` already gets. If `.yipyip/` must exist for Store, Store creates it.

**Tests** — new file `internal/tui/exit_save_test.go` (names exact; reuse this package's existing
model-with-fake-provider helper and temp start dir; drive `Model.Update` / `m.Command` and assert on
`View()`; the sessions dir is `<tempstart>/.yipyip/sessions`):
- `TestExitSaveWritesFile`: run one scripted turn (tool call + result), then `m.Command("/exit")`;
  the process-view command in tests is the existing quit path; assert exactly one file exists under
  `<start-dir>/.yipyip/sessions/`, its JSON `version` is 1, its `conversation` contains the tool
  result text (un-redacted; use a `SECRET123`-carrying fake tool output and assert the secret IS in
  the file, matching R33).
- `TestExitSaveEmptyWritesNothing` (negative): a fresh model with no turn, `/exit` → no sessions
  dir/file created, no `could not save session` line in `View()`.
- `TestDoubleCtrlCSavesAllTabs`: run a turn, press `Ctrl+C` twice with the v1 confirm window; the
  file exists and the conversation contains the turn (exit path via keys, not the slash command).
- `TestSaveFailureShowsLineStillQuits` (negative): point the Store at an unwritable dir (e.g.
  start dir whose `.yipyip` is created read-only via a `chmod 0500` sessions parent, or inject a
  failing saver through a small seam — prefer a field/option `SaveOnExit` over chmod flakiness on
  CI-partitioned systems); `/exit` → `View()` contains `could not save session:` **and** the quit
  still proceeds (the v1 exit code behaviour is asserted by the existing cmd tests staying green —
  `ExitSave` must not break `go test ./cmd/yip`).
- `TestExitKeepsOtherOutput`: v1 behaviour intact — after save the quit path output/`View()` looks
  as before (no new top-level block), so no protected/renamed rendering is visible.
