## Brief

**`docs/usage.md`** — read it first and keep its existing v2 structure/style; append (or weave
into the existing structure where it already has sections for similar topics) these sections:
- **Sessions**: sessions live under `<startdir>/.yipyip/sessions/<id>.json` (12-hex id from the
  file content); every open tab's session is saved when the program exits (`/exit`, `/quit`,
  double `Ctrl+C`); an empty tab saves nothing; `yip --resume [id]` (alias `-c`) reopens one,
  `yip --resume` with no id opens a picker (`Enter`/`Esc`), non-tty or empty dir → fresh
  session; `/sessions` lists them (newest first, ≤10 + `… +N more`), `/sessions <id>` loads one
  into the current tab, `/sessions rm <id>` deletes it after a `y/n` prompt; the current
  tab's own session can never be `rm`d; a failed save prints
  `could not save session: <err>` and still exits 0; the conversation is stored as the agent
  holds it, i.e. already **redacted** (a resolved secret such as an API key or an `{env:NAME}`
  value appears as `[redacted]` in tool results and text, never in clear), but a session file
  can still contain file contents and command output, so mention `.yipyip/` being gitignored;
  API keys are never stored. (Correction of the original brief: the file does NOT hold
  un-redacted tool results.)
- **Tabs**: up to 8 sessions side by side; a tab bar as the top line (`N:<title>`, current
  highlighted); keys `Ctrl+T` (new tab, `tab limit reached` at 8), `Ctrl+W` (close: saves
  first, switches to the left neighbour, else right; the last tab is `/exit`),
  `Ctrl+Tab`/`Ctrl+Shift+Tab` cycle, `Alt+1`–`Alt+8` jump; per-tab conversation/history/queue,
  global model/effort/mode; `/new` opens a fresh session in a new tab (the old tab's file, if
  saved, is kept); the v1 `Tab` (completion) and `Shift+Tab` (mode toggle) keys are unchanged.
- **Questions**: the model may call a `question` tool: an overlay with up to 6 radio options
  (or checkboxes if `multiple`) plus a free-text row; `↑/↓` move, `Space` selects, `Enter`
  confirms, `Esc` cancels (result `cancelled`); it is never approval-gated; the turn simply
  waits.
- **Retry**: connection failures before the first response byte (reset/429/5xx/dial) retry up
  to 10 attempts with waits `1s,2s,4s,8s,16s,32s,60s,60s,60s`; the status shows
  `retrying (n/10) in <wait>`; after the first byte there is no retry, and other 4xx don't
  retry either.
- **Settings defaults**: model/effort/mode changes persist to `~/.config/yipyip/config.json`;
  other keys and `{env:NAME}` references are preserved; a `yipyip.json` in the start dir still
  overrides per project; a failed write prints `could not save settings: <err>`.
