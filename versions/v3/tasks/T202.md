# T202: Session picker overlay (resume) and restore rendering

Phase 2 · Model: sonnet: multi-file wiring of an already-opus-designed frame (`Store.Load` +
`Restore*` accessors from T102), no new security logic; the mixed global/local patch is
convention-following · Depends-on: T201, T101, T102 · Covers: R31 (picker, placement, globals,
queue→draft, `/new` keeps the file), R35 (picker TUI), R35a (list format), R34 (restore seam), R33

## Brief
Implement the resume picker (R35) and the restore of a `session.SessionData` into a live run.

Files: `internal/tui/resume.go` (picker overlay + `restoreInto` helper), tests in
`internal/tui/resume_test.go`.

**restore(data session.SessionData)** — called when the model starts with `Options.ResumeData`
non-nil (T201's seam) or the picker confirms. It:
- calls the agent restore setters from T102 — `RestoreHistory`, `RestoreTokens`,
  `RestoreModelEffortMode` (the stored model/effort/mode **become the global selection**, A6) —
  and fills the TUI-side state (`m.hist`, paste store, queue) from the file's history/pastes/queue.
- queue → draft: the queued messages are joined with `\n` into the textarea value and the queue
  itself is emptied (A7; no turn can be running at resume).
- turn state: restored as finished; a stored `interrupted: true` stays stored-finished and nothing
  resumes the turn; no `Thinking…` line, no finished marker, no live turn state at all is restored
  (A5/A7: markers are turn state, not conversation).
- if `Options.ResumePick` was set (no id, tty) the picker overlay is shown instead; confirming
  with `Enter` calls the same `restore` on the picked file's data.

**Picker overlay** — visually the existing `/model` picker (`internal/tui/picker.go`,
`overlayPicker` in `model.go`): centered list over a dimmed frame, title `resume session`. Rows,
newest first from `Store.List()` (A7): bold first line = title, second line
`<relative updated> · <total_tokens dem space toks> · <model>`, relative time in `2h ago` style
(compute it from `time.Since`; in tests set `updated` in the file to controlled offests, and
accept any of `2h ago`/`2 hours ago`/`2h` — the assertion greps for the row's title and a number of
`h`, not an exact string). At most 12 rows visible, then a scroll indicator `▲/▼`.
Keys: `Up`/`Down` move the cursor, `Enter` restores the selection, `Esc` and `q` exit the whole
program **without starting a session** (exit 0 — this is the same quit path T103 wired; nothing is
saved because nothing was opened). Empty sessions dir never shows the picker (fresh session,
negative path). The picker is a separate struct (e.g. `resumePicker`) — do not abuse the `/model`
picker's state.

Tests in `internal/tui/resume_test.go` (names exact; use the package's fake-provider model
helpers, a temp start dir, and drive `Update`/`Command` while asserting on `View()`; strip ANSI
with `ansi.Strip`; for colour assertions use `withColorProfile(t, termenv.ANSI256)` and check for
`38;5;244` in the raw view):
- `TestResumePickerShowsRowsNewestFirst`: three files with controlled `updated` offsets; the
  picker view lists titles in the newest-first order (`List()` order passed unchanged); each row
  shows a relative-time token (`h`) plus `toks` count plus the model id; the raw (coloured) view
  contains `resume session` as the picker title and at least one `38;5;244`-styled row block
  (frame/title styling is the existing pattern-reuse, so assert at least the dim colour appears
  somewhere in the overlay).
- `TestResumePickerEnterRestores`: `Enter` on the second row → the view (picker closed) shows the
  restored conversation's last assistant text; `TokenCounts`/model/effort/mode match what the
  file stored (assert via the same accessors T102 exposed, or via the rendered pieces the
  status line already shows — use whichever the model provides); the textarea value equals the
  queued messages joined with `\n` (type via `m.input.Value()`/`SetValue`); the history recall
  (`Up` on an empty input) finds the stored history's last message.
- `TestResumePickerEscExitsWithoutStarting` (negative): `Esc` triggers the existing quit path
  (the process-model-side `quit() cmd is produced); nothing from a fresh session is rendered, and
  exactly one exit-shaped command is returned; assert on the keymap side: `View()` never shows
  the fresh-session placeholder and no `Could not save session` error appears (not saved, never
  saved).
- `TestResumePickerEmptyDirFreshStart` (negative): empty sessions dir → no picker is rendered,
  the fresh session placeholder is there (existing v1 rendering is fine).
- `TestResumePickerScrollIndicator` (negative, count > 12): 13 files produce a visible scroll
  indicator (`▲` and/or `▼`) plus at most 12 rows.
- `TestRestoreDropsLiveMarkers`: a stored file whose conversation carries `Thinking…`-text and a
  finished marker produces a view without either (these are turn state, dropped at restore, A7).
