# T501: `question` tool gate in internal/agent

Phase 5 · Model: opus: a new waiting gate next to `internal/agent/approval.go` (the shared-code
pattern for Consequential A1: `internal/tools` untouched; A2: the turn is not finished while
waiting) — concurrency + cross-cutting turn/lifecycle semantics · Depends-on: T000 · Covers: R39
(agent side: tool, args, result, auto-approval, waiting), A1, A2

## Brief
Add the `question` tool. It lives **only** in `internal/agent` (A1: `internal/tools` must stay
byte-identical; `git diff 9519824..HEAD -- internal/tools` is part of the verification). Files:
`internal/agent/question.go` (gate + tool), tests in `internal/agent/question_test.go` — study
`internal/agent/approval.go` first and mirror its shape (notify function, buffered-1 reply
channel, `once` sync so the first answer wins, ctx-done cancellation).

**Types**
```go
type QuestionRequest struct {
	AgentID  string
	Question string   // the model's question text
	Options  []string // up to 6 option labels
	Multiple bool
	reply    chan string // buffered 1
	once     sync.Once
}
// Respond(effect string) answers; first call wins; nil-safe; later calls ignored.
// Cancel() answers "cancelled" idempotently (used on turn cancel/Esc and ctx done).
```
Deterministic results: the chosen labels joined `", "` (multiple mode), a free-text string
returned as-is, or the exact constant `Cancelled` = `"cancelled"` (export it — the TUI overlay
and the e2e both need it).

**Tool** — `runQuestion(ctx, req *provider.ToolCall…)`-shaped function (adapt the exact shape the
existing per-tool runners in `loop.go` use; it must be registered nowhere in `internal/tools`):
args JSON from the model: `{"question": string, "options": []string, "multiple": bool}`
(options ≤ 6: more → truncate silently to 6, not an error — the spec caps the overlay, not the
contract; `question` empty is still valid), `multiple` default false. Registration: add
`question` to the main tool offer (the `mainTools()`/toolSet path and the prompt's tool list so
the model can call it) — in `internal/agent`, never in `internal/tools` (check how `spawn_agent`
and the others get offered and mirror only that wiring).
- It must **never** be gated: do not add it to `gatedTools` (the approval gate stays untouched —
  `IsGated("question")` is false by construction; assert in a test). It runs in both modes.
- While waiting it holds the turn: like the approval gate, it blocks on the reply channel
  until `Respond`/`Cancel`/ctx-done. Interrupts/Esc during the wait behave exactly as the
  approval gate's (the ctx-cancel path cancels the request; the turn is then already being
  cancelled).
- The result goes into the history as a tool result exactly like any other tool's result
  (`Cancelled` literally, on cancel — the turn continues normally, no error state, no
  `Interrupted` mark).

Do not change: `Gate`, `gatedTools`, the approval prompts, the subagent gating regexps, and
anything in `internal/tools`.

Tests in `internal/agent/question_test.go` (names exact; drive a turn whose scripted provider
response is a `question` tool call — reuse the package's existing scripted-provider/fake tool-call
helpers; answer/never-answer via goroutine timing like the approval tests do, no busy waiting):
- `TestQuestionToolOfferedAndUngated` (negative): `ts.offers("question")` (or the mainTools
  equivalent) is true, `IsGated("question")` is false, and `internal/tools`' registry lookup by
  name `"question"` errors (the tool exists only in agent wiring, never in the tools registry).
- `TestQuestionSingleChoiceResult`: options `a`,`b`,`c`, `multiple:false`; respond the label
  `b` → the tool result recorded in history is exactly `b` and the turn continues to the next
  loop iteration (the assistant's follow-up reply, if the fake streams one, still arrives).
- `TestQuestionMultipleResultJoined` (positive contract): `multiple:true`, respond the labels
  `x`,`y` (the TUI's job is the comma-joining; here assert the tool's deterministic side via the
  same `strings.Join(labels, ", ")` path — assert `x, y` is what reaches history) — and the
  free-text path: responding a free string returns it verbatim.
- `TestQuestionEscCancelled` (negative): respond the `Cancelled` constant → history holds a tool
  result `cancelled`, the turn continues normally (no error block, the turn's final message is
  produced by the fake's next reply).
- `TestQuestionNeverFinishesTurnWhileWaiting` (negative, A2): while the question waits (mock
  never responds within the test window), `sess.Busy()` is true, the turn is not finished, no
  `EvTurnDone`-equivalent fires — after `Cancel()` the turn unwinds exactly like an approval
  cancelled at the same point (same event the approval path emits).
- `TestQuestionOptionsCappedAtSix` (negative: 8 options offered, only 6 reach the request —
  assert on the `QuestionRequest.Options` len, not on a crash; looping back the fake's own tool
  call args is fine).
- `TestQuestionRespondOnceOnly` (negative): two `Respond` calls with different strings → the
  first wins (history holds exactly one value).
