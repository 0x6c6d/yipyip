# T606: Stored settings are applied at startup

Phase 6 · Model: sonnet: reads three already-persisted keys at startup; small, no new security logic
beyond validation of untrusted file values · Depends-on: T601, T602 · Covers: R40 (a new session
starts with the stored values; project `yipyip.json` still wins), added by the supervisor (T601/T602
only wrote the keys; nothing read `effort`/`mode` back)

## Brief
`config.SaveSettings` (T601) writes the top-level keys `default_model`, `effort` and `mode` to the
user config; `Load` already applies `default_model` (merged key by key with the start directory's
`yipyip.json`, project wins) but nothing reads `effort` or `mode`: `cmd/yip` always starts in auto
mode with the default effort. Make a new `yip` start with the stored selection:

- Read `effort` and `mode` from the merged config (they are in `Config.Raw` or add typed fields to
  `Config` next to `DefaultModel`; keep the merge order: user config first, project `yipyip.json`
  on top key by key — if `Load` already merges `Raw` that way, reuse it; do not change the merge
  semantics of any existing key).
- Validate: `effort` must be one of the values the agent accepts (see how `/effort` validates in
  `internal/tui/commands.go`/`internal/agent`), `mode` one of `auto`, `manual`. Any other value
  (wrong type, unknown string, empty) is **ignored silently** — startup never fails because of
  these two keys and never prints their value. A stored value is applied exactly like the
  matching slash command would, but without triggering a settings write (nothing changed on disk)
  and without a conversation line.
- Apply in `cmd/yip/main.go` before the UI starts: effort onto the session; mode as the starting
  mode (today `newOptions` forces auto: keep auto as the default when nothing valid is stored).
  A `--resume` of a session still overrides model/effort/mode with the session's stored values
  afterwards (T202 restore path, unchanged).
- The `{env:NAME}` handling, redaction and every other key stay untouched; no new file writes.

Tests in `cmd/yip/main_test.go` (names exact; temp `HOME` and temp start dir like the existing
config tests; use the existing `deps.launch` seam to capture the `tui.Options`/session instead of
running the UI):
- `TestStartupAppliesStoredSettings`: user config holds `"effort": "high"` and `"mode": "manual"`
  (plus `default_model` as the existing tests do) → the captured options/session report effort
  `high` and manual mode.
- `TestStartupProjectConfigOverridesStoredSettings`: user config `"mode": "manual"`, project
  `yipyip.json` `"mode": "auto"` → auto.
- `TestStartupIgnoresInvalidStoredSettings` (negative): `"effort": "ludicrous"`, `"mode": 7` →
  startup succeeds with exit path unchanged, defaults (auto mode, default effort), nothing written
  to stderr containing `ludicrous`.
- `TestStartupStoredSettingsDoNotWriteConfig` (negative): after startup with stored values the
  user config file's bytes are unchanged (no write triggered by applying them).
- Existing `cmd/yip` tests stay green.
