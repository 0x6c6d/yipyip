# T203: `/sessions` command (list / load / rm)

Phase 2 · Model: sonnet: dispatch + formatting of an already-opus-designed Store (T101) +
restored restore path (T202); follows the existing slash-command pattern exactly · Depends-on:
T101, T102, T103, T202 · Covers: R32, R35a, R33 (per-start-dir list only), R15 (new conversation
text lines), A7 (marker/time formats, current-id never for rm)

## Brief
Add the slash command `/sessions` to `internal/tui/commands.go` (dispatch table entry `sessions`),
with the logic in a new `internal/tui/sessions.go` and tests in `internal/tui/sessions_test.go`.
Read the current tab's own session id from the save path's model state (`m.created`/the id kept in
`internal/tui/save.go` and its `m.*` seam — find the field the exit-save wiring stores; if it is
not a field yet, add one unexported field `sessID string` set by the save path, and set it in the
same constructor/first-save round, not by re-parsing files).

- `/sessions`, `/sessions ls` (the bare command without argument): `Store.List()` of the start
  dir. Empty result → one info block `no saved sessions`. Non-empty → one info block per session,
  newline-joined (one `add(blockInfo, ...)` per line is fine too, but keep them in order),
  newest first:
  `<id>  <title>  <15:04  Jan 2>  <total tokens> toks  <model>`
  — id first, exact spaces: **two** spaces between columns (R35a), time from `updated` in the
  local `15:04  Jan 2` layout (note: two spaces before the month, matching the acceptance text —
  reuse `time.Format`; A7). At most 10 rows, then one last line `… +N more` (N = count − 10).
  Format: id and time in `lipgloss.Color("244")`, title/tokens/model in the default fg (R35a);
  the plain (ANSI-stripped) text is what the tests assert on for column layout — the coloured
  variant must contain `38;5;244` for each id/time cell, asserted under a forced colour profile.
- `/sessions <id>`: `Store.Load(id)`, then call the T202 restore path **into the current tab**:
  replace the agent conversation/counters/history/pastes, queue → draft, drop live markers —
  through the very same helper T202 implemented (`restoreInto`, called with the loaded data);
  the only difference: placement is "this tab", not "new tab" (phase 4 makes `restore` take a tab
  target — write it as `restoreInto(tab int, data)` already, so phase 4 only changes the caller).
  After loading, one info block `loaded session <id>`. Unknown id → info block
  `unknown session <id>` (never an error block, never a path); do not replace  anything.
- `/sessions rm <id>`: confirmation. First command call prints one info block
  `remove session <id>? y/n` and remembers an rm-pending state; the next input line `y` →
  `Store.Delete(id)` + info block `removed session <id>`; `n` (or any other single word
  input before anything else reaches the submit path — check input.go's history push path) →
  info block `kept session <id>` and the pending state clears. The **current tab's own id** is
  never offered for `rm` (negative check; A7): print `cannot remove the current session` instead
  and do not enter the pending state (if the id is not the current one, normal flow).
  Delete of an unknown id → `unknown session <id>`.
- Everything goes through `Store` (no direct file reads in the TUI). Text rendered is the redacted
  view of these info lines (they contain no secret material).

Tests in `internal/tui/sessions_test.go` (names exact; the package helpers + temp start dir + T202
`restoreInto`; three `.yipyip/sessions/*.json` files saved via `internal/session.Store` with
controlled `updated`/`total_tokens`/`model`/`title` and a first-user-message string that drives
`Title`):
- `TestSessionsListEmpty` (negative): no files → the view contains exactly `no saved sessions`
  and no id column.
- `TestSessionsListNewestFirstAndColumns`: two files with different `updated`; but keep the row
  count under 10; assert both `id`s appear newest-first in the rendered lines and each line has the
  two-space column layout (one assertion per column via `strings.Contains` on the stripped
  text); under the forced colour profile, the raw view contains `38;5;244`.
- `TestSessionsListOverflow`: 12 files → 10 rows + `… +2 more` last.
- `TestSessionsLoadRestores`: `/sessions <id>` on a file with a queued message + history → the
  input area holds the queued text, the conversation has the stored last assistant block (marker
  lines dropped), counters displayed match the stored ones, info block `loaded session <id>`.
- `TestSessionsLoadUnknownId` (negative): `/sessions deadbeefdead` → view contains
  `unknown session deadbeefdead`; the conversation (e.g. the last assistant text) is unchanged.
- `TestSessionsRmConfirmY`: `/sessions rm <other>` → `y/n` prompt; submit `y` → the file is gone
  from the sessions dir and the info block says `removed session <other>`.
- `TestSessionsRmConfirmN` (negative): prompt then `n` → the file still exists and the view says
  `kept session <other>`.
- `TestSessionsRmNeverCurrentSession` (negative): save the current tab (drive `/exit`-shaped save
  via the T103 path or the save helper directly on a fresh model), then `/sessions rm <ownId>` →
  view contains `cannot remove the current session`, file still exists.
