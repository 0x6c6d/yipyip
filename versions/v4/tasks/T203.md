# T203: /skills command and / suggestions

Phase 2 · Model: opus: shows untrusted skill descriptions, which must be redacted in the transcript and the suggestion line (Consequential assumption 5) · Depends-on: T202 · Covers: R46 (`/skills` list with source and shadow note, re-read on every `/skills`, `no skills found`, suggestions with description); R45 (warnings re-shown)

## Brief
State before this task: `internal/skills.Load(home, startDir) ([]Skill, []string)` returns the
skills (sorted, `Skill{Name, Description, Body, Source}` with `Source` `skills.Global` = `"global"`
or `skills.Project` = `"project"`) and one warning line per skipped entry. `internal/tui` loads
them in `New` from `Options.Home` / `Options.StartDir` into a field on `Model`, prints each warning
as an info line `warning: <line>`, runs `/<name> [args]` for non-shadowed skills, and has one
function deciding whether a skill name is shadowed by a built-in (a key of `slashCommands`).
`m.redact(s)` redacts through the session's `config.Redactor`.

Changes in `internal/tui` (`commands.go`, `help.go`, `input.go`, `model.go` as needed, or a `skills.go`):
1. `/skills` (register in `slashCommands` and in the `commands` list of `help.go`, right after
   `/sessions`, `Help: "list the loaded skills"`): re-reads the skills with `skills.Load` (the stored
   list is replaced, so new, changed and removed skill files take effect), prints each warning as
   `warning: <line>`, then one info block with one line per skill:
   `/<name>  <description>  (global)` or `(project)`, plus `  shadowed by built-in` for a shadowed
   skill. No skills: the single line `no skills found`. Works without a model configured.
2. `/` suggestions: `completions()` (the completion line and Tab completion) and the ghost
   suggestion (`suggestion()` in `input.go`) also offer `"/"+Name` of every loaded, **non-shadowed**
   skill whose name starts with the typed prefix, after the built-ins. In the completion line a
   skill entry is drawn as `/<name> (<description>)` (description omitted when empty, truncated
   to at most 40 cells with `…`), and the description passes `m.redact` before it is drawn.
   Built-in entries are drawn as before. Shadowed skills never appear in suggestions.
3. Update existing tests that pin the full command list (e.g. `TestHelpTextListsCommands` in
   `help_test.go`, and any `cmd/yip` `--help` test) to include `/skills`; no other existing test
   may change.

Tests (new, in `internal/tui/skill_test.go` or `skills_cmd_test.go`; use `newSessionModelOpts`
with skills written under `opts.StartDir` and a temp `opts.Home`; the config key is `SECRET123`):
- `TestSkillsCommand`: a global skill, a project skill, a project skill overriding a global one
  (listed once as `(project)`) and a skill `help` (`shadowed by built-in`); after adding another
  skill file, `/skills` shows it (re-read); a description containing `SECRET123` shows
  `[redacted]` only.
- `TestSkillsCommandEmpty`: no skill dirs → `no skills found`.
- `TestSkillSuggest`: typing `/gr` (key runes into the input) shows `/greet` and its description
  in the view; Tab completes the input to `/greet`; typing `/he` does not suggest the shadowed
  skill `help` twice or its description; a description with `SECRET123` is never in `View()`.
