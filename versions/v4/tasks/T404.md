# T404: Risk-screen hook in the approval gate

Phase 4 · Model: opus: changes `approval.go`, the security-critical approval gate (Consequential assumption 4) · Depends-on: T000 · Covers: R51 (jev can only add a prompt in auto mode, never remove one; manual mode and gate decisions unchanged; no jev answer approves a call)

## Brief
This task may change `internal/agent/approval.go` (and only it, plus tests in
`internal/agent/approval_test.go`). Today `Gate.Check(ctx, mode, agentID, tool, args)` returns
`true` at once for non-gated tools and for gated tools (`bash`, `write_file`, `edit_file`,
`spawn_agent`) in `ModeAuto`; in manual mode it prompts via `notify` unless "always" was chosen,
and fails closed.

Add exactly one optional hook:
```go
// SetRiskScreen installs fn (nil removes it). fn is consulted only in auto mode,
// only for bash, write_file and edit_file, and only to ADD a prompt.
func (g *Gate) SetRiskScreen(fn func(ctx context.Context, tool, args string) bool)
```
Rules in `Check` (guard the field with the gate's mutex; never hold the mutex while calling fn
or notify):
- Non-gated tools, manual mode and every other existing path: unchanged; fn is **never called**
  outside `ModeAuto` and never for `spawn_agent` or non-gated tools.
- `ModeAuto` and tool in {`bash`, `write_file`, `edit_file`} and fn != nil: call fn (a panic in fn
  is recovered and counts as `false`). `false` → `true` (auto-approve, as today). `true` → the
  normal prompt path for this one call (same `ApprovalRequest`, `notify`, ctx handling, fail closed:
  nil notify → `false`), except that `AllowAlways` is treated as `Allow` and **never** stored in
  "always" (the next risky call prompts again, and manual mode later is unaffected).
- fn's result can only lead to a prompt; it is never used to return `true` on its own outside the
  auto path that already returned `true`, and never to skip a prompt.
- Keep the doc comments accurate; `IsGated`, `Decision`, `Reset` unchanged.

Tests (exact names) in `internal/agent/approval_test.go` (keep the existing ones):
`TestRiskScreenPrompts` (auto + fn true → one prompt with tool and args; Allow → true, Deny → false;
nil notify → false), `TestRiskScreenSafe` (auto + fn false → true without prompt),
`TestRiskScreenManual` (manual: fn never called, prompts and results exactly as without fn),
`TestRiskScreenScope` (auto: `spawn_agent`, `read_file` → fn not called), `TestRiskScreenNoAlways`
(AllowAlways on a risk prompt → next risky call prompts again; a manual call afterwards prompts too),
`TestRiskScreenPanic` (fn panics → auto-approve, no prompt, no panic), `TestRiskScreenCancel` (ctx
cancelled while the risk prompt waits → `false` and the ctx error).
