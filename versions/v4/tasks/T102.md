# T102: /<skill> args dispatch in the TUI

Phase 1 · Model: sonnet: slash-command dispatch over an existing loader, no security logic of its own · Depends-on: T101 · Covers: R45 (`/<name> [args]` sends the body, args after a blank line, tools and approval unchanged)

## Brief
Wire skills into the TUI so that `/<name> [args]` runs a loaded skill through the existing agent
loop. The package `internal/skills` exists with:
`skills.Load(home, startDir string) ([]skills.Skill, []string)` (sorted skills + warning lines) and
`type Skill struct{ Name, Description, Body string; Source skills.Source }`.

Changes:
- `internal/tui/model.go`: add `Home string` to `Options` (documented: the user's home directory for
  the global skills folder; `""` = global skills not read). Add to `Model` (not to the per-tab
  `tab` state; skills are global for all tabs) a field holding the loaded `[]skills.Skill` and the
  warnings. `New` loads them once with `skills.Load(opts.Home, opts.StartDir)` when
  `opts.StartDir != ""` (warnings are only stored in this task).
- `internal/tui/commands.go`: in `runSlash`, built-in commands (`slashCommands`) are looked up
  first and always win. Otherwise, if a loaded skill has `"/"+Name == name`, run it; else keep
  `unknown command: <name>`. Running a skill:
  - the message is `Body` when `args == ""`, else `Body + "\n\n" + args` (args = text after the
    name, trimmed, exactly as `runSlash` already splits it);
  - the transcript shows the typed line (`> /<name> <args>`) like a normal message;
  - the message is submitted exactly like a typed message in `Command` (same `sess.Submit` path,
    `pushTurnStart`/`startTurn`, the same `no model configured` / busy / error lines). Factor the
    shared submit code of `Command` into one helper instead of copying it; no other behaviour of
    `Command` changes.
  - A skill grants nothing: no change to approval, mode or tools.
- `cmd/yip/main.go`: set `Options.Home` to the home directory it already computes.
- Skill files are never written.

Tests in a new file `internal/tui/skill_test.go` (use the existing `newSessionModelOpts(t, srv, rel, edit)`
helper of `session_test.go` and `providertest`; write skill files under `opts.StartDir` in the edit
func before `New` runs):
- `TestSkillRun`: project skill `greet` with body `Hello there.`; `m.Command("/greet Bob")`, wait for
  the turn (`waitSession`), `Drain`; the last user message received by the fake provider is exactly
  `"Hello there.\n\nBob"`; the view shows `/greet Bob`.
- `TestSkillRunNoArgs`: `/greet` sends exactly `Hello there.`.
- `TestSkillUnknown`: `/nosuch` prints `unknown command: /nosuch` and sends no request.

## Verification
`scripts/verify/v4/T102.sh` exits 0. It runs the three tests, the phase-1 exit criterion
(`--- PASS: TestSkillRun`) and a supervisor probe (overlay test) that runs a project skill with and
without args against the fake provider and checks an unknown name sends nothing; it also checks
`cmd/yip` passes `Home` and that protected files are untouched.
