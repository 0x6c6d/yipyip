# T505: Tab hotkeys trimmed to Ctrl+T / Ctrl+W

Phase 5 · Model: sonnet: removes key cases and adapts the old v3 tests, no security path · Depends-on: T504 (tabs stay switchable by click before the switch keys go) · Covers: R38

## Brief
Only `Ctrl+T` (new tab) and `Ctrl+W` (close tab) remain as tab hotkeys. `Ctrl+Tab`,
`Ctrl+Shift+Tab` and `Alt+1` … `Alt+8` do nothing at all. `Tab` (completion / suggestion) and
`Shift+Tab` (mode toggle) are unchanged. Switching tabs is done by clicking a tab in the tab bar
(already implemented).

State before this task: `internal/tui/model.go` key handling has cases `"ctrl+t"` (calls
`m.openTab()`), `"ctrl+w"` (`m.closeTab()`), `"ctrl+tab"` (next tab), `keyCycleBack` (previous
tab; the constant `"ctrl+shift+tab"` lives in `internal/tui/tabkeys.go`) and
`"alt+1"` … `"alt+8"` (jump with `m.switchTab`). `internal/tui/help.go` has the `keys` list with
`{"Ctrl+Tab/Ctrl+Shift+Tab", "next/previous tab"}` and `{"Alt+1..Alt+8", "switch to tab 1..8"}`.
Existing v3 tests assert the removed behaviour and must be adapted by this task:
`TestTabCycleKeys` and `TestAltDigitJumps` in `internal/tui/tabbar_test.go` (delete both, and the
now unused helper `altDigit` if nothing else uses it) and `TestHelpListsNewCommands` in
`internal/tui/help_test.go` (drop `"Alt+1"` from its list, keep the rest). Check `cmd/yip`
tests (`TestHelpFlagNewKeys` and others) for `Ctrl+Tab`/`Alt+1` expectations and drop only those
expectations.

Changes (`internal/tui/model.go`, `internal/tui/tabkeys.go`, `internal/tui/help.go`, the tests
named above):
- Remove the three switching cases. Keys whose `String()` is `ctrl+tab`, `ctrl+shift+tab` or
  `alt+1` … `alt+8` are swallowed: no tab change, no text inserted into the input, no block, no
  command. Keep the list of swallowed keys in `tabkeys.go` (replace `keyCycleBack` by, e.g.,
  `func ignoredTabKey(s string) bool`); `model.go` no longer calls `switchTab` from key handling.
- `help.go`: remove the `Ctrl+Tab/Ctrl+Shift+Tab` and `Alt+1..Alt+8` rows; add one row
  `{"Click tab / × / +", "switch tab / close it / new tab"}` (or equivalent text containing
  `×` and `+`); keep the `Ctrl+T` and `Ctrl+W` rows.

Tests (exact name) in `internal/tui/tabbar_test.go`: `TestTabKeys`: with 3 tabs and tab 2 current
and the input holding `abc`, each of `ctrl+tab`, `ctrl+shift+tab` (use `namedKey`) and Alt+1,
Alt+3 (`tea.KeyMsg{Type: tea.KeyRunes, Runes: []rune{'1'}, Alt: true}`) leaves `m.cur`, the tab
count, the input value `abc` and the block count unchanged; `Ctrl+T` then opens a 4th tab that is
current and `Ctrl+W` closes it again (back to 3 tabs); `Shift+Tab` still toggles the mode; the
help text contains `Ctrl+T` and `Ctrl+W` but neither `Ctrl+Tab` nor `Alt+1`.
