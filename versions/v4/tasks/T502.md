# T502: Input select-to-copy

Phase 5 · Model: opus: copies text to the clipboard, must keep the redacted-only rule of R21/R16 (`SECRET123` negative) · Depends-on: T501 · Covers: R42

## Brief
Dragging the left button inside the input field highlights the selection and, on release,
copies the selected text exactly like the conversation copy-on-select (R21); a click without a
drag copies nothing (it only moves the cursor, as already implemented).

State before this task: `internal/tui/inputmouse.go` has
`func (m Model) inputCellAt(x, y int, clamp bool) (row, col int, ok bool)` mapping a screen
position to a visual row/column of the input (`m.input`, a `textarea.Model`, 3 text rows inside
a rounded border, first text row at screen `y = tabBarRows + m.viewport.Height + 1`, first text
column at `x = 1`), and a left press inside the input moves the cursor there (`TestInputClick`).
`internal/tui/mouse.go` has the conversation selection (`selection{active, moved, start, end}`,
`viewportView` reverse-video highlight `\x1b[7m`, `selectedText`) and copies on release with
`_ = m.clip(text)`, sets `m.notice = "<N> characters copied"` (N = rune count) and
`m.noticeUntil = m.now().Add(noticeDuration)` and returns the `noticeMsg` tick. `m.clip` is the
only clipboard writer (`clipboard.go`: OSC 52 + `wl-copy`/`xclip`/`xsel`); `m.redact(s)` is the
session Redactor (`[redacted]` for every configured secret value).

Changes (`internal/tui/inputmouse.go`, `internal/tui/mouse.go`, `internal/tui/model.go` only for
the view hook; no new clipboard code, no exec, no change to `clipboard.go` or `internal/config`):
- A separate input selection state (not the conversation `selection`): a left press inside the
  input starts it (the cursor still moves as in T501), motion with the left button extends it
  (positions outside the input are clamped to the input rows via `inputCellAt(..., true)`), and
  the release ends it. Pressing again anywhere clears an old selection.
- While a drag is active and moved, the selected cells of the input render in reverse video
  (`\x1b[7m`), like the conversation highlight; the input text itself is not changed.
- On release after a moved drag: the selected text is the plain text of the selected visual rows
  (ANSI stripped, trailing spaces trimmed per row, rows joined by `\n`), passed through
  `m.redact` before anything else, then `m.clip(text)` and the same notice/tick as the
  conversation copy. Empty text → nothing copied, no notice. A click without motion copies
  nothing. Factor the copy+notice step of `mouse.go` into one helper used by both selections.
- Only redacted text ever reaches `m.clip`; the selection is taken from what the input shows
  (paste placeholders such as `[Pasted text #1 +N lines]` are copied as shown, never expanded).

Tests (exact names) in `internal/tui/inputmouse_test.go` (use the fake clipboard pattern of
`copy_test.go`: `Options.Clipboard` recorder and the fake clock; for secrets build a session
model with `newSessionModel(t, providertest.New(...))`, whose config resolves the key to
`SECRET123`):
- `TestInputSelect`: input `hello world`; drag from the `h` to the `o` of `world` copies exactly
  `hello world` and the view shows `11 characters copied`; a drag over the second row of a
  2-line input copies only that row; a press and release at the same cell copies nothing; the
  conversation copy tests still pass.
- `TestInputSelectHighlight`: during the drag the view contains `\x1b[7m` on the input row
  (forced color profile as in `TestCopyHighlightReverse`), gone after release.
- `TestInputSelectSecretNeverCopied`: input `key SECRET123 end`; dragging over the whole row
  copies a text that contains `[redacted]` and never `SECRET123`; the notice counts the runes of
  the redacted text.
