# T403: Jev turn routing (easy/hard model per turn)

Phase 4 · Model: opus: picks which configured model runs a turn and sends the user's message to jev; failure must keep the configured model and never stall the turn (Consequential assumption 3) · Depends-on: T401 · Covers: R50 (score < 1 → `easy`, else `hard`, for the whole turn, shown on the status line), R52 (routing falls back to the configured model on error, timeout, low confidence)

## Brief
State before this task (`internal/agent`): `Submit(text)` appends the user message and starts
`runTurn` in a goroutine; `runTurn` calls `s.runLoop(ctx, gen, MainAgentID, hist, s.turnTools(mgr, spawned))`;
`toolSet.model` ("" = the session's current model) selects the model of every request of that
loop. `jev.go` provides `s.JevOn()`, `s.askJev(ctx, state, qs)` (redacts, ≤ 2000 runes, timeout),
`s.noteJev(answered bool)`, the field `turnRouted bool` (makes `account` count tokens as
`RoutingTokens`) and `s.cfg.Jev` (`MinConfidence`, `Route *config.JevRoute{Easy, Hard}` with model
ids validated at load). `provider.JevQuestion{Name, Type: provider.JevScore, Instructions, Levels}`,
`JevAnswer{Score, Confidence}`.

Changes (`loop.go`, `jev.go`; keep it small):
- At the start of each main-agent turn, inside the turn goroutine (so `Submit` still returns at
  once), when `s.JevOn()` and `cfg.Jev.Route != nil`: ask one score question (`Name: "difficulty"`,
  `Levels` = 3 ordered criteria `easy: …`, `medium: …`, `hard: …`, instructions about how hard the
  coding request is), state = `request: ` + the user's message of this turn.
- Use the answer only without error and with `Confidence >= MinConfidence`: `Score < 1` →
  `Route.Easy`, else `Route.Hard`; `noteJev(true)`; emit one `EvInfo` `jev route: <model id>`; set
  `toolSet.model` of the main loop to that id for the **whole turn** (every request, including after
  tool calls), set `turnRouted = true` for the turn, and record the id for
  `func (s *Session) TurnModel() string` (the routed model id of the running or last turn, "" when the
  turn was not routed). Otherwise `noteJev(false)` (only when jev was asked), the turn uses the
  session's model as before and `TurnModel()` is "".
- Not routed at all (no jev request): jev off, or no `route`. Subagents and `/compact` keep the
  session's model; `SetModel`/`ModelID` are never changed by routing.
- Reset `turnRouted` and `TurnModel()` at the start of every turn.

Tests (exact names) in `internal/agent/jev_route_test.go`, with `providertest.ConfigJSON` models
`fake/m1` (default) and `fake/m2` and `route = {"easy":"fake/m2","hard":"fake/m1"}`:
`TestJevRoute` (score 0 and 0.99 → every request of a turn with a tool call uses `m2`, `TurnModel()`
= `fake/m2`; after `SetModel("fake/m2")` score 1 and 2 → `m1`; next turn routes again),
`TestJevRouteFallback` (jev 500, timeout via `SetJevTimeout`, low confidence → session model,
`TurnModel() == ""`, `Fallbacks` counted, turn finishes), `TestJevRouteOff` (jev off, or no route →
no jev request), `TestJevRouteNoBlock` (`Submit` returns in < 100 ms while jev is delayed).

## Verification
`scripts/verify/v4/T403.sh` exits 0. It runs the named tests and a supervisor probe of easy/hard
routing across a tool-call turn, fallbacks, off cases and non-blocking submit; negatively it checks
that a fallback never switches the model, that jev is not called when off, that the session model is
never changed, and that `approval.go` and protected files are untouched.
