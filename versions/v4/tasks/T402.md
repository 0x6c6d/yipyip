# T402: Jev answers single-choice questions (with fallback)

Phase 4 · Model: opus: decides on the user's behalf and sends conversation text off the machine; every failure must fall back to asking the user (Consequential assumption 3) · Depends-on: T401 · Covers: R49 (confident choice answers the question; free-text, multiple, 1-option and low-confidence questions go to the user), R52 (error, timeout, low confidence fall back; the turn finishes)

## Brief
State before this task (`internal/agent`): `questionTool(ctx, agentID, args)` in `question.go`
parses `{question, options, multiple}` into a `QuestionRequest` (question and options already
redacted), emits `EvQuestion` and waits for the user's answer, which becomes the tool result.
`jev.go` provides `s.JevOn()`, `s.askJev(ctx, state, []provider.JevQuestion) ([]provider.JevAnswer, error)`
(redacts, cuts state to `JevStateLimit` = 2000 runes, 10 s timeout, counts input tokens),
`s.noteJev(answered bool)` and `s.cfg.Jev.MinConfidence`. `provider.JevQuestion{Name, Type,
Instructions, Choices map[string]string, Levels}`, `provider.JevChoice`, `JevAnswer{Choice, Confidence}`.

Change `question.go` (and `jev.go`/`loop.go` only as needed, at most ~100 lines of production code):
- Before emitting `EvQuestion`, when `s.JevOn()` and `!req.Multiple` and `len(req.Options) >= 2`:
  ask jev one choice question (`Name` e.g. `answer`, `Choices` = each option label → itself,
  instructions like "Pick the option the user would most likely choose."). State, in this order:
  `question: <q>`, `options: <labels>`, then `conversation:` and the tail of the conversation
  (the last runes of the user/assistant message contents of this turn's history, so that the
  whole state stays within 2000 runes; include the current turn's user message; you may pass the
  loop's current history to the question tool for this).
- Jev's answer is used only when there is no error, `Confidence >= MinConfidence` and `Choice` is
  exactly one of the options: then `noteJev(true)`, emit one `EvInfo` `jev answered: <question> → <label>`
  and return the label as the tool result (no `EvQuestion`). Otherwise `noteJev(false)` (only when
  jev was actually asked) and continue exactly as before (the user is asked).
- Jev off, `multiple=true`, fewer than 2 options (free text only or 1 option): jev is not asked,
  behaviour unchanged. Subagents never have the question tool; nothing changes there.
- No change to `approval.go`; cancel behaviour unchanged (a cancelled turn during the jev call
  returns `Cancelled` like before).

Tests (exact names) in `internal/agent/jev_question_test.go`: `TestJevQuestion` (confident 2-option
question → tool result is the label, no `EvQuestion`, `Answered == 1`; low confidence, choice not
in options, `multiple=true`, 1 option, 0 options and jev off → `EvQuestion`, and for the last four
the fake jev gets no request), `TestJevQuestionState` (the jev state contains the question, the
options and the user's message, never `SECRET123`), `TestJevFallback` (jev 500, 422, timeout via
`SetJevTimeout(150ms)` with fake `Delay`, low confidence → the user is asked, answering finishes the
turn, `Fallbacks` counts each). Answer prompts in tests by polling `PollEvents` and calling
`ev.Question.Respond(...)`.
