# T101: Skills loader, project dir (internal/skills)

Phase 1 · Model: opus: reads untrusted files under the start directory through PathGuard (Consequential assumption 6, confinement and bounded reads) · Depends-on: T000 · Covers: R45 (project skills, frontmatter, name rule, read-only)

## Brief
Create the new package `internal/skills` (files `internal/skills/skills.go`, `internal/skills/skills_test.go`).
It loads skills from `<startDir>/.yipyip/skills/` in this task; the global directory is added by a
later task, so `home` is accepted but not read yet.

Exported API (exactly these names; later tasks and the verification compile against them):
```go
type Source string
const (
    Global  Source = "global"
    Project Source = "project"
)
type Skill struct {
    Name, Description, Body string
    Source Source
}
func GlobalDir(home string) string      // filepath.Join(home, ".config", "yipyip", "skills")
func ProjectDir(startDir string) string // filepath.Join(startDir, ".yipyip", "skills")
// Parse parses one SKILL.md; folder is the name of the skill's folder.
func Parse(folder string, data []byte) (Skill, error)
// Load returns the loaded skills sorted by Name and one warning line per skipped entry.
func Load(home, startDir string) ([]Skill, []string)
```

Format of `<name>/SKILL.md` (hand-parsed, standard library only, no YAML package):
- The first line is exactly `---`; the frontmatter ends at the next line that is exactly `---`.
  Accept `\r\n` line endings. Missing opening line or no closing line → error.
- Between the markers: blank lines and lines starting with `#` are ignored; every other line is
  `key: value` (split at the first `:`, trim spaces; a value wrapped in matching `"` or `'` is
  unwrapped). A non-empty line without `:` → error. Unknown keys are ignored.
- `name` defaults to the folder name; the final name must match `^[a-z0-9-]+$`, else error.
  `description` defaults to `""`. `Body` = everything after the closing line, `strings.TrimSpace`d
  (an empty body is allowed).

Load rules (project directory):
- `startDir == ""` or a missing `.yipyip/skills` directory → no skills and no warning.
- Every project path (the skills directory, each `<folder>`, each `SKILL.md`) is checked with
  `tools.NewPathGuard(startDir)` / `Resolve` from `internal/tools/pathguard.go` (do not change that file and
  do not re-implement symlink checks). A path that resolves outside the start directory, e.g. a
  symlinked skill folder or a symlinked `SKILL.md` pointing outside, is skipped with one warning.
- Only directories are skill folders; a folder without `SKILL.md` is ignored silently.
- A `SKILL.md` larger than 256 KiB is skipped with one warning (check the size before reading, and
  never read more than 256 KiB + 1 bytes).
- Parse errors skip that skill with one warning. Two folders yielding the same `name` → the first
  in folder-name order is kept, the other skipped with a warning.
- Every warning is one line of the form `skill <folder>: <reason>` and names the folder.
- The package only reads: no file creation, write, rename, remove or mkdir; no `os/exec`, no `net/http`.
  Source of project skills is `Project`.

Tests in `internal/skills/skills_test.go` (temp dirs only; resolve `t.TempDir()` with
`filepath.EvalSymlinks`): `TestSkillLoadProject` (two skills, one without `name` defaulting to the
folder, sorted, fields and Source), `TestSkillFrontmatter` (quotes, comments, unknown keys, CRLF,
missing/unclosed frontmatter and invalid name → error from `Parse`), `TestSkillMissingDir`,
`TestSkillSymlinkEscape` (folder symlink and file symlink pointing outside → skipped, warnings),
`TestSkillTooLarge`.

## Verification
`scripts/verify/v4/T101.sh` exits 0. It runs the named tests plus a supervisor probe (an overlay test
file, nothing written to the repo) for loading, defaults and missing dir; negatively it checks that
symlinked skill folders/files escaping the start directory, oversized files and bad frontmatter are
never loaded, that the package contains no write/exec/http calls and that protected files are untouched.
