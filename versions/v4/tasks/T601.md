# T601: Shift+Enter removed (no modifyOtherKeys, no CSI mapping)

Phase 6 · Model: sonnet: removes a terminal escape request and a key mapping and adapts old tests, no security path · Depends-on: T000 · Covers: R36

## Brief
`shift+enter` has no special meaning any more; only `alt+enter` inserts a newline. The xterm
modifyOtherKeys request and the CSI mapping for it are removed, and `/help` / `--help` list only
`Alt+Enter` for the newline.

State before this task:
- `cmd/yip/main.go`: `launchUI` calls `defer enableKeyReporting(os.Stdout, stdoutIsTTY())()`;
  `keyReportingLevel` (= 1) and `enableKeyReporting(w, tty)` write `ESC [ > 4 ; 1 m` and restore
  `ESC [ > 4 ; 0 m`. `stdoutIsTTY` may become unused (remove it then; keep `stdinIsTTY`).
  `WithMouseCellMotion` and `WithAltScreen` stay.
- `internal/tui/keyseq.go`: `keyFromCSI(msg)` converts bubbletea's unexported
  `unknownCSISequenceMsg` (`ESC[27;2;13~`, `ESC[13;2u` → a `shift+enter` key; `ESC[27;3;13~` →
  Alt+Enter; `ESC[27;5;<letter>~` → Ctrl+letter). `Model.Update` (`model.go`) starts with
  `if k, ok := keyFromCSI(msg); ok { msg = k }`. The newline key binding in `model.go` is
  `key.WithKeys("alt+enter", "shift+enter")`.
- `internal/tui/help.go` has the row `{"Alt+Enter / Shift+Enter", "new line (Alt+Enter always; Shift+Enter if the terminal reports it)"}`.
- Existing v3 tests that assert the removed behaviour and must be adapted here:
  `internal/tui/newline_test.go` (`TestShiftEnterInsertsNewline`, helper `shiftEnter`; keep
  `TestAltEnterUnchanged`), `internal/tui/keyseq_test.go` (all of it; its
  `parseWithBubbletea`/`feedSequence` helpers are needed below — move them into
  `newline_test.go`), `internal/tui/help_test.go` (`TestHelpMentionsShiftEnter`,
  `TestHelpShiftEnterOneLine`, and `"Shift+Enter"` in the list of `TestHelpListsNewCommands`),
  `cmd/yip/main_test.go` (`TestHelpFlagMentionsShiftEnter`, the `shift+enter` check in
  `TestHelpFlagListsNewFeatures`, `TestKeyReportingRequestedOnlyOnTTY`).

Changes:
- `cmd/yip/main.go`: remove `keyReportingLevel`, `enableKeyReporting` and its call; no `\x1b[>4`
  is ever written. No comment or identifier in `cmd` or `internal` mentions `modifyOtherKeys`
  any more.
- Delete `internal/tui/keyseq.go` and `internal/tui/keyseq_test.go`; remove the `keyFromCSI` call
  from `Update`; the newline binding keeps only `alt+enter`.
- `help.go`: the newline row becomes `{"Alt+Enter", "new line"}`; no `Shift+Enter` anywhere in
  `HelpText()`.
- Adapt the tests listed above: delete the Shift+Enter-positive tests and assertions; keep all
  other assertions of those tests.

Tests (exact names):
- `internal/tui/newline_test.go`: `TestNewline`: with `a` typed, feeding the raw sequences
  `"\x1b[27;2;13~"` and `"\x1b[13;2u"` through `parseWithBubbletea` (every resulting message,
  key or not, sent to `Update`) leaves the input `a` (no newline, no stray characters), submits
  nothing (no blocks, no quit); `tea.KeyMsg{Type: tea.KeyEnter, Alt: true}` turns it into `a\n`.
- `internal/tui/help_test.go`: `TestHelp`: `HelpText()` contains `Alt+Enter` and not
  `Shift+Enter` (case-insensitive check for `shift+enter`).
- `cmd/yip/main_test.go`: `TestHelpFlagNoShiftEnter`: `run([]string{"--help"}, …)` exits 0, the
  output contains `Alt+Enter` and does not contain `shift+enter` (case-insensitive);
  `TestNoKeyReportingRequest`: `go/parser` over `main.go` finds no function named
  `enableKeyReporting` and the file source contains no `\x1b[>4` / `[>4;` escape.
