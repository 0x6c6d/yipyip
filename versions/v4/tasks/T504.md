# T504: Tab bar clicks: `×` closes, `+` opens, title switches

Phase 5 · Model: sonnet: mouse dispatch onto the existing close/add/switch paths, no new save or security logic · Depends-on: T503 · Covers: R43, R38 (Ctrl+T limit message unchanged; tab switching by click replaces the removed switch keys)

## Brief
Make the tab bar clickable. Assumption (spec gap): since the Ctrl+Tab / Alt+N switch keys are
removed in v4, a click on a tab's `<N>:<title>` (or a collapsed `…`) switches to that tab.

State before this task: `internal/tui/tabbar.go` has
`func (m Model) tabBarLayout() (line string, zones []tabZone)` with
`type tabZone struct{ start, end, tab int; kind tabZoneKind }` (display columns `[start, end)` on
screen row 0, kinds `tabZoneSwitch`, `tabZoneClose`, `tabZonePlus` with `tab == -1`); segments
are `<N>:<title> ×`, followed by ` +` when fewer than `maxTabs` (8) tabs are open.
`internal/tui/tabs.go` has `addTab() error` (`errTabLimit` at 8), `switchTab(i)` (out of range or
current: no change), `(m Model) closeTab() (Model, tea.Cmd)` (saves the current tab through the
exit save path, removes it, the left neighbour becomes current; with one tab it saves and
returns the quit command, exactly `/exit`), `tabOf(sess) int`. `model.go` handles `ctrl+t`
(`addTab`; on `errTabLimit` adds the info line `tabLimitMsg` = `tab limit reached`, other errors
as `error: …`; on success returns `m.waitEvent()`) and `ctrl+w` (`closeTab`).
`internal/tui/mouse.go` `Model.mouse` handles the wheel, then subtracts `tabBarRows` from `msg.Y`
for the conversation selection (and the input click/selection when present); a press on screen
row 0 currently does nothing.

Changes (`internal/tui/mouse.go`, `internal/tui/tabs.go`, `internal/tui/model.go`, optional new
`internal/tui/tabclick.go`):
- Move the Ctrl+T body into one method `func (m Model) openTab() (Model, tea.Cmd)` used by
  both the key and the `+` click (`/new` may keep its own call), so the limit message and errors are identical.
- A left-button press on screen row 0 (before the `tabBarRows` shift) is looked up in the zones of
  `tabBarLayout()` and handled before anything else; it never starts a conversation or input
  selection. Release and motion on row 0 do nothing.
  - `tabZonePlus` → `openTab()`.
  - `tabZoneClose` on the current tab → `closeTab()` (same as Ctrl+W, incl. quit on the last tab).
  - `tabZoneClose` on another tab i → that tab is saved and closed through the same `closeTab`
    path, and the tab that was current before the click stays current (find it again with
    `tabOf` of its session after the removal).
  - `tabZoneSwitch` → `switchTab(tab)`.
  - A press outside every zone (gaps, past the end) does nothing.
- No change to the save path, the session store or `closeTab`'s save/cancel logic.

Tests (exact names) in a new `internal/tui/tabclick_test.go` (use `newSessionModel`,
`answerServer`, `tabTurn`, `mustAddTab`, `readSavedFile`, `tabBarLine` from the existing test
files; find a button's column with `strings.Index` + `ansi.StringWidth` on `tabBarLine(m)` or from
the zones; send `tea.MouseMsg{X, Y: 0, Button: tea.MouseButtonLeft, Action: tea.MouseActionPress}`):
- `TestTabButtons`: tab 1 with a finished turn `tab one question`, plus tabs 2 and 3, tab 3
  current: clicking the `×` of tab 1 leaves 2 tabs with the former tab 3 still current and the
  saved file holds `tab one question` (and never `SECRET123`); clicking the `×` of the current
  tab selects its left neighbour; clicking `+` opens a new current tab; with 8 tabs the bar has no
  `+` and Ctrl+T adds exactly one `tab limit reached` line; clicking `×` on the only remaining tab
  returns the quit command and saves it (like `TestCtrlWLastTabExitsLikeExit`).
- `TestTabClickSwitch`: with 3 tabs a click on `1:` switches to tab 1, a click on `2:` to tab 2;
  a click on the gap between segments or right of the bar changes nothing; no click on row 0
  writes to the clipboard (`Options.Clipboard` recorder) or moves the input cursor.
