## Brief
Document v4 for users and for future agents. Code is finished; change only `docs/usage.md`,
`CLAUDE.md` (outside its "Delegation workflow" section), `internal/tui/help.go` and
`internal/tui/help_test.go` (fix production code only if a doc example exposes a real bug, and
say so). `README.md` is the spec and stays unchanged.

What v4 added or changed (read the code to get exact names, messages and defaults):
- Skills: `<name>/SKILL.md` folders (frontmatter `name`, `description`, then the body) in
  `~/.config/yipyip/skills/` and `<startdir>/.yipyip/skills/` (project wins on the same name);
  `/<name> [args]` sends the body (args appended after a blank line) as a user message;
  built-in commands win over skills of the same name; `/skills` lists them with source and
  shadow note; skills appear in `/` suggestions; bad files are skipped with one warning line.
  Code: `internal/skills` (loader), `internal/tui` (`/skills`, dispatch).
- Jev (System One decisions): config block `jev` (`baseURL`, `apiKey` as `{env:TYPESAFE_API_KEY}`,
  `route.easy`/`route.hard` = configured `provider/model` ids, and the other keys and defaults in
  `internal/config`); the jev host is reachable only while `jev` is configured; `/jev` toggles
  (off at start, `jev is not configured` without the block), `/jev stats` counters; with jev on:
  single-choice questions with ≥ 2 options can be answered by jev, each turn can be routed to the
  `easy`/`hard` model, and in auto mode a risky tool call is turned into an approval prompt;
  any jev error, timeout or low confidence falls back to the old behaviour. Code:
  `internal/provider/jev.go` (client), `internal/provider/providertest` (fake System One
  endpoint), `internal/agent/jev.go` (decider), the risk-screen hook in `internal/agent/approval.go`,
  `internal/tui` `/jev` and status line (`jev`, `route: <id>`).
- Input: a left click moves the cursor; dragging in the input selects and copies (redacted).
- Tabs: segments `N:<title> ×`, a `+` after the last one (not at 8 tabs); click a title to
  switch, `×` to close (saved first), `+` to open; the bar always fits one row. Hotkeys are only
  `Ctrl+T` and `Ctrl+W`; `Ctrl+Tab`, `Ctrl+Shift+Tab` and `Alt+1`–`Alt+8` are gone.
- Newline: only `Alt+Enter`; Shift+Enter has no special meaning (the key-reporting request and
  the tmux `extended-keys` advice are gone).
- Questions render inline in the conversation and leave a line `Q: … → A: …`.
