# T602: Question rendered inline in the transcript

Phase 6 · Model: opus: moves model-authored and user-typed text into the selectable transcript, must stay redacted (`SECRET123` negative, R16/R21) · Depends-on: T000 · Covers: R39

## Brief
The pending question of the `question` tool is no longer a centered overlay: it renders as a
block inside the conversation transcript, below the last message, scrolling with it. Once it is
answered (or cancelled) the block is replaced by one answer line `Q: <question> → A: <answer>`.
Keys, tool results and cancel behaviour stay exactly as they are.

State before this task (`internal/tui`):
- `question.go`: pending queue `m.questions []*agent.QuestionRequest` and state `m.qs`
  (`row`, `marks`, `text`), `enqueueQuestion`, `cancelQuestions`, `closeQuestion(answer)`
  (answers the first request with `Respond`, shows the next one), `questionResult()`,
  `questionKey(k)` (↑/↓/j/k move, Space toggles, runes on the free row type, Backspace, Enter
  confirms, Esc → `agent.Cancelled` = `cancelled`; every key is swallowed while a question is
  pending), `questionBox()` (rounded border; title `Question`, the redacted question, one row per
  option with `○`/`●` or `[ ]`/`[x]`, the free row `type your own answer[: text]█`, the hint
  `questionHint`) and `overlayQuestion(vp)` = `m.overlayCentered(vp, m.questionBox())`.
- `model.go`: `overlays(vp)` shows `overlayQuestion` when `len(m.questions) > 0` (and no
  approval is pending); `refreshTo(follow)` renders `m.blocks` with `m.renderBlock` into
  `m.lines` and the viewport; blocks keep raw text and are redacted when rendered
  (`m.redact`). `mouse.go` maps screen rows to `m.lines` through `viewRows()` (which runs
  `overlays`), so copy-on-select copies whatever is in `m.lines`.
- Existing v3 tests assert the overlay and must be adapted by this task (keep their names):
  `internal/tui/question_test.go` (`askQuestion` comment/message, `countMarked` relies on the
  `│` border, `TestQuestionOverlaySingleChoiceRadio`, `TestQuestionOverlayMultipleCheckbox`,
  `TestQuestionRedactsSecretInPrompt`, …) and `e2e/question_test.go` (`startQuestion`, the
  "overlay still shown" / "overlay lacks" checks). The agent side (`internal/agent/question.go`)
  and jev-answered questions (info line `jev answered: …`) do not change.

Changes (`question.go`, `model.go`, `blocks.go`, the two test files above, a new test file):
- While `len(m.questions) > 0`, `refreshTo` appends the box of the first pending question after
  the last rendered block (separated like blocks are), left-aligned, width
  `max(20, min(questionMaxW, viewport width - 4))`, and follows to the bottom when the question
  appears. Every change of the question state (move, toggle, typing, next question) re-renders
  the content. The box is a live element, not an entry of `m.blocks`.
- Every text of the inline box, including the user's free text, passes `m.redact` (it is now
  part of `m.lines` and therefore copyable); `SECRET123` never reaches `m.lines`, `View()` or the
  clipboard.
- On Enter (with an answer) or Esc, `closeQuestion` also appends one permanent block with the raw
  text `Q: <question> → A: <answer>` (question with newlines folded to spaces; answer = the
  tool result: label(s) joined `, `, the free text, or `cancelled`), rendered redacted and dim
  (an info-style block kind of your choice). `cancelQuestions` (turn cancelled, tab closed) adds
  the line `Q: <question> → A: cancelled` for each cancelled question.
- Remove the question branch of `overlays` and delete `overlayQuestion`; the approval prompt,
  picker and completions overlays stay as they are.

Tests (exact names) in a new `internal/tui/question_inline_test.go` (reuse `askQuestion`,
`press`, `questionToolResult`, `plain` from `question_test.go`):
- `TestQuestionInline`: after the user message `ask me` the view shows the question box below
  it (the line with `ask me` comes before the `Question` title line), the box's free row is in
  `m.lines`, `overlayQuestion` is gone (the viewport rows above the box show the normal
  conversation); Down, Space, Enter → the tool result is `b`, the view contains
  `Q: Which one? → A: b` and no longer `type your own answer`; Esc on a second question →
  `Q: … → A: cancelled`.
- `TestQuestionInlineScrolls`: with a long conversation before the question the box is at the
  bottom of the view; PgUp/wheel (whatever scrolls the viewport while a question is pending, or
  `m.viewport.ScrollUp` directly) moves the box out of the visible rows.
- `TestQuestionInlineSecret`: a question `use SECRET123?` with option `yes SECRET123` and free
  text `my SECRET123` typed: neither `View()` nor `strings.Join(m.lines, "\n")` ever contains
  `SECRET123` (they show `[redacted]`), the answer line reads `A: my [redacted]`, and dragging
  over the box and the answer line copies no `SECRET123` (fake clipboard).
