# T202: Skill run: built-in wins, redaction, startup warnings

Phase 2 · Model: opus: skill text is untrusted and must be redacted before transcript, model history and session file (Consequential assumption 5) · Depends-on: T102, T201 · Covers: R45 (built-in wins, redactor before view/session file, one warning line per skipped skill, skills grant nothing)

## Brief
State before this task: `internal/skills` exports `Load(home, startDir) ([]Skill, []string)`
(global + project, project wins, warning lines for skipped entries) and
`Skill{Name, Description, Body string; Source Source}`. `internal/tui` has `Options.Home`, loads the
skills once in `New` (stored on `Model`, global for all tabs), and `runSlash` in `commands.go` runs
`/<name> [args]` for a loaded skill after the built-in `slashCommands` lookup: the message
`Body` (+ `"\n\n" + args` when args are given) is submitted through the same helper `Command` uses.

Changes (in `internal/tui`, mainly `commands.go`, `model.go`, a new `skills.go` if useful):
1. Built-in wins: a skill whose `"/"+Name` is a key of `slashCommands` is never run by
   `/<name>`; the built-in runs as before (e.g. a project skill `help` → `/help` shows the help text
   and sends nothing to the model). Keep this decision in one function
   (e.g. `shadowed(name string) bool`) that later tasks reuse.
2. Redaction: the skill message (body and args) is passed through the session's redactor
   (`m.redact(...)`, which calls `agent.Session.Redact` and so `config.Redactor`) **before**
   `Submit`, so the agent history, every request to the model and the saved session file only
   ever contain `[redacted]` instead of a configured secret. The transcript line is redacted too
   (blocks are already redacted on render; do not bypass that). Do not add any redaction logic of
   your own and do not change `internal/config/redact.go`.
3. Startup warnings: each warning line returned by `skills.Load` in `New` is added to the
   transcript as one info line `warning: <line>` (redacted on render like every block).
4. Skills grant nothing: no change to the approval gate, mode, tools or "always" state.

Tests in `internal/tui/skill_test.go` (use `newSessionModelOpts`; its config uses the API key
`SECRET123`; write skills under `opts.StartDir` and set `opts.Home` to a temp home in the edit func):
- `TestSkillBuiltinWins`: project skill `help` with body `SKILLBODY` → `/help` shows the help text,
  the fake provider gets no request, and `SKILLBODY` is not in the view.
- `TestSkillSecretRedacted`: skill body and args both contain `SECRET123`; after the turn no
  request message, no `View()` and no session data passed to `Options.SaveOnExit` on `/exit`
  (marshal it with `encoding/json`) contains `SECRET123`, while `[redacted]` reached the model.
- `TestSkillWarnings`: one bad project skill (invalid name) and one good → exactly one
  `warning:` line in the view naming the bad folder; the good skill still runs.
- `TestSkillArgsAppended`: a global-only skill runs with args after a blank line.
