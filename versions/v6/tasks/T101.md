# T101: Config: optional search block

Phase 1 · Model: opus: new public config schema holding a secret, https/loopback rule and error texts that must never echo values (Consequential assumptions 4, 5, 6) · Depends-on: T000 · Covers: R57, R3 (config part: the search URL never enters the provider allowlist)

## Brief
State before this task: `internal/config` loads `~/.config/yipyip/config.json` merged key by key
with `<startdir>/yipyip.json` (`Load(home, startDir, getenv)`), substitutes `{env:NAME}` in every
string (unset/empty → `*MissingEnvError` naming `NAME`; every resolved value is registered with
`Config.Redactor`; `Config.EnvNames` lists every referenced `NAME`) and then runs `(*Config).fill()`
in `config.go`, which parses known keys. `jev.go` is the model to follow: `fillJev` parses the
optional `"jev"` object with the helpers `asObject`, `optString`, `typeError` (errors name the JSON
path only, never a value). `AllowedBaseURLs()` (in `jev.go`) returns the provider base URLs plus
`jev.baseURL`; the HTTP transport for provider and jev calls is built from it.

Create `internal/config/search.go` and add one call in `fill()` plus one field in `Config`
(`config.go`). Do not change `redact.go`, `env.go` or `jev.go`.
- `const DefaultSearchBaseURL = "https://api.search.brave.com"`.
- `type Search struct { BaseURL string; APIKey string }` (doc comment: the `"search"` object;
  `BaseURL` without trailing `/`, `APIKey` the resolved key).
- `Config.Search *Search` (doc comment: `"search"`, nil when absent). Without a `"search"` key
  `Config.Search` is nil and nothing else changes.
- `fillSearch(v any) error`, called from `fill()` when the key `"search"` exists:
  - not an object → error naming `search` (use `asObject`).
  - `"apiKey"` is required: absent, not a string, or empty after `{env:}` resolution → error
    naming `search.apiKey` (e.g. `config: "search.apiKey" is required` /
    `config: "search.apiKey" must be a non-empty string`). An unset `{env:BRAVE_API_KEY}` is already
    reported by the env resolver as a `*MissingEnvError` naming `BRAVE_API_KEY`; keep that.
  - A literal (non-`{env:}`) `apiKey` is accepted and registered with `c.Redactor.Add(key)` so it
    is redacted everywhere like an `{env:}` value.
  - `"baseURL"` optional, default `DefaultSearchBaseURL`; must be a string that parses as an
    absolute URL with a non-empty host and scheme `https`, or scheme `http` only when the host
    (case-insensitive, without port) is exactly `127.0.0.1`, `::1` or `localhost`. Anything else
    (other http hosts such as `127.0.0.2` or `localhost.example.com`, `ftp:`, no host, not a
    string) → error naming `search.baseURL`, e.g.
    `config: "search.baseURL" must be an https URL (http only for 127.0.0.1, ::1 or localhost)`.
    A trailing `/` is trimmed (`strings.TrimRight(base, "/")`).
  - No error text ever contains the given baseURL, the key or any other config value.
- The project file `yipyip.json` may set `"search"` like any other key (normal merge).
- `AllowedBaseURLs()` and `BaseURLs()` stay unchanged: the search URL never appears in them (the
  search client gets its own transport in a later task).

Tests (exact names) in a new `internal/config/search_test.go` (temp HOME and start dir, `getenv`
stub; `BRAVE_API_KEY` resolves to a fake value such as `BRAVEVAL1`, never a real key):
- `TestSearchConfigLoad`: `{"search":{"apiKey":"{env:BRAVE_API_KEY}"}}` → `Search.APIKey` is the
  fake value, `EnvNames` contains `BRAVE_API_KEY`, `Redactor.Redact` hides the value.
- `TestSearchConfigDefaults`: no `baseURL` → `DefaultSearchBaseURL`; `"http://127.0.0.1:8080/"`,
  `"http://localhost:9"`, `"http://[::1]:7/"`, `"https://search.example.org/"` load with the
  trailing `/` trimmed.
- `TestSearchConfigAbsent`: no `"search"` key → `Search == nil`.
- `TestSearchConfigMissingKey`: no `apiKey`, `"apiKey": ""`, `"apiKey": 7` → error naming
  `search.apiKey`; `{env:BRAVE_API_KEY}` unset → error naming `BRAVE_API_KEY`.
- `TestSearchConfigNonHTTPS`: `http://example.com`, `http://127.0.0.2:9`,
  `http://localhost.example.com`, `ftp://127.0.0.1`, `https://`, `"baseURL": 7`, `"search": "on"`
  are rejected; the error names `search.baseURL` (or `search` for the non-object) and does not
  contain the given URL's host.
- `TestSearchConfigNoEcho`: with a resolved key `SECRET123` and an invalid `baseURL`, the error
  contains neither `SECRET123` nor the URL; a literal `"apiKey":"LITERALKEY1"` is redacted by
  `Config.Redactor`.
- `TestSearchNotInAllowedBaseURLs`: with providers, `jev` and `search` configured,
  `AllowedBaseURLs()` and `BaseURLs()` do not contain the search base URL.
- `TestSearchConfigProject`: `"search"` only in the project `yipyip.json` loads.
