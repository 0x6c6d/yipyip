# T204: TUI: approval summary shows the query, /help line

Phase 2 · Model: sonnet: small TUI rendering and help text change, the gate itself is untouched · Depends-on: T000 · Covers: R60 (the prompt shows the query text), R57 (help names the `search` block and `BRAVE_API_KEY`)

## Brief
State before this task: `internal/tui/approval.go` renders the approval prompt for the first
pending `*agent.ApprovalRequest{AgentID, Tool, Args}` as `[<agent>] <tool>` plus a summary and the
hint `y / n / a`; `argsSummary(tool, args string) string` returns the `command` for `bash`, the
`path` for `write_file`/`edit_file`/`read_file`, otherwise the raw JSON args (all text is redacted
and shortened in `approvalLines`). `internal/tui/help.go` `HelpText()` returns one line per slash
command, the `/<skill> [args]` line, then a `Keys:` block; it is shown by `/help` and `yip --help`
and must never contain `cost`, `$` or `price`. Existing tests: `internal/tui/approval_test.go`
(`waitPrompt`, `keyRunes`, `newSessionModel`) and `internal/tui/help_test.go`.

Change `internal/tui/approval.go` and `internal/tui/help.go` only (plus tests):
- `argsSummary`: for tool `web_search` return the string value of `query` (fallback to the raw
  args as for other tools when it is missing or not a string). The prompt therefore shows
  `[main] web_search` (or the subagent id) and the query text; `y`, `n`, `a` work as for `bash`
  (no change to the key handling).
- `HelpText()`: after the `Keys:` block append a blank line and a `Web search:` block with one
  line: `  web_search  search the web (Brave) when a "search" block is configured, key from
  BRAVE_API_KEY; asks for approval in manual mode` (one line, wording may vary slightly but it
  must contain `web_search`, `"search"` and `BRAVE_API_KEY`).

Tests (exact names):
- `TestApprovalWebSearchQuery` (in `internal/tui/approval_websearch_test.go`): `argsSummary("web_search",
  `{"query":"golang generics","count":3}`) == "golang generics"`; a model with a pending
  `web_search` request (build one through a session with a scripted `web_search` call, or add the
  request the way the existing approval tests do) renders `web_search`, `golang generics` and
  `y / n / a`, and not `"count"`; a missing `query` falls back to the raw args.
- `TestApprovalWebSearchSecret`: a query containing a resolved secret (`SECRET123`, as in the
  existing TUI Secret tests) is shown as `[redacted]` in the prompt.
- `TestHelpWebSearch` (in `internal/tui/help_test.go` or a new file): `HelpText()` contains
  `web_search`, `"search"` and `BRAVE_API_KEY`, and still none of `cost`, `$`, `price`.
Keep all existing TUI tests green (`TestHelp*`, `TestApproval*`). Known side effect: the existing
`TestHelpCommand` (`internal/tui/commands_test.go`) renders `/help` in the default test window,

change to it, and no other existing test may change).
