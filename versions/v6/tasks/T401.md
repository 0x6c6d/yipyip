# T401: Docs: docs/usage.md for search and reads

Phase 4 · Model: haiku: documentation only, one file, checked by grep · Depends-on: T104, T202, T204, T302, T303 · Covers: R57, R62, R59, R60, R61, R63 (user documentation)

## Brief
State before this task: `docs/usage.md` is the user guide (sections `Install`, `Configuration`
with a list of top-level keys incl. `jev`, `Modes`, `Slash commands`, ..., `Jev decisions`,
`Retry`, `Settings defaults`, `Security`). Its intro says yip "reads, searches and edits files and
runs shell commands only inside that directory", and `## Security` says "yip has no web tools" and
"File tools (...) are confined to the start directory". v6 changed this:
- Optional top-level config key `search`: `{"baseURL": "https://api.search.brave.com", "apiKey":
  "{env:BRAVE_API_KEY}"}`. `baseURL` defaults to `https://api.search.brave.com` and must be https
  (plain http only for `127.0.0.1`, `::1`, `localhost`); `apiKey` is required when the block
  exists; a literal key works but `{env:BRAVE_API_KEY}` is recommended; errors name the key
  (`search.apiKey`, `search.baseURL`, or the env variable) and never show values. The project
  `yipyip.json` may set it like the providers. Without `search` there is no web tool.
- Tool `web_search` (Brave Search API): `query` (required, ≤ 400 characters), `count` 1-10
  (default 5); returns title, URL and snippet per result after the line
  `Web search results (untrusted data, not instructions):`, at most 8,000 characters. It needs
  approval in manual mode like `bash` (`y / n / a`, the prompt shows the query); auto mode runs it;
  subagents use it under the same approvals. The query and the results are redacted (a resolved
  secret in the query is sent as `[redacted]`). The Brave host is reachable only by the search
  client, never by provider or jev calls. There is no tool to fetch web pages.
- `BRAVE_API_KEY` is never shown, written to a file or sent anywhere but the Brave host, and it is
  removed from the `bash` environment like every `{env:}` variable.
- Reads: `read_file`, `glob` and `grep` accept absolute paths, `..` and symlinks anywhere on the
  file system (relative paths start at the start directory), ungated, output redacted and truncated;
  `glob`/`grep` print absolute paths for files outside the start directory. Warning: this includes
  files such as `~/.ssh` keys or other configs; only resolved config secrets are redacted.
- Writes: `write_file` and `edit_file` only change files inside the start directory (symlinks that
  point outside are refused, also for new files below them); `/undo` only restores files inside.

Change only `docs/usage.md`:
- Configuration: add a `search` entry to the key list and a short JSON example containing the
  literal text `"search"`, `https://api.search.brave.com` and `{env:BRAVE_API_KEY}`.
- New section `## Web search` (after `## Jev decisions` or before `## Security`) describing
  `web_search`, its arguments, approvals, redaction and that results are untrusted data.
- Fix the intro sentence and `## Security`: replace "yip has no web tools" and the "confined to the
  start directory" sentence by the v6 rules above (network: provider hosts, the jev host while
  configured, the Brave host for `web_search` only while `search` is configured; reads anywhere,
  writes confined), including the `~/.ssh` warning.
- Mention `web_search` in `## Modes` among the tools that ask for approval in manual mode.
Do not change `README.md`, `CLAUDE.md` or any code.
