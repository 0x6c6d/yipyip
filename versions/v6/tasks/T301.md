# T301: PathGuard read mode ResolveRead (pathguard.go)

Phase 3 · Model: opus: changes the security-critical path confinement `pathguard.go` (Consequential assumption 1, Risk "PathGuard") · Depends-on: T000 · Covers: R62 (resolution part), R63 (write mode stays confined), R4

## Brief
State before this task: `internal/tools/pathguard.go` defines `PathGuard` (`NewPathGuard(startDir)`,
`Root()`), `ErrOutsideStartDir`, and `(*PathGuard).Resolve(p)`: empty path or NUL byte → error;
relative paths are joined to the root; the path is cleaned; the deepest existing ancestor is
`filepath.EvalSymlinks`-resolved (a dangling symlink or broken chain is an error, never followed)
and the non-existing rest is appended; a result outside the root → error wrapping
`ErrOutsideStartDir`. Every confined caller uses `Resolve`: `write_file`, `edit_file`, the undo
journal, the session store, project skills, `AGENTS.md` (and, until T302, `read_file`/`glob`/`grep`).

Change `internal/tools/pathguard.go` (this is the one task allowed to change it) and its test:
- `Resolve` keeps exactly today's semantics (write mode: confined). Update its doc comment to say
  it is the write-mode resolution used by every caller that writes or must stay inside.
- New `func (g *PathGuard) ResolveRead(p string) (string, error)` (read mode): the same steps as
  `Resolve` (empty/NUL → error, relative paths start at the root, clean, resolve the deepest
  existing ancestor with `EvalSymlinks`, dangling symlink → error, append the non-existing rest)
  but without the inside-the-root check: absolute paths, `..` and symlinks may resolve anywhere on
  the file system. Share the resolution code between both methods (one unexported helper); do not
  duplicate it. Update the type and package doc comments (the guard confines writes; reads use
  `ResolveRead`).
- No other file changes (callers are switched in a later task).

Tests (exact names) in `internal/tools/pathguard_test.go` (keep every existing `TestGuard*` test
unchanged and green); use a temp base dir with `start/` as root and `outside/` next to it, both
symlink-resolved:
- `TestGuardReadAbsoluteOutside`: `ResolveRead(<outside>/f.txt)` returns that path.
- `TestGuardReadDotDot`: `ResolveRead("../outside/f.txt")` returns `<outside>/f.txt`.
- `TestGuardReadSymlinkOutside`: `start/link` → `outside`; `ResolveRead("link/f.txt")` returns
  `<outside>/f.txt`; `ResolveRead("x.txt")` returns `<root>/x.txt`; `ResolveRead("/")` returns `/`.
- `TestGuardReadErrors`: `""`, a path with a NUL byte and a dangling symlink are errors.
- `TestGuardWriteStillConfined`: `Resolve` rejects with `ErrOutsideStartDir` the absolute outside
  path, `../outside/new.txt`, `link/f.txt`, `link/sub/new.txt` (new file below an outside symlink)
  and `link` itself; it still accepts `x.txt` and `sub/new.txt`.
