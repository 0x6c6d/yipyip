# T203: e2e: web_search Secret tests

Phase 2 · Model: opus: the end-to-end proof that no secret reaches the search service, the model, the UI or a file (Risk "Secrets", Consequential assumptions 11 and 16) · Depends-on: T202 · Covers: R61, R57 (`BRAVE_API_KEY` redacted and stripped from `bash`), R59

## Brief
State before this task: the agent session registers the gated `web_search` tool when the config
has a `"search"` block (`{"baseURL": ..., "apiKey": ...}`); the tool redacts the query before
sending it to Brave and redacts the results; `{env:NAME}` values are registered with the config
Redactor and every `{env:}` variable is stripped from the `bash` environment (`StripEnv`). The e2e
package (`e2e/helpers_test.go`) builds an environment with `newEnvServer(t, srv, envOpts{contextLimit,
projectJSON, noModel})`: temp HOME and start dir, global config from
`providertest.ConfigJSON(srv.URL, "{env:FAKE_KEY}", limit)`, a `getenv` stub (`FAKE_KEY` →
`SECRET123`, `TYPESAFE_API_KEY` → `JEVKEY-E2E`), auto mode, and a TUI model; `e.submit(t, text)`
runs a turn and drains events into `e.Model`; `e2e/secret_test.go` has `filesUnder`, `mustContain`,
`mustNotContain`. The fake Brave endpoint is `providertest.NewBrave(fn)` (`BraveResponse{Results:
[]BraveResult{Title, URL, Description}}`, `Requests()` with `Query url.Values`).

Change only files in `e2e/` (test code): in `helpers_test.go` add `BRAVE_API_KEY` →
`BRAVEKEY-E2E` to the `getenv` stub (nothing else there changes), and create
`e2e/websearch_secret_test.go` with these tests (exact names):
- `TestSecretWebSearchE2E`: fake provider scripting one `web_search` call with query
  `look up SECRET123 please` and then a text reply; project `yipyip.json` with
  `{"search":{"baseURL":<brave.URL>,"apiKey":"{env:BRAVE_API_KEY}"}}`; Brave returns a result whose
  title, URL and snippet contain `SECRET123` and `BRAVEKEY-E2E`. Assert: the Brave request's `q`
  contains `[redacted]` and not `SECRET123`; its `X-Subscription-Token` is `BRAVEKEY-E2E` (the key
  is really used there); neither `SECRET123` nor `BRAVEKEY-E2E` appears in `e.Model.View()`, the
  status line, any provider request body, `e.Session.History()`, or any file under HOME or the
  start directory; the view shows the redacted result (`[redacted]`).
- `TestSecretBraveKeyNotInBashEnv`: with the real environment also holding `BRAVE_API_KEY`
  (`t.Setenv`) and the same `search` block, a scripted `bash` call `echo "k=$BRAVE_API_KEY"` →
  the tool result shows `k=` with nothing after it, and `BRAVEKEY-E2E` appears nowhere in the view
  or provider requests.
Keep every existing e2e test green; never contact a real host.
