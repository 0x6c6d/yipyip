# T302: read_file, glob, grep read anywhere; writes stay confined

Phase 3 · Model: sonnet: switches file tools to the opus-built `ResolveRead`, no confinement logic of its own; the supervisor runs the write-escape negatives itself · Depends-on: T301 · Covers: R62, R63 (write tools part), R4

## Brief
State before this task: `internal/tools/pathguard.go` (T301) offers `Resolve(p)` (write mode:
confined, escapes wrap `ErrOutsideStartDir`) and `ResolveRead(p)` (read mode: absolute paths, `..`
and symlinks may resolve anywhere; empty/NUL/dangling symlink → error). In `internal/tools`,
`files.go` `runReadFile`, `runWriteFile`, `runEditFile` and `search.go` `searchTarget` (used by
`glob` and `grep`) all call `r.guard.Resolve`; output paths are made relative to the start
directory with `r.relPath(abs)`. `Registry.Run` redacts every output; `Truncate` cuts long output.
Tests `TestReadFileOutside` (`files_test.go`) and `TestSearchPathEscape` (`search_test.go`) assert
that reads outside are refused; this behaviour is intentionally removed by v6 (R62).

Change `internal/tools/files.go` and `internal/tools/search.go` (do not change `pathguard.go`,
`registry.go`, `bash.go` or any other file):
- `runReadFile` and `searchTarget` call `r.guard.ResolveRead`; `runWriteFile` and `runEditFile`
  keep `r.guard.Resolve` (unchanged behaviour: a path whose resolved form is outside the start
  directory is an error result, nothing is written and the `BeforeWrite` hook is not called).
- A display helper `displayPath(abs string) string`: the start-directory-relative slash path when
  `r.guard.Resolve(abs)` succeeds (reuse the guard, never re-implement the inside check), else the
  absolute path. `read_file` errors, `glob` results and `grep` `path:line:text` hits use it, so
  inside files print as before and outside files print absolute paths.
- `grep`'s optional `glob` filter: inside files are matched as before; for files outside the start
  directory the filter is matched against the path relative to the searched directory.
- Output is still redacted (by `Registry.Run`) and truncated exactly as before; reads stay ungated.
- Tool descriptions: `read_file`, `glob`, `grep` say they read any path (relative paths start at
  the start directory); `write_file`, `edit_file` keep "inside the start directory".

Tests (exact names); delete `TestReadFileOutside` and `TestSearchPathEscape` (replaced) and keep all
other existing tests green. Use a temp base with `start/` (root), `outside/` holding `secret.txt`
(`TOPSECRET` plus the line `key SECRET123`) and `start/link` → `outside`, a Redactor knowing
`SECRET123`:
- `TestReadFileAnywhere`: `read_file` of the absolute outside path, `../outside/secret.txt` and
  `link/secret.txt` returns `TOPSECRET`; inside reads work as before.
- `TestReadGlobOutside`: `glob` `*.txt` with `path` = absolute outside dir, `../outside` and `link`
  lists `secret.txt` with its absolute path; inside globs still print relative paths.
- `TestReadGrepOutside`: `grep` `TOPSECRET` with those three paths finds the line, printed as
  `<abs path>:1:TOPSECRET`.
- `TestReadEtcStyle`: `read_file` of `/etc/passwd` (skip if it does not exist) succeeds and is not
  an error result.
- `TestReadRedactedOutside`: the outside file's `SECRET123` comes back as `[redacted]` from
  `read_file` and `grep`.
- `TestReadDanglingSymlink`: a dangling symlink is an error result for `read_file`, `glob`, `grep`.
- `TestWriteConfined`: `write_file` and `edit_file` with the absolute outside path,
  `../outside/x.txt`, `link/x.txt`, `link/secret.txt` and `link/sub/new.txt` return error results
  containing `outside the start directory`; no file is created or changed under `outside/` and the
  `BeforeWrite` hook is never called.

## Verification
`scripts/verify/v6/T302.sh` exits 0. It runs the named tests, the spec commands `go test
./internal/tools -run Read` and `-run Write`, and a supervisor probe: positively outside files are
read, globbed and grepped (absolute paths, redacted); negatively every write/edit escape (absolute,
`..`, outside symlink, new file below an outside symlink) must fail with nothing written and the
hook never called. It checks that only `files.go`, `search.go` and their tests changed and that
`write_file`/`edit_file` still call `Resolve`.
