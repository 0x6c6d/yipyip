# T503: TUI approval prompt shows the web_fetch URL

Phase 5 · Model: opus: what the user sees before approving a network call, redacted (Consequential assumption #12) · Depends-on: T401, T403 · Covers: R71 (manual mode prompt shows the URL), R69 (URL redacted before it is shown)

## Brief
v8 adds the gated tool `web_fetch` with one argument `url` (already registered and gated). In manual mode the
TUI approval prompt must show the URL, the way it shows the query for `web_search`. Edit only `internal/tui/approval.go`
and add a test file.

`internal/tui/approval.go`, function `argsSummary(tool, args string) string`: add `case "web_fetch": key = "url"`
next to the `web_search` case. The summary already passes through `m.redact` and is shortened by the caller; keep
that, so a secret in the URL is shown as `[redacted]`. Without a string `url` field the raw arguments are shown, as for
the other tools.

New tests in `internal/tui/approval_webfetch_test.go` (package `tui`; build the model like `approval_websearch_test.go`
does, with the fake provider scripting a `web_fetch` tool call; the session starts in manual mode for the prompt; never
let the session reach a real host: use a URL like `http://127.0.0.1:9/doc` and deny, or check the prompt only):
- `TestApprovalWebFetchURL`: `argsSummary("web_fetch", `{"url":"http://127.0.0.1:9/doc"}`)` is
  `http://127.0.0.1:9/doc`; with `{}` it falls back to `{}`; in the running model the view shows `[main] web_fetch`,
  the URL and `y / n / a`, and the prompt does not show the raw JSON key `"url"`.
- `TestApprovalWebFetchSecret`: a URL containing `SECRET123` (the fake provider's key) is shown with `[redacted]` and the
  view never contains `SECRET123`.

## Verification
