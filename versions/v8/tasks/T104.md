# T104: Remove jev from internal/config (leftover key ignored)

Phase 1 · Model: opus: config schema change and the leftover-key / `{env:}` secret rule (Consequential assumptions #3, #4) · Depends-on: T103 · Covers: R47-R56 removed (config part), §4 "a leftover `jev` key is ignored without error or warning", changed network rule (jev host gone)

## Brief
v8 removes jev (an external turn-routing service). No other package uses the config's jev API any more
(done before this task). This task removes it from `internal/config`. A user's old config may still contain
a `jev` block: it must load without error or warning, as an ordinary unknown key.

Delete:
- `internal/config/jev.go` (`DefaultJevBaseURL`, `DefaultJevModel`, `DefaultJevMinConfidence`, `Jev`,
  `JevRoute`, `fillJev`, `AllowedBaseURLs`, `validJevURL`, `parseJevRoute`)
- `internal/config/jev_test.go`

Edit:
- `internal/config/config.go`: remove the `Jev` field of `Config` and the `c.Raw["jev"]` branch in `fill()`.
  Unknown top-level keys are already ignored; do not add any code that names the old key.
  `{env:NAME}` substitution keeps running over the whole merged config (every string, unknown keys
  included), exactly as today: a leftover block with an unset variable still fails like in v1–v7, and a
  resolved value is still registered with the Redactor. Do not change `env.go` or `redact.go`.
- `internal/config/search.go`: the comment "not part of AllowedBaseURLs" → "not part of BaseURLs".
- `internal/config/search_test.go`: rewrite `TestSearchNotInAllowedBaseURLs` as `TestSearchNotInBaseURLs`
  without jev: with a `search` block (custom `baseURL`) and with the default one, neither search URL is in
  `cfg.BaseURLs()`.
- Remove any other `jev`/`typesafe`/`systemone` mention (any case) under `internal/config/`.

New test `TestConfigLeftoverKey` in a new file `internal/config/leftover_test.go` (package `config`; use the
existing helpers `writeFile`, `fakeEnv`, `GlobalPath`, `Load`). Build the key only in Go as `"\x6aev"` (string
concatenation into the JSON text; never write the three letters). Cases:
1. global config = one fake provider (`baseURL` `http://127.0.0.1:9/v1`) + leftover block
   `{"baseURL":"https://leftover.example","apiKey":"literal","model":7,"min_confidence":"bad","route":{"easy":"nope/x"}}`
   (ill-typed under the old rules) → `Load` returns no error; `cfg.BaseURLs()` equals exactly
   `["http://127.0.0.1:9/v1"]`; the default model is still the provider's model.
2. the same block in the project file `yipyip.json` instead → loads too.
3. leftover block `{"apiKey":"{env:LEFTOVER_SET}"}` with `LEFTOVER_SET=SECRET123` → loads, and
   `cfg.Redactor.Redact("k SECRET123")` returns `"k [redacted]"`.
4. leftover block `{"apiKey":"{env:LEFTOVER_UNSET}"}` with that variable unset → `Load` fails with an error that
   names `LEFTOVER_UNSET` (unchanged v1 rule).
