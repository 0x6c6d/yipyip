# T101: Remove jev from internal/tui and e2e

Phase 1 · Model: opus: first step of a cross-cutting removal tied to Consequential assumption #4 (`/jev` must become an unknown command) · Depends-on: T000 · Covers: R47-R56 removed (tui part: `/jev`, `/jev stats`, tab/toggle state, status-line `jev` field, `/help` entry), §4 "`/jev` is an unknown command"

## Brief
v8 removes jev (an external turn-routing service) completely. This task removes every jev use from the TUI
and the end-to-end tests. The agent, provider and config packages still contain their jev code after this
task (later tasks remove it); do not touch them, only stop calling them. The tree must build and pass
`make check` afterwards.

Delete these files:
- `internal/tui/jev.go` (the `/jev` command, registered via `slashCommands["/jev"]` in an `init`)
- `internal/tui/jev_test.go`
- `e2e/jev_test.go`, `e2e/jev_norisk_test.go`

Edit:
- `internal/tui/model.go`: remove the `jevOn` field of `Model` and every use of it.
- `internal/tui/tabs.go`: remove `_ = sess.SetJev(m.jevOn)` (a new tab no longer inherits a jev switch).
- `internal/tui/status.go`: remove the status-line fields `jev` (from `m.sess.JevOn()`) and `route: <id>`
  (from `m.sess.TurnModel()`); the other fields stay exactly as they are.
- `internal/tui/help.go`: remove the `/jev` entry from the command list (so `/help`, `--help` output and
  command suggestions no longer list it).
- `internal/tui/help_test.go`: drop `/jev` from the expected lists; keep all other expectations.
- `e2e/helpers_test.go`: remove the `TYPESAFE_API_KEY` → `JEVKEY-E2E` env branch.
- Any other file under `internal/tui/` or `e2e/` that still mentions jev (case-insensitive), `typesafe` or
  `systemone`: remove the mention (comments included).

New test `TestUnknownCommandRemoved` in a new file `internal/tui/removed_cmd_test.go` (package `tui`, built
like the existing model tests that drive `Model.Update` + `View()` with the fake provider). Build the old
command name only as `"/" + "\x6aev"`. It asserts:
- submitting `"/\x6aev"` shows exactly the existing unknown-command line `unknown command: /` + `"\x6aev"`
  (the dispatcher's `"unknown command: "+name` in `commands.go`), and sends no request to the fake provider;
- submitting `"/\x6aev stats"` shows the same line and sends no request;
- `Commands()` has no entry whose name is `"/\x6aev"`, and the `/help` text contains no `"\x6aev"`
  (case-insensitive);
- the rendered view (status line) contains neither `"\x6aev"` nor `route:`.
