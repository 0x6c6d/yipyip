# T301: Fetch HTTP client NewFetchHTTPClient

Phase 3 · Model: opus: SSRF-critical client in the security-critical `transport.go` (Risk item C v8, Consequential assumptions #6, #7) · Depends-on: T199 (Phase 1's comment-only `transport.go` guard is checked before code is added) · Covers: R69 (transport part), R68 (URL rule shared with redirects)

## Brief
v8 adds a tool `web_fetch` that reads one web page by URL. It is the first code that reaches arbitrary hosts, so it
gets its own HTTP client, built only in `internal/provider/transport.go` (the only place that builds HTTP clients).
This task builds that client and its URL rule; the tool itself comes later. **Only add** code and comments to
`transport.go`: no existing line may be changed or removed (the provider and search clients stay as they are).

Add to `internal/provider/transport.go` (stdlib only: `net`, `net/netip`, `syscall`, `net/url`, `unicode/utf8`, …):

```go
const FetchTimeout = 20 * time.Second   // total per call, redirects included
const MaxFetchRedirects = 5
const MaxFetchURLLen = 2000             // characters (runes)

var ErrAddressNotAllowed = errors.New("address not allowed")   // Error() exactly "address not allowed"
var ErrTooManyRedirects  = errors.New("too many redirects")
var ErrRedirectNotAllowed = errors.New("redirect not allowed")

// FetchOptions configures NewFetchHTTPClient.
type FetchOptions struct {
	Timeout   time.Duration // 0 = FetchTimeout
	AllowAddr string        // test hook: one exact resolved "ip:port" exempt from the address check; "" in production
}

// ValidateFetchURL checks raw against the web_fetch URL rule and returns the parsed URL.
// The error text is a short reason without the URL, e.g. "url is empty", "url is longer than 2000 characters",
// "scheme must be http or https", "url has no host", "url must not contain user info", "cannot parse url".
func ValidateFetchURL(raw string) (*url.URL, error)

func NewFetchHTTPClient(opts FetchOptions) *http.Client
```

URL rule (R68): not empty; at most 2,000 runes; parses with `url.Parse`; scheme `http` or `https` (case-insensitive);
non-empty `Hostname()`; no userinfo (`u.User != nil` is refused, also `user@` without password).

`NewFetchHTTPClient` returns a new `*http.Client` with:
- `Timeout` = `opts.Timeout` (or `FetchTimeout` when 0); `Jar` nil (no cookies are ever stored);
- its own `*http.Transport` (never `http.DefaultTransport`, never shared with the provider/search clients):
  `Proxy: nil`, TLS ≥ 1.2, bounded dial/TLS-handshake times, and a `net.Dialer` whose `Control` function checks
  the **resolved** address of every connection (so DNS names, DNS rebinding and redirects are all covered): parse
  `address` with `net.SplitHostPort` + `netip.ParseAddr`, `Unmap()` it, and return `ErrAddressNotAllowed`
  (unwrapped, so `errors.Is` works through `net.OpError` and `url.Error`) when it is loopback, private (incl.
  `fc00::/7`), link-local unicast, link-local multicast, interface-local multicast, multicast, unspecified, in
  `0.0.0.0/8`, or unparsable. CGNAT `100.64.0.0/10` and other public addresses are allowed. When `address` equals
  `opts.AllowAddr` exactly, the check is skipped (tests and probes only; nothing in non-test code may set it).
  Put the address decision in an unexported pure function `fetchAddrAllowed(netip.Addr) bool`;
- `CheckRedirect`: more than `MaxFetchRedirects` redirects (`len(via) > 5`) → `ErrTooManyRedirects`; a redirect
  target that fails `ValidateFetchURL` (e.g. `http://u:pw@host/`, `ftp://…`) → `ErrRedirectNotAllowed`; the target's
  address is then checked at dial time like any other;
- a wrapping `http.RoundTripper` (unexported type) that clones every request (redirects included) and sets
  `User-Agent: yipyip`, deletes `Authorization`, `Proxy-Authorization` and `Cookie`.

Tests (package `provider`, new file `internal/provider/fetch_test.go`; httptest servers on 127.0.0.1 only, exempted
through `AllowAddr: srv.Listener.Addr().String()`; never contact a real host):
- `TestWebFetchBlockedAddresses`: without `AllowAddr`, GETs to `127.0.0.1`, `[::1]`, `10.0.0.1`, `192.168.1.1`,
  `169.254.169.254`, `0.0.0.0` (port 9 or the test server's port) fail with `errors.Is(err, ErrAddressNotAllowed)`;
  an allowed test server that redirects to a second 127.0.0.1 server fails the same way and the second server gets
  no request; a 127.0.0.1 server whose exact `ip:port` is not `AllowAddr` (other port) is refused.
- `TestWebFetchRequest`: the server sees `User-Agent: yipyip` and no `Authorization`/`Cookie` even when the caller
  sets them and the server sets a cookie (two requests); 5 redirects are followed, 6 fail with `ErrTooManyRedirects`;
  a redirect to a userinfo URL fails with `ErrRedirectNotAllowed`; a slow server fails after `Timeout: 300ms`
  within 3 s; `NewFetchHTTPClient(FetchOptions{})` has `Timeout == 20*time.Second`, `Jar == nil` and its own transport.
- `TestFetchAddressPolicy`: `fetchAddrAllowed` refuses `127.0.0.1`, `127.1.2.3`, `::1`, `10.0.0.1`, `172.16.0.1`,
  `192.168.1.1`, `169.254.169.254`, `0.0.0.0`, `0.1.2.3`, `::`, `fe80::1`, `fc00::1`, `fd12::1`, `224.0.0.1`, `ff02::1`,
  `ff01::1`, `::ffff:127.0.0.1`, `::ffff:10.0.0.1`, and allows `8.8.8.8`, `1.1.1.1`, `100.64.0.1`, `93.184.216.34`,
  `2606:4700::1` (pure function, no dial).
- `TestValidateFetchURL`: accepts `http://example.org/x`, `HTTPS://example.org`; refuses empty, 2,001 characters,
  `ftp://h/x`, `file:///etc/passwd`, `http:///x`, `http://u:pw@h/x`, `http://u@h/x`, `javascript:alert(1)`.

The supervisor probe `scripts/verify/v8/probes/fetch.go` compiles against exactly this API (`FetchOptions{Timeout,
AllowAddr}`, `ErrAddressNotAllowed`, `NewFetchHTTPClient`); read it, never edit it.
