# T501: Agent wiring: FetchClient seam, gated and registered tests

Phase 5 · Model: opus: wires the SSRF-sensitive tool into sessions and proves the approval gate for main agent and subagents (Risk items C v8 and C approvals, Consequential assumption #12) · Depends-on: T401, T403 · Covers: R68 (main agent and subagents), R71, changed R7

## Brief
Already done: `internal/tools` always registers `web_fetch` (gated; `tools.Options.Fetch *http.Client`, nil = the
production client `provider.NewFetchHTTPClient(provider.FetchOptions{})`, which refuses loopback/private addresses),
and `internal/agent/approval.go` lists `web_fetch` in `gatedTools`. Do not edit `approval.go`, `internal/tools` or
`internal/provider`.

`internal/agent/session.go`:
- `Options` gains `FetchClient *http.Client // test seam for web_fetch; nil = the tools default fetch client`.
- `NewSession` passes it as `tools.Options{…, Fetch: opts.FetchClient}`. Never pass `opts.HTTPClient` (the provider
  client) or the search client there: the fetch client is separate.
- Subagents share the session's registry, so they offer `web_fetch` too; keep it that way.

New tests in `internal/agent/webfetch_test.go` (package `agent`; fake provider from `providertest`, a local httptest
page with `Content-Type: text/plain`; `FetchClient: provider.NewFetchHTTPClient(provider.FetchOptions{AllowAddr:
page.Listener.Addr().String(), Timeout: 5 * time.Second})`; drive the session with `Submit`, `NextEvent`,
`ApprovalRequest.Respond`, `Wait`, like the existing `websearch_test.go` / `approval_websearch_test.go`):
- `TestWebFetchGated`:
  - manual mode, main agent: the model calls `web_fetch` with the page URL; exactly one `EvApproval` with
    `Tool == "web_fetch"` whose `Args` contain the URL; `Deny` → the page gets no request and the tool result is an
    error containing `DeniedMessage`; `Allow` → exactly one request and a result starting `url: `;
  - manual mode, subagent: the main agent spawns a subagent (approve `spawn_agent`) whose model calls `web_fetch`;
    its approval request carries the subagent's id and the URL; `Deny` → no request;
  - auto mode: no `EvApproval`, one request, result starting `url: `;
  - `AllowAlways` for `web_fetch` does not approve `bash` (one table row per other tool: `bash`, `write_file`,
    `edit_file`, `spawn_agent`, `web_search` still `IsGated`; `read_file`, `glob`, `grep`, `question` not).
- `TestWebFetchRegistered`: with no `search` block in the config, the first provider request of the main agent and the
  first request of a subagent both list `web_fetch` in `ToolNames` (and not `web_search`); with no `FetchClient`, an
  auto-mode call to the 127.0.0.1 page returns exactly `web_fetch failed: address not allowed` and the page gets no
  request.

Existing agent tests that assumed no `web_fetch` must keep passing; adapt only an exact tool-list assertion if one
breaks, without weakening it (add `web_fetch` to the expected list).

The supervisor probe `scripts/verify/v8/probes/agentfetch.go` compiles against `agent.Options{Config, StartDir,
FetchClient}`; read it, never edit it.
