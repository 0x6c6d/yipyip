# T101: TestMainCancelLongTurn (cancel in the 60th tool round)

Phase 1 · Model: opus: turn cancellation is concurrency code and the only brake of the Consequential (money) "main agent unlimited" assumption · Depends-on: T000 · Covers: R65, R64, R54, R6 (removed part)

## Brief
Context: the main agent of `yip` (package `internal/agent`, module `yipyip`) no longer has a limit on
model calls per turn (`const MaxIterations = 0` in `internal/agent/loop.go`, `runLoop` loops while
`limit == 0 || i < limit`); subagents keep `const MaxSubagentIterations = 500`. Cancelling the turn
(`Session.Cancel`, bound to `Esc` in the TUI) is now the only brake. Prove that cancel still works deep
inside a long turn.

**Change only `internal/agent/loop_test.go`**: add one top-level test `func TestMainCancelLongTurn(t *testing.T)`.
Do not change `loop.go` unless the new test exposes a real bug in it; if so, fix it minimally and keep
both constants unchanged. Do not touch other tests.

Reuse what already exists in `loop_test.go` (read `TestCancelStopsTurn` and `TestMainNoIterationLimit`
there first and mirror their style): `newLoopSession(t, srv)` (temp HOME/start dir, model `m1`, cleanup
cancels and waits), `waitTurn(t, s, d)`, `findEvent(evs, kind, sub)`, and the aliases
`fakeResp = providertest.Response`, `fakeCall = providertest.ToolCall`. Session API:
`s.SetMode(ModeAuto)`, `s.Submit(text) error`, `s.NextEvent(ctx) (Event, error)`, `s.PollEvents() []Event`,
`s.Cancel()`, `s.Busy() bool`, `s.History() []HistoryEntry` (`Role`, `Content`, `ToolCalls []ToolCall{ID, Name, Arguments}`,
`ToolCallID`); `Event{Kind, AgentID, Tool, Text}` with kinds `EvToolCall`, `EvToolResult`, `EvInfo`,
`EvError`, `EvTurnDone`; `MainAgentID`; `CancelledMessage` (= `"cancelled"`).

Test script (fake provider via `providertest.NewFunc(func(n int, _ providertest.Request) fakeResp)`, `n` is
the 0-based request index):
- `n <= 58` (requests 1–59): one `glob` call, ID `fmt.Sprintf("g%d", n)`, arguments `{"pattern":"*.none"}`.
- `n == 59` (request 60): two calls: `bash` ID `"b59"` arguments `{"command":"sleep 30"}`, then `glob` ID `"c59"` arguments `{"pattern":"*"}`.
- any later request: `fakeResp{Text: "unexpected"}` (must never be reached).

Steps and assertions:
1. `newLoopSession`, `s.SetMode(ModeAuto)` (so `bash` runs without an approval prompt), `s.Submit("work long")`.
2. Read events with `s.NextEvent` under a `context.WithTimeout` of at most 30 s. Count `EvToolCall` events of
   `MainAgentID`. If `EvTurnDone` or `EvError` arrives before the 60th tool call, `t.Fatalf` at once (this is
   what catches a returning iteration limit). Every wait in the test must be bounded; the test must never hang.
3. The 60th `EvToolCall` must have `Tool == "bash"`. Then `time.Sleep(200 * time.Millisecond)` (let bash start),
   `start := time.Now()`, `s.Cancel()`, `waitTurn(t, s, 2*time.Second)`, and assert `time.Since(start) <= 2*time.Second`.
4. `s.Busy()` is false; the remaining events (`s.PollEvents()`) end with `EvTurnDone`, contain an `EvInfo`
   with text `cancelled`, and contain no `EvError` of `MainAgentID`.
5. `len(srv.Requests()) == 60` exactly.
6. History integrity: for every assistant entry, every `ToolCalls[i].ID` has exactly one later entry with
   `Role == "tool"` and that `ToolCallID`; there is no tool entry without a matching call. The `b59` result
   exists; the `c59` result has `Content == CancelledMessage`. The history contains 60 assistant entries and
   no assistant entry with text `unexpected`.
7. `s.Cancel()` again is a no-op (idle).

Constraints: no real network, no files outside `t.TempDir()`, no new helper files, no new dependencies, `gofmt`
clean. Do not write the string `iteration limit (50)` anywhere. The test must pass with `-race` and when
repeated (`-count=3`).
