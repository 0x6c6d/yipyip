# T205: Inline italic, strike, code, links, escapes

Phase 2 · Model: opus: parses untrusted model text, and new inline forms can reassemble a secret (A1) · Depends-on: T102 · Covers: R75 (italic, inline code, strike, links, no markup shown), R76 (inline code not interpreted), A13

## Brief
`internal/tui/markdown.go` has `renderMarkdown(src string, width int) string` with a block pass
and an inline pass (e.g. `renderInline`). The inline pass so far: code spans (N backticks to the
next run of exactly N) are protected and emitted unchanged with their backticks; `**x**`/`__x__`
become bold (flanking rules: opener followed by non-space, closer preceded by non-space; `__`
only at word boundaries); unmatched markers literal. In `blocks.go` assistant blocks are rendered
with it and a secret guard falls back to the redacted source when `m.redact(ansi.Strip(out))`
differs from `ansi.Strip(out)`. Complete the inline pass (A13). Scan left to right; at each
position the first matching form wins, in this order:

1. **Backslash escape**: `\` followed by one of `` \ ` * _ { } [ ] ( ) # + - . ! | ~ < > `` emits
   that character literally (never markup). Any other `\x` stays as written.
2. **Code span**: as today, but now emitted without its backticks, in a code style (e.g. a
   lipgloss foreground colour); if the content starts and ends with a space and is not all
   spaces, strip one space on each side. The content is never interpreted (no emphasis, links,
   escapes). An unclosed backtick run is literal.
3. **Image** `![alt](url)`: not supported, emitted literally (all characters).
4. **Link** `[text](url)`: `[` up to the matching `]` (brackets inside balanced), immediately
   followed by `(`, a url without spaces, `)`. Emits inline(text) + ` (` + url + `)`; when the
   stripped rendered text equals the url, only the url. Anything else with brackets is literal.
5. **Autolink** `<http://…>` or `<https://…>` (no space, `<` or `>` inside) emits the url.
6. **Emphasis**: `**x**`/`__x__` bold (unchanged), `*x*`/`_x_` italic, `~~x~~` strike.
   Same flanking rules for all: opener followed by a non-space, closer preceded by a non-space;
   `_` and `__` open only when not preceded by a letter or digit and close only when not followed
   by one (`snake_case_name` stays); `*` may be intraword. The closer is the nearest matching
   marker of the same kind; the content is inline-rendered recursively. `***x***` needs no special
   handling but must not panic or lose characters other than markers. Unmatched markers literal.

No markup character of a rendered form is shown. Table cells, list items, quotes and headings use
the same inline pass, so they get all of this automatically.
