# T101: Markdown renderer skeleton: block pass, fences, headings, bold

Phase 1 · Model: opus: parses untrusted model text, the base every later renderer task builds on · Depends-on: T000 · Covers: R75 (headings, bold), R76 (fences, inline code not interpreted)

## Brief
Create `internal/tui/markdown.go` with

```go
// renderMarkdown renders assistant markdown (already redacted) as styled terminal text.
func renderMarkdown(src string, width int) string
```

Contract: pure (no Model, no I/O, no package state changed), deterministic, never panics on any
input (including invalid UTF-8). `width` is the number of columns available; `width <= 0` means
unknown (render at natural width). Output lines are joined with `"\n"`; no trailing newline is
added; a trailing `"\r"` on a source line is dropped. One output line per source line unless a
construct says otherwise. Soft line breaks are kept exactly; lines are never reflowed or joined.
Blank lines stay blank. Only the standard library plus `lipgloss`, `x/ansi` and the existing
`Highlight` (chroma, in `highlight.go`) may be used.

**Block pass** (line based). Write it as a dispatcher over block rules (e.g. one function per
construct that consumes one or more lines and returns rendered lines, tried in a fixed order), so
later tasks can add tables, lists, quotes and rules without restructuring. Rules in this task,
in this order:
1. Fenced code: a line whose `strings.TrimSpace` starts with three backticks opens a fence; the
   language is the first word after the backticks. It closes at the next line whose
   `TrimSpace` is exactly three backticks. Closed: the fence lines are dropped and the code is
   replaced by `Highlight(code, lang)` split into lines (exactly what `highlightFences` in
   `highlight.go` produces for that block). Unclosed (no closing line yet, still streaming):
   the opening line and every remaining line are emitted unchanged and nothing after it is
   processed. Lines inside a fence are never given to any other rule or to the inline pass.
   You may extract the fence scanning of `highlightFences` into a shared helper, but
   `highlightFences` keeps its behaviour, and `TestHighlightGo`, `TestHighlightUnknownLang`
   and `TestFenceHighlightedInView` pass unchanged.
2. ATX heading: up to 3 leading spaces, 1 to 6 `#`, then a space or the end of the line, then the
   text; a trailing run of `#` preceded by a space is removed. Emitted: the inline-rendered text
   in bold; level 1 also underlined. No `#` is shown. Seven `#` or `#text` without a space are
   not headings. No setext headings.
3. Everything else: a paragraph line, passed through the inline pass.

**Inline pass** (e.g. `renderInline(s string) string`), in this task:
- Code spans are found first: a run of N backticks opens, the next run of exactly N backticks
  closes; the content between is never interpreted. In this task the span is emitted unchanged
  including its backticks (a later task styles it). An unclosed run is literal text.
- `**text**` and `__text__` become `text` in bold, markers removed. An opening marker is
  followed by a non-space, a closing one is preceded by a non-space; `__` opens only when not
  preceded by a letter or digit and closes only when not followed by one (so `snake__case`
  stays). Unmatched markers stay literal. The content of a bold span is itself inline-rendered.
- Everything else is copied unchanged. Text without markdown comes back byte-identical
  (for example `a - b`, `x | y`, `snake_case`, `2 * 3`).

Styles are package-level lipgloss styles in `markdown.go` (for example `mdBold`, `mdH1`).
Do not wire the renderer into `blocks.go` (another task does that).

**Tests** in a new `internal/tui/markdown_test.go` (compare `ansi.Strip` output with exact
expected strings): `TestMarkdownSkeletonHeadings` (levels 1-6 lose their `#`; trailing `#`
removed; `####### x` and `#x` unchanged; with `withColorProfile(t, termenv.ANSI256)` the raw
output of a heading differs from its stripped form, i.e. it is styled),
`TestMarkdownSkeletonBold` (`**b**`, `__b__`, bold inside a heading, unclosed `**x` literal,
`snake__case` literal, `**x**` inside a code span left with its backticks and stars),
`TestMarkdownSkeletonFence` (closed go fence: no backtick fence line, the code text present
when stripped, `**`, `#` and `|` inside it untouched; unknown language stays plain; unclosed fence:
output equals input), `TestMarkdownSkeletonPassThrough` (plain inputs come back byte-identical,
also with `width` 0 and -1).
