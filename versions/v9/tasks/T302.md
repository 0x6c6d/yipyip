# T302: /clear in place and its /help entry

Phase 3 · Model: opus: Consequential A2 (/clear writes no session file, keeps the saved one) and turn cancellation · Depends-on: T301 · Covers: R73, changed `/new` and `/clear` (alias removed, `/help` text)

## Brief
Today `/clear` is an alias of `/new` (`internal/tui/commands.go`: `"/clear": cmdNew`), which
opens a new tab. Make `/clear` its own command that empties the current tab in place.

`internal/tui/tabs.go` has `func (m *Model) resetTab(keepHistory bool) error`: it replaces the
current tab by a fresh tab (new agent session with the global model, effort and mode, empty
transcript; denies pending approvals, cancels pending questions, cancels the old session's
running turn and subagents, stops its event pump; no save; tab count and index unchanged; with
`keepHistory` the input history and pastes are kept and the input draft is left alone). On error
it changes nothing. It does not start the new event pump.

1. `commands.go`: add

   ```go
   // cmdClear is /clear: the current tab is emptied in place ...
   func cmdClear(m Model, _ string) (Model, tea.Cmd)
   ```

   It calls `m.resetTab(true)`; on error it adds one error block `"error: " + err.Error()` and
   returns `m, nil`; otherwise it adds exactly one info block `cleared` and returns
   `m, m.waitEvent()`. Register `"/clear": cmdClear`. `cmdNew` and `/new` stay unchanged;
   update `cmdNew`'s doc comment, which mentions `/clear`. `/clear` works while idle and while a
   turn runs (slash commands already bypass the busy queue in `submit`).
2. `help.go`: the `/clear` entry gets a description that does not contain the word `alias`,
   e.g. `clear this tab's conversation (fresh session, same tab)`. `/new` stays
   `open a fresh session in a new tab`.
3. Existing tests to change: `TestNewClearsSession` (`commands_test.go`) and
   `TestHistorySurvivesNew` (`input_test.go`) loop over `/new` and `/clear`; reduce both to
   `/new` only, assertions otherwise unchanged. Any other test that relies on `/clear` opening a
   tab gets the same treatment (name it in the report).

**Tests** in a new `internal/tui/clear_test.go`:
`TestClearKeepsTab` (after a turn, `/clear` typed and sent with Enter: 1 tab, a new session,
exactly one block, the info `cleared`, the old answer gone from the view, a non-nil command),
`TestClearWithTwoTabs` (on tab 1 of 2: still 2 tabs, `m.cur == 1`, tab 0 untouched),
`TestClearWhileBusy` (provider `providertest.Response{Text: "late", Delay: 30 * time.Second}`:
Enter, `waitBusy`, `/clear`; the old session finishes within `waitSession`'s 10 s; 1 tab, `cleared`),
`TestClearKeepsHistory` (same `m.hist` pointer; Up recalls `/clear`, then the earlier inputs),
`TestClearNoSave` (no session file appears; with a file saved before via `m.saveTab()`, the same
single file with the same bytes remains), `TestClearKeepsGlobals` (model, effort and mode of the new
session equal the ones before), `TestClearNewStillAddsTab` (`/new` after `/clear` gives 2 tabs),
`TestClearHelpEntry` (the `HelpText()` line with `/clear` has no `alias`).
