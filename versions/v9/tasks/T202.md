# T202: Tables wrapped to the width

Phase 2 · Model: opus: width arithmetic on untrusted input, the "never overflow" rule · Depends-on: T201 · Covers: R75 (tables wider than the viewport wrap, never overflow), A10, A14

## Brief
`internal/tui/markdown.go` has `renderMarkdown(src string, width int) string`; its table rule
detects GFM tables and lays them out with box borders (`┌─┬─┐`, `│ cell │`, `├─┼─┤` after the
header, `└─┴─┘`), one space of padding on each side of a cell, per-column alignment and a bold
header, at natural width (column width = widest rendered cell, `ansi.StringWidth`). The layout
function takes the column widths. Make tables fit `width`.

A rendered table line is `Σw + 3·cols + 1` columns wide (`w` = content width of each column).

1. `width <= 0`, or the natural table fits (`Σw + 3·cols + 1 <= width`): unchanged natural layout.
2. Otherwise compute `min_i = min(3, natural_i)` per column. If `Σmin + 3·cols + 1 > width`
   the table cannot fit: emit the table's source lines unchanged (plain text, through nothing
   else), never a box wider than `width`.
3. Otherwise shrink: repeatedly reduce the currently widest column by one (on a tie the leftmost
   of them), never below its `min_i`, until `Σw + 3·cols + 1 <= width`.
4. Wrap every cell to its column width with `ansi.Wrap(cell, w, "")` (it keeps ANSI styles, breaks
   at word boundaries and hard-breaks words longer than `w`, so no character is lost). A row
   becomes as many physical lines as its tallest cell; shorter cells are padded with blank cell
   lines. Alignment and the bold header apply per physical line. Every line of the table then
   has exactly the same width, `<= width`.

The `● `/continuation indent is already accounted for by the caller (it passes the viewport
width minus 2). Nothing else in the renderer changes.

**Tests** (in `internal/tui/markdown_test.go`, ANSI stripped): `TestMarkdownTableWrap`
(a 3-column table whose first body cell is `word` repeated 12 times with spaces, a short cell and
a 50-character word, at width 40: every line `<= 40` and all lines of the table equally wide,
`word` appears 12 times, all 50 `x` are present, the header words are present, starts with `┌`
and ends with `└`), `TestMarkdownTableWrapAlign` (a right-aligned column stays right-aligned on
every wrapped line), `TestMarkdownTableFitsUnchanged` (a small table renders identically at
width 0 and width 80), `TestMarkdownTableTooNarrow` (10 columns at width 20: output equals the
source), `TestMarkdownTableWideChars` (cells with CJK and emoji at width 30: every line
`<= 30` by `ansi.StringWidth`). Add a view test `TestMarkdownTableView`: a table answer at a
model width of 40 (`newBlockModel` then `Update(tea.WindowSizeMsg{Width: 40, Height: 40})`)
has no view line wider than 40.
