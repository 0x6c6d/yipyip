# T206: Incomplete input, fence isolation, robustness, fuzz seeds

Phase 2 · Model: opus: robustness of the parser of untrusted model text (panics, blow-ups, streaming states) · Depends-on: T102 T202 T203 T204 T205 · Covers: R76 (incomplete markdown plain, fences untouched, inline code not interpreted), A14, A15

## Brief
`internal/tui/markdown.go` has `renderMarkdown(src string, width int) string`, a complete
stdlib-only markdown renderer for assistant blocks: fenced code via `Highlight` (unclosed fence →
rest plain), GFM tables with box borders that shrink and wrap to `width` (or fall back to the
source when they cannot fit), headings, lists, blockquotes (depth bounded at 32), horizontal rules
(`─`×width, 40 when `width <= 0`), inline bold/italic/strike/code/links/escapes. `blocks.go` calls
it for assistant blocks (after redaction, width = viewport width − 2) with a secret guard.
Assistant text arrives in streaming deltas, so every prefix of a valid document is rendered too.
Harden it and pin the behaviour with tests; fix whatever these tests reveal in `markdown.go`
(and only there).

Required behaviour:
- **Incomplete input renders as plain text without error**: a half-streamed table without its
  separator yet (`| a | b |` then `| c`) is unchanged; an unclosed `**` or `` ` `` is literal; an
  unclosed fence leaves the opening line and all lines after it unchanged (their `|`, `#`, `**`
  included). The finished text renders fully.
- **Fences are isolated**: inside a closed fence (any or no language) `|---|`, `| x |`, `# h`,
  `**b**`, `> q`, `- i` are never interpreted; with an unknown language the code is shown as
  written. Inline code content is never interpreted.
- **Never panics**, for any width (−1, 0, 1, 2, 5, 40) and any input: empty, lone markers
  (`|`, `||`, `|-|`, `**`, `*`, `_`, `~~`, `` ` ``, three backticks, `[`, `](`, `[a](`, `<http`,
  `> `, `- `, `1.`, `#`, `######`), NUL and invalid UTF-8 bytes, CJK and emoji table cells,
  5000 nested `>`, `**a` repeated 2000 times, a 300-column table.
- **No blow-up**: a document of about 100 KB (tables, lists, quotes, inline markup repeated)
  renders in well under 2 s; no quadratic rescans per character (scan each line a bounded number
  of times).
- **Width ≤ 0 (A14)**: tables at natural width, rules 40 wide.
- **Determinism**: the same input and width always give the same output.

**Tests** (in `internal/tui/markdown_test.go`):
`TestMarkdownIncomplete` (each incomplete case above, stripped output equals the input;
the completed table then renders with `┌` and without `|---`), `TestMarkdownFenceUntouched`
(the fence cases above), `TestMarkdownNoWidth`, `TestMarkdownNoPanic` (every input × every width
above, with `recover` reporting the input), `TestMarkdownLargeInput` (timing bound 2 s),
`TestMarkdownStreamingView` (feed a table answer to `newBlockModel()` in small `EvText` deltas of
3 characters; after every delta `View()` works and no view line is wider than the model width; at
the end the view has the box and no `|---`), and `FuzzMarkdown` with at least 20 `f.Add` seeds
(the inputs above plus valid documents) whose body checks: no panic, deterministic output, and
for valid UTF-8 input valid UTF-8 output. `go test` runs the seed corpus; do not commit a
`testdata/fuzz` directory.

## Verification

probe of incomplete and fenced input, a robustness probe (no panic for the inputs and widths above,

interpreted. Also the diff guard and `make check`.
