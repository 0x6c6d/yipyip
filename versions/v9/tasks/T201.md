# T201: Tables at natural width

Phase 2 · Model: opus: parses untrusted model text into a layout (splitting, escapes, ragged rows) · Depends-on: T101 · Covers: R75 (tables: borders, padding, bold header, alignment), R76 (incomplete table plain)

## Brief
`internal/tui/markdown.go` has `renderMarkdown(src string, width int) string`: a line-based
block pass (a dispatcher over block rules: fence first, then heading, then paragraph) followed
by an inline pass (`**bold**`, `__bold__`, code spans protected). Add a **table rule** to the
block pass, tried right after the fence rule.

**Detection (A8).** A table starts at a header line that contains at least one cell separator
`|` and is directly followed by a separator line. A separator line contains at least one `|` and
only `|`, `-`, `:` and spaces; split into cells (same splitting as below), every cell matches
`^ *:?-+:? *$` and the cell count equals the header's. Body rows are the following lines that
contain at least one cell separator; the table ends at the first line without one (a blank line
included) or at the end of the input. Without a valid separator directly after the header,
nothing is a table: the lines stay paragraph lines (this is how a half-streamed table looks,
and it must render as plain text).

**Cell splitting.** Trim the line; drop one leading `|` and one trailing `|` if present; split on
`|` that is not preceded by a backslash and not inside a code span (backtick runs, same rule as
the inline pass). In cell text `\|` becomes `|`. Cells are trimmed. Each row is normalised to the
header's cell count: missing cells are empty, extra cells are dropped. Each cell is rendered with
the inline pass; widths are measured with `ansi.StringWidth` of the rendered cell.

**Alignment** per column from the separator cell: `:--` left, `--:` right, `:-:` center, `---`
left. It applies to header and body cells. Center: left padding `(w-cw)/2`, the rest on the right.

**Layout (A9)**, column width `w` = widest rendered cell of the column (header included):

```
┌───────┬─────┬───────┐
│ Name  │ Qty │  Mid  │
├───────┼─────┼───────┤
│ apple │   3 │   a   │
│ kiwi  │  12 │ bbbbb │
└───────┴─────┴───────┘
```

That is the rendering of `| Name | Qty | Mid |`, `|:-----|----:|:---:|`, `| apple | 3 | a |`,
`| kiwi | 12 | bbbbb |`: top line `┌` + `─`×(w+2) per column joined by `┬` + `┐`; rows `│ ` +
padded cell + ` │` per column (adjacent columns share one `│`); the `├─┼─┤` line only after the
header; `└─┴─┘` at the end. Header cells are bold (padding outside the bold styling is fine).
The table's source lines (header, separator, rows) are replaced by these lines; lines before and
after the table are rendered as before. No `|---|` source line is ever shown for a rendered table.

**Width.** This task renders at natural width always. Put the layout in its own function that
takes the column widths, so the next task can shrink columns and wrap cells when the table is
wider than `width`; leave a short comment where that hook goes.

**Tests** (in `internal/tui/markdown_test.go`, compare ANSI-stripped lines with trailing spaces
trimmed): `TestMarkdownTableBasic` (the example above exactly, with a paragraph line before and
after), `TestMarkdownTableAlign` (left, right, center, default), `TestMarkdownTableCells`
(`a \| b` → cell `a | b`; a code span containing `|` is one cell; `**b**` in a cell shows `b`;
a row with fewer cells is padded, one with more is cut), `TestMarkdownTableNotATable`
(no separator line; a separator with a different cell count; a separator cell `-x-`; a line
`a | b` followed by `---`: all render unchanged as plain text), `TestMarkdownTableHeaderBold`
(with `withColorProfile(t, termenv.ANSI256)` the header row differs from its stripped form).
