# T201: Subreaper, descendant walk, zombie reaping

Phase 2 · Model: opus: security-critical kill-set rules, zombie reaping next to `cmd.Wait` (Consequential assumptions 1 and 3) · Depends-on: T101 · Covers: R102, R103, R105

## Brief
`internal/tools/reaper_linux.go` already has a process-wide tracker of the process groups started by
`BashRunner.Run` (pgid = command pid) and `func KillAll(grace time.Duration)` that SIGTERMs live tracked groups,
polls (≤ 50 ms) until `grace`, then SIGKILLs; it is serialised by a mutex and never signals yip itself.
Processes that escape their group (`setsid sleep 300 &`, double forks) still survive. This task catches them.

### Files
- `internal/tools/reaper_linux.go` (extend), `internal/tools/reaper_other.go` (add a no-op `InitSubreaper`),
  `internal/tools/reaper_test.go` (add tests). No other files.

### API (exported, exact)
- `func InitSubreaper()`: Linux: `syscall.RawSyscall(syscall.SYS_PRCTL, 36 /* PR_SET_CHILD_SUBREAPER */, 1, 0)`;
  any error is ignored. Idempotent. Other OSes: no-op.

### Kill set (extend the collection step of `KillAll`)
Walk descendants of yip: read every `/proc/<pid>/stat` once per pass (fields after the last `)`: state=3,
ppid=4, pgrp=5, session=6); starting from `os.Getpid()`, collect processes whose ppid is in the collected set,
repeating until a pass adds nothing new. A descendant joins the kill set if any of these holds:
(a) its pgrp is a live tracked group; (b) its parent is already in the kill set; (c) its session differs from
yip's own session (`getsid(0)`, read from `/proc/self/stat` field 6).
Untracked same-session descendants that do not descend from a kill-set member (clipboard helpers like
`xclip`/`wl-copy`, a test's own bystander children, `go test` helpers) are never signalled. Never pid ≤ 1, never
yip's own pid. Single pids are signalled with `syscall.Kill(pid, sig)` only if they were seen in the same `/proc`
pass and are not zombies. SIGTERM groups and single pids, poll, re-collect on each poll (new escapees found
during the grace are added), SIGKILL what is left.

### Zombies
With the subreaper set, orphans become yip's children and stay zombies after death; `kill -0` succeeds on
zombies. Liveness is always "state ≠ Z". During polling and after SIGKILL, reap zombies that are members of
this call's kill set, whose ppid is yip's pid and that are not an active `BashRunner` command (the tracker knows
the active pids) with
`syscall.Wait4(pid, &ws, syscall.WNOHANG, nil)` per pid. Never `Wait4(-1, …)`: it would steal the exit status
from `cmd.Wait` in a concurrently running `Run` or from an `exec.Cmd` owned by other code. The grace poll must end
early when only zombies are left.

### Tests (`internal/tools/reaper_test.go`, exact names, no `t.Parallel`; same conventions as the existing reaper tests)
- `TestReaperSubreaper`: after `InitSubreaper()`, `PR_GET_CHILD_SUBREAPER` (37) returns 1 (or `/proc/self/status`
  shows it).
- `TestReaperSetsid`: after `InitSubreaper()`, `setsid sleep 3021 >/dev/null 2>&1 &` via `BashRunner` is alive,
  then gone after `KillAll(2*time.Second)`.
- `TestReaperDoubleFork`: `( setsid sh -c 'sleep 3022 >/dev/null 2>&1 &' & ) >/dev/null 2>&1` → gone after `KillAll`.
- `TestReaperZombie`: a re-parented setsid sleep killed by `KillAll(2*time.Second)` makes the call return in < 1 s
  (the zombie is reaped, not waited for) and no zombie child with that pid remains.
Keep the T101 tests (`TestReaperBackground`, `…TermIgnored`, `…Idempotent`, `…ExitedGroup`, `…Bystander`,
`…Timing`) green; a same-session bystander started by the test with `Setpgid: true` must still survive.
