New behaviour to document:
- When yip exits, it terminates every process its `bash` commands started, including background jobs
  (`cmd &`, `nohup`), dev servers and watchers, from the main agent and from subagents. Processes yip did not
  start are never touched.
- When: every exit path: quitting the UI (`/quit`, `/exit`, Ctrl+C twice, Ctrl+D), closing the terminal or
  `kill <pid>` (SIGTERM/SIGHUP: the session is saved first), the end of a `yip -p` run (also after `--timeout`,
  `--max-model-calls`, an unanswered question or a signal), and a crash exit (after the crash record).
- How: SIGTERM first, a 2 s grace, then SIGKILL for what is left; exit is delayed by at most about 2.5 s, and is
  immediate when nothing is left. Running subagents are cancelled first.
- Linux only: yip registers as a child subreaper, so processes that detach with `setsid` or a double fork
  are caught as well. On other platforms only the process groups of the commands are terminated.
- Not covered: `kill -9` of yip itself (cannot be caught); long-lived servers do not survive the session.
