# T101: Process tracker and KillAll for tracked groups

Phase 1 · Model: opus: security-critical signal code with pid-reuse and concurrency rules (Consequential assumption 2) · Depends-on: T000 · Covers: R101, R102, R105, R106

## Brief
yip runs shell commands only through `tools.BashRunner.Run` (`internal/tools/bash.go`). Each command starts
as `bash -c` with `Setpgid: true`, so the command pid is also its process-group id (pgid). Today the group is
SIGKILLed only on timeout/cancel; anything the command backgrounds (`sleep 300 &`) survives yip. This task adds
a process-wide tracker and `tools.KillAll` that terminates those groups. (A later task adds the
subreaper and a `/proc` descendant walk; do not implement those here, but structure the code so a
"collect kill set" step can be extended.)

### API (exported, exact)
- `func KillAll(grace time.Duration)`

### Semantics of `KillAll(grace)`
1. Serialised by a package mutex (concurrent callers run one after the other; safe under `-race`).
2. Collect the kill set from the tracker: for each tracked pgid, the group is "live" only if it is still
   tracked, `syscall.Kill(-pgid, 0)` succeeds, and a scan of `/proc/<pid>/stat` finds at least one process with
   field 5 (pgrp) == pgid whose state (field 3) is not `Z`. Parse `stat` after the last `)` (the comm may contain
   spaces/parens). A group that is not live is dropped from the tracker and never signalled.
3. Never signal pid/pgid ≤ 1, `os.Getpid()` or yip's own pgid (`syscall.Getpgrp()`).
4. Send SIGTERM to every live group (`syscall.Kill(-pgid, SIGTERM)`).
5. Poll every ≤ 50 ms until no group of the set is live or `grace` has passed; return early when none is left.
6. SIGKILL the groups still live; then drop the dead entries. Active entries (command still inside `Run`)
   are signalled like the others, but stay tracked until `Run` marks them inactive.
7. With nothing tracked/live it returns in well under 100 ms (no sleep before the first check). A second call
   right after a first is a no-op returning at once.
Only `syscall`, `os`, `strconv`, `strings`, `sync`, `time` (stdlib) are used.

### Tests (`internal/tools/reaper_test.go`, exact names, no `t.Parallel`)
Run commands with `(&BashRunner{Dir: t.TempDir()}).Run(ctx, cmd, 10*time.Second)`. Use unique sleep
durations, find pids via `echo $!` or `/proc/*/cmdline`, consider a pid gone when `/proc/<pid>` is missing or its
state is `Z`, and SIGKILL leftovers in `t.Cleanup`.
- `TestReaperBackground`: `sleep 3011 >/dev/null 2>&1 &` → `Run` returns within 2 s, sleep alive;
  `KillAll(2*time.Second)` → gone, and the call took < 2.5 s.
- `TestReaperTermIgnored`: `trap '' TERM; sleep 3012 >/dev/null 2>&1 &` → gone after `KillAll(300*time.Millisecond)`.
- `TestReaperIdempotent`: after a `KillAll`, a second call returns in < 100 ms; also run 4 concurrent `KillAll`
  calls with a live background sleep (no race, sleep gone).
- `TestReaperExitedGroup`: a command without background children (`echo hi`) → after `Run` its group is not
  live; `KillAll` does not signal it and drops the entry (assert via an unexported helper such as a tracked
  count or `trackedPGIDs()`; test-only exports go in an `export_test.go` if needed).
- `TestReaperBystander`: a `sleep 3013` started by the test itself with `exec.Command` and `Setpgid: true` (not via
  `BashRunner`) survives `KillAll` while a tracked background sleep is killed.
- `TestReaperTiming`: `KillAll` with nothing left < 100 ms; with a TERM-ignoring tracked child and
  `KillAll(2*time.Second)` < 2.5 s.
