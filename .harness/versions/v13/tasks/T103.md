# T103: Session-level tests: Reset re-read, subagent prompt, /init project-only

Phase 1 · Model: sonnet: tests of existing session paths with the fake provider, no security code changes · Depends-on: T102 · Covers: R109, R112, R113, R12

## Brief
yip now adds the user-wide file `<cfg.GlobalDir>/AGENTS.md` to the system prompt as a `# Global AGENTS.md`
section before the project `# AGENTS.md` section (`internal/agent/prompt.go`, `buildSystemPrompt`, called by
`NewSession` and `(*Session).Reset`). `config.Config.GlobalDir` is set by `config.Load` to `<home>/.config/yipyip`.
Subagents reuse the parent's `SystemPrompt()` (`internal/agent/agenttools.go`, tool `spawn_agent`).
`/init` (`internal/agent/init.go`) builds its user prompt from the project `AGENTS.md` only.

Pin these session-level behaviours with tests in a new file `internal/agent/globalagents_session_test.go`
(package `agent`). Use the existing helpers: `newLoopSession(t, srv)` in `loop_test.go` (temp home with
`.config/yipyip`, so `base.cfg.GlobalDir` points there), `providertest.New(...)` responses
(`fakeResp`, tool calls as in `agenttools_test.go` / `subagent_test.go`), `submitAndWait`, `srv.Requests()`.
Write the global file before creating the session (create a second session with
`NewSession(Options{Config: base.cfg, StartDir: dir})` after writing, as `systemappend_test.go` does).

Top-level tests:
- `TestGlobalAgentsReset`: session created with global `GLOBAL-OLD`; overwrite the file with `GLOBAL-NEW`;
  `SystemPrompt()` still has `GLOBAL-OLD` (not watched); after `s.Reset()` it has `GLOBAL-NEW` and not `GLOBAL-OLD`;
  the next request's system message (`Messages[0]`, role `system`) carries `GLOBAL-NEW`.
- `TestGlobalAgentsSubagent`: global `GLOBAL-SUB-NOTE`; the main model calls `spawn_agent`; the subagent's
  request (the request whose user message is the spawned task) has a system message containing `GLOBAL-SUB-NOTE`.
- `TestGlobalAgentsInitPrompt`: global `GLOBAL-INIT-NOTE`, project `AGENTS.md` `PROJECT-INIT-NOTE`; run `/init`
  the way `init_test.go` does; the `/init` request's user message contains `PROJECT-INIT-NOTE` and does not
  contain `GLOBAL-INIT-NOTE`; its system message does contain `GLOBAL-INIT-NOTE` (changed R12); the global file
  is byte-identical afterwards and no other file appears in the global dir.

Only add this test file; change production code only if a test exposes a real bug in the v13 global-file
feature (then keep the fix minimal and inside `internal/agent/prompt.go` or `session.go`).
