# T404: Timeout and max-model-calls exits

Phase 4 · Model: opus: turn cancellation and the only automated money brakes (Consequential A4, Risk: money) · Depends-on: T302 · Covers: R90, R95

## Brief
In `runHeadless` (`cmd/yip/headless.go`):
- Pass `agent.Options.MaxModelCalls: f.h.maxCalls` when building the session (the counter is shared
  by the main agent and all subagents; it exists in `internal/agent`, do not change it). When the turn
  ends with an error wrapping the limit (the main agent's `EvError` text contains
  `model call limit reached`, and `sess.ModelCalls() >= f.h.maxCalls`), finish with reason
  `max_calls`, exit 5 (also cancel remaining subagents: `sess.Cancel()`).
- `--timeout`: a timer started right before `Submit`; when it fires, `sess.Cancel()` (cancels the turn
  and its subagents), wait for `EvTurnDone`/`sess.Wait()` with a 10 s grace bound, finish with reason
  `timeout`, exit 4. The event loop's `NextEvent` context must not block past the timeout.
- SIGINT/SIGTERM (`signal.NotifyContext`): cancel the turn, reason `error`, exit 1.
- Precedence when several apply: timeout (4) > question (3) > max_calls (5) > error (1) > done (0);
  write a small pure function `exitFor(state) (code int, reason string)` and unit-test it in
  `cmd/yip/headless_exit_test.go` (`TestExitFor`).

E2E tests in new `e2e/headless_limits_test.go`:
- `TestHeadlessExit4`: fake reply with `Delay: 30*time.Second`; `--timeout 1s --json` → exit 4 in under
  10 s, `result` reason `timeout`, `exit_code` 4.
- `TestHeadlessExit5`: `--max-model-calls 2 --json`; main agent's first reply calls `spawn_agent`
  `{"task":"loop"}`, every subagent request gets an endless `glob` `{"pattern":"*"}` tool call, main
  requests after that call `wait_agent` → the fake saw exactly 2 requests, exit 5, reason `max_calls`,
  `model_calls` 2.
- `TestHeadlessExit5Main`: main agent alone with endless `glob` calls, `--max-model-calls 3` → exactly 3 requests, exit 5.
- `TestHeadlessSigterm`: start the binary (with `exec.Command`, not `runYip`) against a 30 s `Delay`
  reply; after the fake received the request send `SIGTERM` → exit 1 within 10 s.

## Verification
`.harness/verify/v11/T404.sh` exits 0. It runs `TestExitFor` and the four e2e tests; negative checks:
`--timeout 0s`/`--max-model-calls 0` exit 2 with the built binary, and the fake never sees the (n+1)-th request.
