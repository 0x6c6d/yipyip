# T407: Exit code tests 0, 1, 2

Phase 4 · Model: sonnet: e2e tests of existing behaviour plus a small usage-record addition · Depends-on: T302 · Covers: R90

## Brief
1. Usage `result` record (plan A12): when `parseArgs` (or the runner's own usage checks) ends a run
   with exit 2 and `--json` was among the arguments together with `-p`, stdout gets exactly one line,
   a `result` record (`cmd/yip/headless_events.go` `resultRecord`) with `exit_code` 2, reason `usage`,
   empty `session_id`/`final_text`, zero counts, `tools` `{}`, `files_changed` `[]`. The usage message
   stays on stderr. Without `--json` stdout stays empty. Implement in `cmd/yip/main.go`/`headless.go`
   (a small helper `usageResult(stdout io.Writer)`), keep `TestUnknownFlag` passing.
2. E2E tests in new `e2e/headless_exit_test.go` (helpers from `e2e/headless_test.go`):
   - `TestHeadlessExit0`: text reply → exit 0, `--json` result `exit_code` 0, reason `done`.
   - `TestHeadlessExit1`: (a) global config apiKey `{env:MISSING_KEY}` with the variable unset → exit 1,
     stderr names `MISSING_KEY`; (b) fake answers `Status: 400` with a body (not retried) → exit 1,
     `--json` result reason `error`, an `error` record present.
   - `TestHeadlessExit2`: `--json` without `-p` → exit 2; `-p x --timeout bogus --json` → exit 2 and
     stdout is exactly one `result` line with reason `usage`; `-p x --json --bogus` → exit 2; stdout
     never contains anything but that line.
