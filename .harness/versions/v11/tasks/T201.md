# T201: Agent SystemAppend option

Phase 2 · Model: sonnet: small, self-contained agent option with a unit test · Depends-on: T000 · Covers: R96

## Brief
Add `SystemAppend string` to `agent.Options` (`internal/agent/session.go`). When non-empty, the system
prompt of the session (history[0] and `SystemPrompt()`) is the normal prompt followed by `"\n\n"` and
the append text. It must also survive `Reset()` (the system prompt is rebuilt there or kept: check
`internal/agent/session.go` and `internal/agent/prompt.go`) and `RestoreHistory` (a restored history
whose first message is a system prompt gets the current system prompt including the append; read how
`RestoreHistory` treats the system message today and keep that behaviour, only with the append added).
Subagents keep their own system prompt (unchanged). Store the option on `Session`; no other API changes.

Test file `internal/agent/systemappend_test.go` (use the existing test helpers in `internal/agent`
tests, e.g. how `session_test.go` builds a session against `providertest`):
- `TestSystemAppend`: session with `SystemAppend: "EXTRA-RULES-42"`; `SystemPrompt()` ends with
  `"\n\nEXTRA-RULES-42"`; after a submitted turn the fake provider's first request has a system message
  containing `EXTRA-RULES-42`.
- `TestSystemAppendAfterReset`: after `Reset()`, `SystemPrompt()` still ends with the append.
- `TestSystemAppendEmpty`: without the option `SystemPrompt()` is byte-identical to a session built
  before this change would produce (compare with a second session without the option; no trailing blank lines).

## Verification
`.harness/verify/v11/T201.sh` exits 0. It runs the three named tests and the whole `internal/agent` package,
and checks that `Options.SystemAppend` exists.
