# T101: Headless flag parsing

Phase 1 · Model: sonnet: CLI flag parsing with moderate design judgment, no security logic · Depends-on: T000 · Covers: R85, R86, R94, R95

## Brief
Extend the command line of `cmd/yip` so the headless flags are accepted. Files: `cmd/yip/main.go`
(change `parseArgs`, `flags`, `deps`, `runWith`), new `cmd/yip/headless_args.go`, new
`cmd/yip/headless.go` (stub only), new `cmd/yip/headless_args_test.go`. Do not change the `--help` text
(another task does).

1. In `headless_args.go` define
   ```go
   type headlessFlags struct {
       prompt       string        // value of -p/--prompt ("-" = read stdin later)
       json         bool          // --json
       answers      []string      // --answer, repeatable, in order
       approve      []string      // --approve, repeatable; each value split on ",", trimmed, empty parts dropped
       dir          string        // --dir
       model, effort, mode string // --model, --effort, --mode
       timeout      time.Duration // --timeout (0 = none)
       maxCalls     int           // --max-model-calls (0 = unlimited)
       systemAppend string        // --system-append
       noSave       bool          // --no-save
       transcript   string        // --transcript
   }
   ```
   and add to `flags`: `headless bool` (true when `-p`/`--prompt` was given) and `h headlessFlags`.
2. `parseArgs` accepts, besides the existing `--version`, `--help`, `--resume [id]`/`-c`:
   `-p`, `--prompt`, `--json`, `--answer`, `--approve`, `--dir`, `--model`, `--effort`, `--mode`,
   `--timeout`, `--max-model-calls`, `--system-append`, `--no-save`, `--transcript`.
   Value flags take both `--flag value` and `--flag=value` (also `-p value`, `-p=value`); the value after
   a space is taken verbatim even when it starts with `-` (so `-p -` and `--answer -x` work). Booleans
   (`--json`, `--no-save`) take no value. Keep the existing `--resume` parsing unchanged.
3. Usage errors (exit 2, one line `yip: <reason>` followed by the existing `usage` line on stderr):
   a value flag at the end without value; `-p ""` (empty prompt); any headless flag without `-p`
   (reason names the flag, e.g. `yip: --json requires -p`); with `-p`: `--resume`/`-c` without an id;
   `--timeout` not a Go duration or `<= 0`; `--max-model-calls` not an integer or `< 1`; `--mode` other
   than `auto`/`manual`. `--model`/`--effort` values are validated later by the runner. Unknown
   arguments stay a usage error as today (`TestUnknownFlag` must still pass). `--version`/`--help`
   behave as today.
4. `deps` gets `stdin io.Reader` (`run` passes `os.Stdin`). `runWith` calls
   `runHeadless(f, d, d.stdin, stdout, stderr, cs)` when `f.headless`, else `runUI` as today.
   `headless.go` holds a stub `func runHeadless(f flags, d deps, stdin io.Reader, stdout, stderr io.Writer, cs *crashState) int`
   that prints `yip: headless mode not implemented` to stderr and returns 1 (the next task replaces it).
   Note `runWith` already passes `stdout`; keep that signature.

Tests in `headless_args_test.go` (call `parseArgs` directly with `bytes.Buffer`s):
- `TestParseHeadlessFlags`: all flags in both forms parse into the expected `headlessFlags`
  (repeated `--answer a --answer b` keeps order; `--approve bash,glob --approve read_file` → 3 names;
  `-p -` gives prompt `-`; `--timeout 1m30s`; `--max-model-calls 2`; `--resume abc123abc123 -p hi`).
- `TestParseHeadlessWithoutPrompt`: each headless flag alone → code 2, done, stderr mentions `-p`.
- `TestParseHeadlessBadValues`: missing value, empty prompt, `--timeout x`, `--timeout 0s`,
  `--max-model-calls 0`, `--max-model-calls abc`, `--mode bogus`, `-p hi --resume` (no id) → code 2.
- `TestParseInteractiveUnchanged`: `[]`, `--resume`, `--resume abc`, `-c` still parse as before with `headless == false`.
