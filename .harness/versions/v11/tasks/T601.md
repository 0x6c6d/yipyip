# T601: Help text for headless mode

Phase 6 · Model: haiku: help text with string-contains tests (Plan routing: /help text) · Depends-on: T101 · Covers: R100, R85

## Brief
Document headless mode in the two help outputs. Files: `internal/tui/help.go`, `cmd/yip/main.go`
(`usage` and `helpUsage` constants), tests in `internal/tui/help_test.go` and `cmd/yip/main_test.go`.
- `usage` line: `usage: yip [--version] [--help] [--resume [id]] [-p prompt [flags]]`; `helpUsage`
  starts with the matching `Usage:` line and gets a "Headless mode" block listing every flag, one per
  line with a short description: `-p, --prompt <text>` (`-` reads stdin), `--json`, `--answer <text>`
  (repeatable), `--approve <tool,...|all>`, `--dir <path>`, `--model <id>`, `--effort <low|medium|high>`,
  `--mode <auto|manual>` (default auto with -p), `--timeout <duration>`, `--max-model-calls <n>`,
  `--system-append <text>`, `--no-save`, `--transcript <file>`, `--resume <id>`; then the exit codes
  `0 done, 1 run error, 2 usage error or crash, 3 unanswered question, 4 timeout, 5 model-call limit`.
- `tui.HelpText()` (shown by `/help` and appended by `yip --help`) gets a short line pointing to headless
  mode (`yip -p "<prompt>"` runs one turn without the UI; see `yip --help`). Do not repeat the full flag
  list there. Never write the word "cost" anywhere in help (existing `TestHelpTextNoCost`).
- Existing help tests (`TestHelpFlag*`, `TestResumeHelpMentionsFlag`, `TestHelpText*`) keep passing.

Tests:
- `TestHelpFlagHeadless` (`cmd/yip/main_test.go`): `run([]string{"--help"}, ...)` output contains `-p`,
  `--json`, `--answer`, `--approve`, `--dir`, `--timeout`, `--max-model-calls`, `--system-append`,
  `--no-save`, `--transcript`, and each of `0 done`, `3 unanswered question`, `5 model-call limit`.
- `TestHelpTextHeadless` (`internal/tui/help_test.go`): `HelpText()` contains `yip -p`.
