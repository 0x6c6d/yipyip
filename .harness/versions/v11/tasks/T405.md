# T405: Session save, resume and no-save

Phase 4 · Model: opus: writes and prunes session files (Consequential A10, Risk v11 retention) · Depends-on: T203, T302 · Covers: R90, R91, R97

## Brief
In `runHeadless` (`cmd/yip/headless.go`), using `internal/session` (`NewStore`, `Load`, `Save`,
`Prune`, `FromAgent`, `ApplyTo`):
- `--resume <id>` (with `-p`; parsing exists): before any model call `store.Load(id)`; any error →
  `unknown session <id>` on stderr (never the error text, it names a path), exit 1. Then
  `session.ApplyTo(data, sess)`, and the stored model/effort of the data (if valid via
  `SetModel`/`SetEffort`), unless `--model`/`--effort` are given; the mode stays the headless one.
- Save once at run end for exit codes 0, 1, 3, 4, 5 (never 2, never on a crash) when
  `session.FromAgent` reports ok (a user message exists): resumed runs keep the loaded id and created
  time; new runs pass id "" and the current UTC RFC 3339 time, and the store derives the id
  (read `Store.Save` and how `internal/tui/save.go`/`autosave.go` obtain the id). Then
  `store.Prune(25, id)`. The `result` record's `session_id` is that id. A save error → stderr
  `yip: could not save session: <redacted err>`, exit code unchanged, `session_id` "".
- `--no-save`: no `Store` is created, nothing is saved or pruned, nothing under `.yipyip/sessions` is
  created, changed or deleted; `session_id` is "".
- The session must be saved after the turn ended (after `sess.Wait()`), so the stored turn is complete.

E2E tests in new `e2e/headless_session_test.go`:
- `TestHeadlessResume`: run 1 `-p first --json` (fake text `one`) → `session_id` 12 hex chars, file
  `.yipyip/sessions/<id>.json` exists. Run 2 `--resume <id> -p second --json` → the fake's request of
  run 2 contains user `first`, assistant `one` and user `second`; run 2 `session_id` == id.
  Unknown id: `--resume abcdefabcdef -p x` → exit 1, stderr contains `unknown session abcdefabcdef`, 0 requests.
- `TestHeadlessNoSave`: `.yipyip/sessions` pre-filled with one valid session (use run 1); a run with
  `--no-save --json` → `session_id` "", directory listing and file bytes unchanged. In a fresh dir
  `--no-save` leaves `.yipyip/sessions` absent.
- `TestHeadlessSaveOnQuestion`: an unanswered question (exit 3) still yields a non-empty `session_id`
  whose file loads.
- `TestHeadlessPrune`: with 30 valid older sessions present, after a run exactly 25 session files
  remain, including the new one.
